# Design Module

## 目的

`design-module` は、新規実装と機能拡張の設計成果物を、想定 Y/N に応じた decision table で取捨選択するモジュール skill である。
人間設計レビューを通過した上で、実装モジュールへ渡せる `実装範囲` と `テスト設計` を固定する。

## 呼び出し関係

- 呼び出し元: 人間、または上位モジュール skill。
- 返却先: 呼び出し元。
- モジュールが呼ぶ下位 skill: `design-bundle`、`detail-spec-design`、`diagramming`、`implementation-scope`、`test-design`。
- モジュールが呼ぶ下位 agent: `designer`、`diagrammer`、`test_designer`。

## 入口条件

- `preparation-module` の出口（作業 branch、`plan.md`）が固定されている、または同等の入力（作業 branch、依頼要約、`task-id`、active plan folder）が呼び出し元から渡されている。
- `想定 Y/N 評価` を本モジュールの最初に固定する。下位 agent 起動の前に行う。

## 出口条件

- `想定 Y/N 評価` が `plan.md` に固定されている。
- `人間設計レビュー` 承認済み。
- `実装範囲` が `designer` 担当の成果物として固定されている。
- `テスト設計` が `test_designer` 担当の成果物として固定されている。
- decision table で「-」のみになった artifact は省略理由が `plan.md` に 1 行残っている。

## 担当 artifact

| 成果物ID | 担当 | 依存対象 | 起動先 |
| --- | --- | --- | --- |
| `想定 Y/N 評価` | 呼び出し元 agent | `preparation-module` の出口 | なし |
| `詳細仕様差分` | `designer` | `想定 Y/N 評価` | `designer` |
| `画面設計差分` | `designer` | `想定 Y/N 評価`, `詳細仕様差分?` | `designer` |
| `設計差分図` | `diagrammer` | `想定 Y/N 評価`, `詳細仕様差分?`, `画面設計差分?` | `diagrammer` |
| `人間設計レビュー` | 人間 | `詳細仕様差分?`, `画面設計差分?`, `設計差分図?` | 人間 |
| `実装範囲` | `designer` | `人間設計レビュー` | `designer` |
| `テスト設計` | `test_designer` | `人間設計レビュー` | `test_designer` |

`実装範囲` と `テスト設計` は並列可。`画面設計差分`と`設計差分`は並列可。

## 想定 Y/N 評価

- 本モジュールに入った直後、下位 agent を起動する前に、呼び出し元 agent が依頼要約と実コード（および関連する `docs/spec.md`、`docs/architecture.md`、active plan の既存成果物）を読んで各想定の Y/N と根拠を `plan.md` に記録する。
- 評価する想定は次の 9 つ。1 想定 1 行で「Y/N、根拠 1 文、参照ファイルまたは仕様」を書く。
    - 仕様変更または仕様追加がある
    - 画面変更がある
    - 内部構造変更がある
    - 画面の表示変更がある（layout、文言、style、表示構造のいずれか。`storybook-module` の TRIGGER 軸）
    - frontend ロジック変更がある（state、API、Wails bridge、ルーティング、副作用、フォーム validation のいずれか。`implementation-module` の TRIGGER 軸）
    - backend 変更がある
    - frontend と backend を接続する
    - 実装済み責務を独立に証明したい
    - 実行時にしか確定しない値または原因分離が要る分岐がある
- 「仕様変更または仕様追加がある」「画面変更がある」「内部構造変更がある」が全て N の場合は、本モジュール全体を省略して呼び出し元へ戻す（省略理由を `plan.md` に 1 行残す）。
- 評価結果は `決定 table` と後続モジュールが共通の入口として参照する。

## decision table

複数想定が同時に Y なら、各行で「要」になった artifact を全部作る。

| 想定 | 詳細仕様差分 | 画面設計差分 | 設計差分図 |
| --- | --- | --- | --- |
| 仕様変更または仕様追加がある | 要 | - | - |
| 画面変更がある | - | 要 | 推奨 |
| 内部構造変更がある | - | - | 要 |

`人間設計レビュー`、`実装範囲`、`テスト設計` はモジュールに入った時点で常に要。「推奨」は省略可だが、揃える場合は `人間設計レビュー` の前に固定する。

## 各 artifact の詳細

### 詳細仕様差分

- `designer` を Task ツールで起動して作らせる。
- 下位 skill: `detail-spec-design`。
- 起動入力に含める内容: 親要件、現行仕様、対象範囲、未決事項、`想定 Y/N 評価` の結果、active plan folder。
- 呼び出し元 agent と本モジュール skill は本文を代筆しない。

### 画面設計差分

- `designer` を Task ツールで起動して作らせる。
- 下位 skill: `design-bundle`（画面設計差分パート）。
- 対象画面ごとに `screen-design-diff.<screen-id>.md` を作る。
- 既存画面設計正本との差分だけを扱う。

### 設計差分図

- `diagrammer` を Task ツールで起動して作らせる。
- 下位 skill: `diagramming`。
- 「内部構造変更がある」が Y の場合は要。「画面変更がある」が Y の場合は推奨。
- Mermaid 図と説明、根拠、検証観点を固定する。

### 人間設計レビュー

- 詳細仕様差分、画面設計差分、設計差分図のうち「要」になった成果物が揃った時点で人間へ返す。
- 差し戻しまたは追加質問の場合は、対象成果物を作った同じ agent を再起動して引き継ぎ入力に差し戻し内容を明示する。新規 agent を起こさない。
- 設計差分図を省略する場合は、省略理由を `plan.md` に書いた上でレビューへ進む。

### 実装範囲

- `人間設計レビュー` 承認後に `designer` を Task ツールで起動して作らせる。
- 下位 skill: `implementation-scope`。
- 承認済み設計成果物から、実装モジュールが受け取れる「承認済み実装範囲、依存、検証単位」へ分ける。

### テスト設計

- `人間設計レビュー` 承認後に `test_designer` を Task ツールで起動して作らせる。
- 下位 skill: `test-design`。
- 承認済み詳細仕様差分または画面設計差分から、シナリオテストと単体テストの観点を分けて固定する。
- `実装範囲` と並列可。

## 不変条件

- 設計成果物本文（詳細仕様差分、画面設計差分、設計差分図、実装範囲、テスト設計）を本モジュール skill が代筆しない。各 artifact は担当 agent が Task ツールで作る。
- `想定 Y/N 評価` を下位 agent 起動の前に固定する。会話文脈だけで進めず、`plan.md` に記録する。
- `人間設計レビュー` 承認なしで `実装範囲` と `テスト設計` の起動へ進めない。
- 差し戻し時は同じ agent を再起動する。会話文脈は引き継がず、差し戻し内容を引き継ぎ入力に明示する。
- `設計差分図` の成立条件を満たすのに揃えずに `人間設計レビュー` へ進める場合は、省略理由を `plan.md` に固定する。
- AI だけで設計成果物と実装範囲を確定しない。

## 返す成果物

- decision table 結果: 各想定の Y/N、各 artifact の要不要、省略理由（あれば）。
- 設計成果物の参照: 作成済み artifact のファイルパス、担当 agent、人間承認状態。
- 差し戻し記録: 差し戻し対象、戻し先 agent、戻し結果、戻せない場合の停止理由。
- 後続モジュールへの引き継ぎ: `実装範囲`、`テスト設計` のパス、UX デザイン変更想定の Y/N、Storybook モジュールへ進むかどうか。
- 停止判定: 停止理由、不足項目、戻し先。

## 作業を止める条件

- `想定 Y/N 評価` で仕様変更、画面変更、内部構造変更がすべて N と判定された。呼び出し元へ戻す（停止扱いではなく早期出口）。
- `想定 Y/N 評価` を固定する前に下位 agent を起動しそうな状態になった。
- `人間設計レビュー` 承認が得られない、または差し戻しを解消できない。
- `designer`、`diagrammer`、`test_designer` のいずれかが必要なのに起動できない。
- `設計差分図` の成立条件を満たすのに省略理由を固定できない。
- 設計判断が AI 単独で確定できる範囲を越え、人間判断が要るのに得られない。
- 停止時は不足項目、衝突箇所、固定できない判断、戻し先を返す。
