# Diagramming

## 目的

`diagramming` は、Claude 本体がモジュール判断に必要な図成果物を作る時の作業プロトコルである。
図は仕様正本ではなく、task 内の判断補助成果物として扱う。

この skill は、設計差分図、人間が明示した補助図だけを扱う。
目的に合わない旧規約は、保持せず作り直してよい。

## 対応ロール

- Claude 本体が task 文脈を持ったまま読んで適用する。
- 呼び出し元は `design-module`、または図化が要る他の場面とする。
- 担当成果物は `設計差分図`、明示された補助図とする。

## 呼び出し元から渡される情報

- 必須呼び出し元: 図作成を依頼した agent または人間。
- 必須図化目的: 図で固定する判断。
- 必須根拠参照: 図の根拠にする task 内成果物または docs 正本。
- 必須作業計画フォルダ: 図成果物を置く `docs/exec-plans/active/<task-id>/`。
- 必須図成果物種別: `設計差分図`、明示された補助図のいずれか。
- 非必須予定変更箇所: 追加予定箇所、削除予定箇所、変更しない接続先。
- 非必須修正方針判断: `investigation-module` で固定済みの原因の原因、責務境界、採用する修正方針、禁止する修正。
- 非必須問題点: 修正方針判断で確認した問題。
- 非必須修正方針: 修正方針判断で確認した直し方。
- 非必須禁止範囲: 図に含めてはいけない範囲。

## 作業前に読む正本

- Mermaid を含む Markdown を図成果物の正本とする。
- 図成果物の置き場所は active plan folder（`docs/exec-plans/active/<task-id>/`）とする。
- 差分図の雛形を使う場合は [review-diff-template.md](/Users/iorishibata/Repositories/AITranslationEngineJP/.claude/skills/diagramming/references/templates/review-diff-template.md) を参照する。
- 外部成果物が不足または衝突する場合は停止し、衝突箇所を返す。

## skill 内の拘束条件

| 図成果物種別 | 用途 | 必須図 | 必須説明 | 含める範囲 | 含めない範囲 |
| --- | --- | --- | --- | --- | --- |
| `設計差分図` | 人間設計レビューまたは軽量変更の実装着手判断 | Mermaid コンポーネント図 | 概要、各箱の説明、差分凡例、追加予定、削除予定、変更しない接続先 | 予定変更箇所と接続先の最小範囲 | 全体構成図、正本図、変更しない箇所の網羅 |
| 明示された補助図 | 人間または呼び出し元が指定した判断 | 指定された Mermaid 図 | 図が補う判断、必要な箱の説明 | 指定された範囲 | 指定外の範囲 |

図成果物の正本性は次の表に従う。

| 成果物 | 扱い |
| --- | --- |
| `.md` | Mermaid と説明を含む task 内の図成果物正本 |

## 担当ロールが判断してよい範囲

- 図は呼び出し元の次判断を補う範囲だけに限定する。
- 図は Mermaid で作り、Markdown に置く。
- Markdown 図成果物は、Mermaid コードブロック、図種別、箱または参加者、接続、必要な凡例が読めることを確認する。
- コンポーネント図、構成図、状態図は、概要と各箱の説明を Markdown に置く。
- シーケンス図は、参加者、呼び出し順序、分岐、問題点、修正方針が図内で読める場合、Mermaid だけでよい。
- `設計差分図` は、赤を削除、緑を追加、黄色を変更なしとして差分凡例に固定する。
- `設計差分図` のシーケンス図、状態遷移図、その他の図は、ユーザー要求または複雑性がある場合だけ作る。
- 図の方向は上から下を基本にする。
- 図が大きくなり、対象判断を読みにくくする場合は図を分割する。
- `設計差分図` は追加、削除、変更しない接続先を区別する。
- 目的に合わない古い diagramming 規約は、互換目的で残さない。
- モジュール成果物として不要な汎用図作成規約は、保守時に削除または再整理してよい。

## skill が扱わない対象

- プロダクトコードの変更は扱わない。
- プロダクトテストの変更は扱わない。
- docs 正本図の更新は扱わない。
- 画面表示の設計（Storybook の story とコンポーネント）だけで足りる判断は扱わない。
- Mermaid を含まない図ファイルを新規作成しない。

## 返す成果物

- 判断結果: 図作成の完了、未完了、停止の判定を返す。
- 図成果物種別: 扱った図成果物種別を返す。
- 図成果物path: 作成または更新した Markdown の path を返す。
- 根拠参照: 図の根拠にした task 内成果物または docs 正本を返す。
- 図説明: 図が補う判断を返す。
- 検証結果: Markdown 確認と Mermaid 記述確認の結果を返す。
- 不足情報: 図作成を完了できない不足項目を返す。
- 禁止事項: 出力にプロダクトコード、プロダクトテスト、docs 正本本文の変更を含めない。

## 作業を完了できる条件

- Markdown 図成果物の path が返っている。
- 根拠参照が返っている。
- 図説明が返っている。
- Markdown 確認と Mermaid 記述確認の結果が返っている。
- `設計差分図` の場合は、コンポーネント図が揃っている。
- `設計差分図` の場合は、追加予定、削除予定、変更しない接続先が区別されている。
- `設計差分図` の場合は、コンポーネント図の概要と各箱の説明が揃っている。
- `設計差分図` の場合は、赤、緑、黄色の差分凡例が揃っている。

## 作業を止める条件

- 必須呼び出し元が不足する場合は停止する。
- 必須図化目的が不足する場合は停止する。
- 必須根拠参照が不足する場合は停止する。
- 必須作業計画フォルダが不足する場合は停止する。
- 必須図成果物種別が不足する場合は停止する。
- `設計差分図` で予定変更箇所が不足する場合は停止する。
- `設計差分図` でコンポーネント図が不足する場合は停止する。
- `設計差分図` でコンポーネント図の概要または各箱の説明が不足する場合は停止する。
- `設計差分図` で赤、緑、黄色の差分凡例が不足する場合は停止する。
- `設計差分図` が予定変更箇所以外を網羅図として含む場合は停止する。
- Markdown 図成果物の Mermaid コードブロックが壊れている場合は停止する。
- 図成果物種別に必要な Mermaid 記述要素が不足する場合は停止する。
- 停止時は不足項目、衝突箇所、戻し先を返す。
