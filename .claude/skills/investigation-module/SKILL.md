# Investigation Module

## 目的

`investigation-module` は、人間が確認した不具合、レビュー非通過、検証失敗の観測記録から、実装モジュールへ渡せる「修正方針判断、修正実行入力」を Claude 本体が固定する設計モジュールの亜種である。
修正は fail-test ベースで進める前提で、本モジュールの出口で先に不具合を検出できるテスト観点と修正方針を分けてから、実装モジュールへ渡す。

## 呼び出し関係

- 呼び出し元: 人間、または上位モジュール skill。
- 返却先: 呼び出し元。
- モジュールが呼ぶ skill: `fix-decision`（Claude 本体が読んで適用）。
- モジュールが呼ぶ agent: なし（既定）。

## 入口条件

- `preparation-module` の出口（作業 branch、`plan.md`、軽 / 重判定）が固定されている。
- 人間観測記録（人間が見た画面、操作、ログ、失敗、期待との差分）が固定されている。
- 修正対象の Wails process または接続先が単一化されている。
- ブラウザ操作（`chrome-devtools` MCP ツール群、`mcp__plugin_chrome-devtools-mcp_chrome-devtools__*`）が利用できる。

## 出口条件

- `修正方針判断` が承認済み。
- `人間修正レビュー` 承認済み。
- `修正実行入力` が実装モジュールへ渡せる形で固定されている。
- 仕様変更または仕様追加が必要と判断された場合は停止して呼び出し元へ戻す（`design-module` への迂回が必要か、人間判断を仰ぐ）。

## 担当 artifact

| 成果物ID | 担当 | 依存対象 |
| --- | --- | --- |
| `人間観測記録` | Claude 本体 | 入口条件 |
| `修正方針判断` | Claude 本体 | `人間観測記録`, `事前準備` |
| `人間修正レビュー` | 人間 | `修正方針判断` |
| `修正実行入力` | Claude 本体 | `人間修正レビュー` |

## 各 artifact の詳細

### 人間観測記録

- Claude 本体が固定する。
- 不具合判断資料から、確認済みの不具合、期待との差分、観測された操作または条件を task 内成果物として固定する。
- 仮説や推測は含めない。観測事実のみを書く。

### 修正方針判断

- Claude 本体が `fix-decision` skill を Skill ツールで読んで適用する。
- 入力: 人間観測記録、active plan folder、Wails 接続対象、画面の正本（Storybook の story と svelte コンポーネント）、観測ログ仕様。
- 次を固定する:
    - 観測済み問題（人間観測記録から確認できる問題）。
    - 画面再現確認（`chrome-devtools` MCP ツールで実装済み画面の `data-testid` またはセレクタに従って再現した結果）。
    - 原因仮説（複数仮説と検証順序）。
    - 観測ログ検証（一時ログ追加、観測結果、削除確認）。
    - 確定原因（観測で確定したもののみ）。
    - 採用する修正方針（仕様が不足していない時のみ）。
    - 禁止する修正（新しい状態値の追加、症状だけを隠す分岐などを具体的に）。

### 人間修正レビュー

- `修正方針判断` が固まった時点で人間へ返す。
- 人間レビューを依頼する直前に、active plan folder に `summary.md` を一時作成し、レビュー終了後に削除する。固定セクションは「概要」と「図」の 2 つ。
- 差し戻しまたは追加質問の場合は、Claude 本体が同じ文脈で書き直す。

### 修正実行入力

- Claude 本体が固定する。
- 次を実装モジュールへ渡す入力として `plan.md` に記録する。
    - 承認済み修正方針（恒久修正として採用する方針）。
    - 禁止する修正（実装で許可しない対症療法）。
    - 影響ファイル候補（観測事実に基づく候補）。
    - 画面再現確認の再現手順と修正後に満たすべき期待状態（実装モジュールが利用する）。
    - 追加する fail-test の観点（修正前に追加して fail を確認、修正後に pass を確認）。

## 不変条件

### 修正方針判断の必須観点

| 観点 | 拘束する判断 |
| --- | --- |
| `観測済み問題` | 人間観測記録から確認できる問題だけを固定する。 |
| `画面再現確認` | 実装済み画面の `data-testid` またはセレクタに従い、人間観測記録のユーザー操作を `chrome-devtools` MCP ツールで再現する。 |
| `原因仮説` | 観測事実から複数の原因候補を立て、検証する順序と根拠を固定する。 |
| `観測ログ検証` | 仮説を否定または支持するために追加した一時ログ、観測結果、削除確認を固定する。 |
| `確定原因` | 観測で確定した原因だけを固定する。 |
| `採用する修正方針` | 仕様が不足していない場合だけ恒久修正を固定する。 |
| `禁止する修正` | 新しい状態値の追加、症状だけを隠す分岐などを具体的に固定する。 |

### 責務境界

- 修正方針判断と修正実行入力の本文は Claude 本体が task 文脈を持ったまま書く。agent には渡さない。
- 影響ファイルは候補として扱う。実装の変更ファイルを本モジュールで確定しない。

### 安全境界

- 一時観測ログ以外のプロダクトコード変更は本モジュールでは行わない。
- プロダクトテスト変更、docs 正本本文変更は本モジュールでは行わない。
- 追加した一時観測ログは `修正方針判断` を返す前に削除する。

### 仕様不足の停止

- 修正方針が仕様変更・機能追加・受け入れ条件の新規判断を必要とすると Claude 本体が判断した場合は、本モジュールを停止する。停止時は呼び出し元へ「`design-module` 経由の仕様変更が必要」と戻す。

## 返す成果物

- 観測済み問題: 根拠から確認できる問題。
- 画面再現確認: 再現手順、操作結果、画面状態、証跡参照。
- 確定原因: 観測で確定した原因。
- 採用する修正方針: 恒久修正として採用する方針。
- 禁止する修正: 実装で許可しない対症療法。
- 影響ファイル候補: 観測事実に基づく候補。
- 修正実行入力: 実装モジュールへ渡す入力一式（追加する fail-test の観点を含む）。
- 停止判定: 停止理由、不足項目、戻し先。

## 作業を止める条件

- 人間観測記録が不足する。
- Wails 接続対象が単一化されていない。
- 実装済み画面の `data-testid` またはセレクタに従ったユーザー操作を `chrome-devtools` MCP ツールで再現確認できない。
- 観測ログを追加または確認できず、仮説を検証できない。
- 追加した一時観測ログを削除できない。
- 原因が仮説に留まり、採用する修正方針を固定できない。
- 修正方針が仕様変更・機能追加・受け入れ条件の新規判断を必要とすると判断した。
- `人間修正レビュー` 承認が得られない、または差し戻しを解消できない。
- 停止時は不足項目、衝突箇所、固定できない判断、戻し先を返す。
