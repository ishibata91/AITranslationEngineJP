# Experiment Workflow

## 目的

`experiment-workflow` は、ループ前提の実験フローの入口オーケストレーターである。何をどこまで良くすれば終わりかが数値で決まっていない task の入口で、達成条件と測る道具を人間承認まで持ち上げ、ループを回して、達成のための実装になっていないことを確かめてから採否を人間へ渡す。

本モジュールが固定するのは作る順序と承認順序とし、実験の判断基準は `research-protocol` skill が持つ。実装方針の設計と確定仕様は扱わない。`design.md` と `spec.md` は作らない。実験は探索であり、変える対象と測る値だけを先に固定して、あとはループが決める。

## 呼び出し関係

- 呼び出し元: 人間。準備の段は人間が 1 回だけ起動し、ループの段は `/loop` が繰り返し起動する。
- 返却先: 人間。
- モジュールが呼ぶ下位 skill: `research-protocol`（Claude 本体が読んで適用。判断基準、`criteria.md` と `loop-log.md` の書き方、3 agent の検証規約）。
- モジュールが呼ぶ下位 agent: `researcher`（`fresh`）、`criteria_reviewer`（`fresh`）、`metric_gaming_reviewer`（`fresh`）。
- 下流の段: なし。人間採否で完結する。採用した変更を統合先 branch へ取り込むかは、本モジュールの外で人間が決める。

## 段の分け方

本モジュールは準備の段とループの段に分かれる。Claude 本体は、起動時にどちらの段にいるかを、作業計画フォルダの成果物が揃っているかで判定する。

- 準備の段: 人間が 1 回だけ起動する。達成条件と測る道具と変える前の測定を揃える。この段は `/loop` で回さない。人間承認と `達成条件レビュー` が入るため、繰り返し起動すると承認待ちで空回りする。
- ループの段: `/loop` が繰り返し起動する。1 起動で 1 回分だけ進める。

Claude 本体は、準備の段の出口条件が揃っていない状態でループの段へ入らず、不足している成果物を人間へ返す。

## 準備の段

### 入口条件

- 呼び出し元から `task-id` と事象が渡されている。
- 統合先 branch（既定 `master`）が local に存在する。
- 実験に使える資源（外部の接続先、使える機械、使える外部データ）が渡されている。

### 出口条件

出口条件は、そのままループの段の入口条件になる。ループの段は、達成条件が固定され測る道具が動く状態から始まる。

- 作業 branch が `claude/<task-id>` として local に存在する。
- 作業計画フォルダ `docs/exec-plans/active/<task-id>/` に `plan.md`、`criteria.md`、`loop-log.md`、`measurements.csv` が存在する。
- 測る道具が砂場に存在し、走らせると達成条件の各行の値が出る。
- `measurements.csv` に 0 回目が 2 行（変える前の測定の 1 度目と 2 度目）記録されている。
- `measurements.csv` に `予備の回` が記録され、`loop-log.md` に変えた対象と各行の動き幅が書かれている。
- `criteria.md` の達成条件の全ての行に、現在の値と揺れの底と達成の線と線の出どころが埋まっている。
- `達成条件レビュー` が通過済みで、通過した日付が `criteria.md` のレビュー節に記録されている。
- `criteria.md` の達成条件の表の全ての行に、貢献の承認が記録されている。
- `criteria.md` の選択肢の表のうち、渡された資源を前提から外す行に人間承認が記録されている。

### 担当成果物

| 成果物ID | 担当 | 依存対象 | 起動先 |
| --- | --- | --- | --- |
| `branch 準備` | Claude 本体 | 入口条件 | なし |
| `plan.md` | Claude 本体 | `branch 準備` | なし |
| `選択肢の調査` | `researcher`（`fresh`） | `plan.md` | `researcher` agent |
| `criteria.md` | Claude 本体 | `選択肢の調査` | なし |
| `測る道具` | Claude 本体 | `criteria.md` | なし |
| `変える前の測定` | Claude 本体 | `測る道具` | なし |
| `予備の回` | Claude 本体 | `変える前の測定` | なし |
| `達成条件レビュー` | `criteria_reviewer`（`fresh`） | `予備の回` | `criteria_reviewer` agent |
| `人間承認（目的への貢献）` | 人間 | `達成条件レビュー` | 人間 |

Claude 本体は、依存対象の成果物が揃うまで、その成果物の作業を始めない。測る道具の実装に関わる調査は `測る道具` の段で行う。

Claude 本体は、`criteria.md` の欄を 3 つの段に分けて埋める。達成の線は揺れの底と対象を変えたときの動き幅を見ないと置けないため、`criteria.md` の段では線を空欄で残す。

- `criteria.md` の段で埋める: 測る値、数え方、目的への貢献、選択肢の表、標本の表、誤りの種類の表。
- `変える前の測定` の段で埋める: 現在の値、揺れの底。
- `予備の回` の段で埋める: 達成の線、線の出どころ。

Claude 本体は、`達成条件レビュー` を通過するまで `criteria.md` と測る道具を書き直して再実行し、通過してから人間承認を依頼する。この順序により、抜け道と実測から出る書き直しが人間承認より前に終わる。人間が同じ達成条件を繰り返し承認する形にしない。

## ループの段

### 入口条件

- 準備の段の出口条件が揃っている。
- `loop-log.md` の最後の回と `measurements.csv` の最終行から、前の回の状態を読める。

### 1 起動で進める範囲

Claude 本体は、1 回の起動で 1 回分だけ進める。1 回分は次で終わる。

- `loop-log.md` の最後の回の次にすることを読み、その対象を変える。
- 測る道具を走らせ、`measurements.csv` へ 1 回分を追記する。
- 標本を読んだ結果を砂場へ書き、集計を `loop-log.md` の該当回へ書く。
- 変更を commit する。commit message に回の番号と変えた対象を書く。
- 達成の線を満たすかを判定し、次にすることを `loop-log.md` へ書く。

Claude 本体は、1 起動で 2 回分以上を進めない。人間が回ごとの結果を見て次の回へ介入できる状態を保つ。

Claude 本体は、達成の線を満たさなかった回も残す。

### 出口条件

- 達成の線を満たしていない場合: `measurements.csv` にその回が追記され、`loop-log.md` にその回の判断と次にすることが書かれ、変更が commit されている。次の起動へ続く。
- 達成の線を満たした場合: `作り込みの検査` が通過し、人間が採否を決め、判断と理由が `loop-log.md` に記録されている。Claude 本体は、ループを止めることを人間へ返す。

Claude 本体は、達成の線を満たした起動で `作り込みの検査` を起動し、その回でループを止める。次の回へ進まない。

### 担当成果物

| 成果物ID | 担当 | 依存対象 | 起動先 |
| --- | --- | --- | --- |
| `1 回分の測定` | Claude 本体 | ループの段の入口条件 | なし |
| `作り込みの検査` | `metric_gaming_reviewer`（`fresh`） | 達成の線を満たした回 | `metric_gaming_reviewer` agent |
| `人間採否` | 人間 | `作り込みの検査` | 人間 |

## branch 準備

- 作業 branch を既定名 `claude/<task-id>` として local に作成または切り替える。
- 統合先 branch（既定 `master`）からの分岐元 commit を控える。
- remote repository を変更しない（push、tag push、remote branch delete は行わない）。

## plan.md

`plan.md` は次の 6 つだけを持つ。達成条件と測り方は `criteria.md`、各回の記録は `loop-log.md` と `measurements.csv` が持つ。

- 事象: 人間が見た、実験を起こす元になったことを 1 件 1 行で書く。
- 対象: 実験で変える対象と、変えない対象を書く。変えない対象は、変えない理由を添えて書く。
- 砂場: 実験の道具と標本を置く場所を書く。`.gitignore` で除外される場所を選び、除外を確かめた根拠を添える。
- 接続先: 実験を回すのに使う外部（接続先、機械、読むデータの場所）を書く。実験の条件として固定するものを書く。
- branch 情報: 作業 branch 名、統合先 branch 名、分岐元 commit を書く。
- やらないこと: この実験で扱わない範囲を書く。後続 task へ回す対象は、回す先を添えて書く。

実験フローの `plan.md` は要求の節を持たない。何をどこまで達成するかは `criteria.md` の達成条件の表が持つ。

## criteria.md と loop-log.md と measurements.csv

書き方は `research-protocol` skill に従う。Claude 本体が Skill ツールで読んで適用する。

- `criteria.md`: 達成条件、診断の値、集めた選択肢、標本の分け方、誤りの種類、測る道具の場所。
- `loop-log.md`: 各回の判断、仮説の表、測定手段を変えた記録、採否。数値の並びは持たない。
- `measurements.csv`: 回ごとの測定値。

本モジュールが固定するのは書く順序と承認順序とし、欄の意味と埋め方は `research-protocol` skill が持つ。

何を何回変えるか、どの標本で測るか、値の差を改善と呼べるかの判断も `research-protocol` skill が持つ。

## 変える前の測定

Claude 本体は、対象を変えずに同じ条件で 2 度測り、両方を `measurements.csv` の 0 回目として書く。回の欄を両方 `0` とし、変えた対象の欄へ 1 度目と 2 度目の別を書く。

- 1 度目の値を `criteria.md` の達成条件の表の現在の値の欄へ書く。
- 2 度の値の差を `criteria.md` の達成条件の表の揺れの底の欄へ書く。

## 予備の回

`予備の回` は、達成の線を置くために、対象を 1 つ変えて値がどれだけ動くかを実測する回である。線を置く根拠を、実測した動き幅で持つために置く。

Claude 本体は次を行う。

- 変える対象を 1 つ選び、選んだ理由を `loop-log.md` へ書く。効きそうな対象を選ぶ。
- 開発用の標本で 1 回測り、`measurements.csv` へ書く。回の欄を `p`、段の欄を `探索` とする。評価用の標本を使わない。
- 達成条件の各行について、変える前の値からの動き幅を `loop-log.md` へ書く。
- 動き幅を根拠に達成の線と線の出どころを `criteria.md` へ書く。
- 線が揺れに埋もれる行を、割合で測る行なら標本の件数を増やし、件数で数える行なら線を置き直す。どちらもできない行は診断の表へ移す。

Claude 本体は、`予備の回` をループの段の回数に数えない。ループの段は回 1 から始まる。

動き幅から線を置く判断、線が揺れに埋もれる行の扱い、動き幅が揺れの底以下だった場合の扱いは `research-protocol` skill が持つ。

## 達成条件レビュー

`達成条件レビュー` は、人間承認を取る前に、達成条件と測る道具が達成を測れるかを検証する AI 検証である。`criteria_reviewer` agent（`fresh`、読み取り専用）が担う。

- 起動入力: `plan.md` のパス、`criteria.md` のパス、測る道具のパス、`measurements.csv` のパス、`task-id`、対象 repo のルート。
- 戻し先: 本モジュール。
- 完了: 達成条件の表の全ての行に判定が付いている。
- 否決時: Claude 本体が同じ文脈で `criteria.md` または測る道具を書き直し、`達成条件レビュー` を再実行する。通過するまで繰り返す。否決理由を解消できない場合は人間へ論点として上げる。
- 通過時: Claude 本体が通過した日付を `criteria.md` のレビュー節へ書き、人間承認を依頼する。この日付が、達成の線と数え方を固定する起点になる。

検証内容、判断範囲、出力は `research-protocol` skill の `達成条件レビュー` 節が持つ。

## 作り込みの検査

`作り込みの検査` は、達成条件を満たした後に、達成のための実装になっていないかを検査する AI 検証である。`metric_gaming_reviewer` agent（`fresh`、読み取り専用）が担う。

- 起動入力: `criteria.md` のパス、`loop-log.md` のパス、`measurements.csv` のパス、砂場の標本のパス、測る道具のパス、作業 branch の分岐元 commit、`task-id`、対象 repo のルート。
- 戻し先: 本モジュール。
- 完了: 検査観点の全てに判定が付いている。
- 否決時: Claude 本体がループの段へ戻り、否決理由に当たる変更を差し替えて回を足す。否決を人間承認で越えない。

検査観点、判断範囲、出力は `research-protocol` skill の `作り込みの検査` 節が持つ。

## 選択肢の調査

`選択肢の調査` は、達成条件を測る手段と対象を変える手段について、自作の前に既存の手法を洗う調査である。`researcher` agent（`fresh`、読むことと検索だけ）が担う。

- 起動入力: `plan.md` のパス、事象、探す対象（測る手段か変える手段か）、使える資源、`task-id`、対象 repo のルート。
- 戻し先: 本モジュール。Claude 本体が結果を `criteria.md` の選択肢の表へ 1 行 1 つで書く。報告されている効果の大きさの欄も併せて埋める。達成の線を届く見込みで置く場合、線の出どころがこの欄を指す。
- 完了: 探す対象について、外部の手法と repo 内の既存実装の両方に当たった結果が返っている。

探す範囲、判断範囲、出力は `research-protocol` skill の `選択肢の調査` 節が持つ。

## 人間承認と人間採否

Claude 本体は、`達成条件レビュー` が通過した後に、次を人間へ示す。

- 達成条件の各行の目的への貢献の欄と、その行が `plan.md` の事象のどれに当たるか。
- 達成条件の各行の現在の値、揺れの底、達成の線、線の出どころ。
- `達成条件レビュー` が試した抜け道と、作れなかったこと。
- 診断の表へ移した行と、移した理由。
- 選択肢の表のうち、渡された資源を前提から外す行。

人間が返すのは次の 2 つとする。

- 達成条件の各行の目的への貢献の欄が、自分の困りごとと合っているかの判定。合っている行へ貢献の承認の日付を書く。
- 資源を前提から外す行の可否。

Claude 本体は、達成の線の値と数え方を人間の承認対象にしない。線が働く形かは `達成条件レビュー` が判定済みで、線の値の良し悪しを人間が判定する手立てが無いためとする。

Claude 本体は、貢献の承認の欄が埋まるまでループの段へ入らない。

Claude 本体は、`作り込みの検査` が通過した後に、`measurements.csv` の最後の回の値と砂場の標本を人間へ示す。

Claude 本体は、達成の線をループを止める条件として扱い、採否と分ける。線を満たしたらループを止め、採否は人間が標本を読んで決める。

Claude 本体は、人間が採らないと決めた場合、その理由を新しい仮説として `loop-log.md` へ書き、次の回へ回す。達成の線を動かさない。

## 不変条件

- `人間承認（目的への貢献）` なしでループの段へ入らない。
- `達成条件レビュー` 通過なしで `人間承認（目的への貢献）` を依頼しない。
- `達成条件レビュー` の否決を人間承認で越えない。解消できない否決は停止して人間へ返す。
- 達成の線の値と数え方を人間の承認対象にしない。
- 1 起動で 2 回分以上を進めない。
- `作り込みの検査` 通過なしで `人間採否` を依頼しない。
- `作り込みの検査` の否決を人間承認で越えない。
- 達成の線と数え方を `達成条件レビュー` の通過日付より後に動かさない。
- 砂場を commit に入れない。
- プロダクト正本（`docs/architecture.md` など）を本モジュールでは変更しない。
- remote repository を変更しない。

## 返す成果物

準備の段が返すもの。

- 作業 branch 名、統合先 branch、分岐元 commit。
- 作業計画フォルダのパス、`plan.md` のパス、`criteria.md` のパス、`loop-log.md` のパス、`measurements.csv` のパス、砂場のパス、測る道具のパス。
- 達成条件の表の全ての行と、0 回目の 2 度分の値と、揺れの底。
- `予備の回` で変えた対象と、達成条件の各行の動き幅。
- 達成条件の各行の達成の線と線の出どころ。
- 診断の表へ移した行と、移した理由。
- 選択肢の表のうち、採らなかった行とその理由。
- `達成条件レビュー` の判定結果、否決理由、抜け道、通過した日付と、通過までに書き直した回数。
- ループの段へ渡す、1 回目で変える対象。

ループの段が返すもの。

- その回の番号、段、変えた対象、測った標本、測った値、判定、commit hash。
- 標本を読んだ結果の集計と、読んだ役割。
- 次にすること、またはループを止めること。
- 達成の線を満たした回では、`作り込みの検査` の判定結果と否決理由、人間採否の結果。

## 作業を止める条件
