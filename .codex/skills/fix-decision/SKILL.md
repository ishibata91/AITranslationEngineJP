# Fix Decision

## 目的

`fix-decision` は、人間が確認した不具合、レビュー非通過、検証失敗の修正前調査を、恒久修正へ渡せる修正方針判断と原因箇所シーケンス図へ変換する作業プロトコルである。
`fix_decider` が原因の原因、壊れている責務境界、採用する修正方針、禁止する対症療法、原因箇所の呼び出し順序を task 内成果物として固定する時に使う。

## 対応ロール

- `fix_decider` が使う。
- 呼び出し元は `fix_lane` とする。
- 返却先は `fix_lane` とする。
- 担当成果物は `修正方針判断` と `原因箇所シーケンス図` とする。

## 入力規約

- 必須人間観測記録: 人間が見た画面、操作、ログ、失敗、期待との差分。
- 必須修正前調査: `investigator` が返した観測事実、仮説、ログ、未確認事項、影響ファイル候補。
- 必須作業計画フォルダ: `修正方針判断` と `原因箇所シーケンス図` を置く `docs/exec-plans/active/<task-id>/`。
- 非必須レビューYAML: 修正対象に関係する既存のレビュー結果。
- 非必須検証ログ: 修正対象に関係する既存の検証出力。

## 外部参照規約

- エージェント実行定義と実行境界は [fix_decider.toml](/Users/iorishibata/Repositories/AITranslationEngineJP/.codex/agents/fix_decider.toml) に従う。
- 修正レーンの進行境界は [fix-lane](/Users/iorishibata/Repositories/AITranslationEngineJP/.codex/skills/fix-lane/SKILL.md) に従う。
- 修正前調査は [investigate](/Users/iorishibata/Repositories/AITranslationEngineJP/.codex/skills/investigate/SKILL.md) に従う。
- Mermaid 構文確認は `mmdc` を使う。

## 内部参照規約

### 修正方針判断の必須観点

| 観点 | 拘束する判断 |
| --- | --- |
| `観測済み問題` | 人間観測記録と修正前調査から確認できる問題だけを固定する。 |
| `原因の原因` | 表面症状を生んだ上流の責務違反、契約違反、状態不整合を固定する。 |
| `責務境界` | 返却元、呼び出し元、状態モデル、永続化、表示のどこが壊れているかを分ける。 |
| `採用する修正方針` | 既存仕様へ戻す恒久修正だけを固定する。 |
| `禁止する修正` | 新しい状態値の追加、`null` の握りつぶし、症状だけを隠す分岐などを具体的に固定する。 |
| `残る不足` | 恒久修正へ進めない未確認事項を固定する。 |

### 原因箇所シーケンス図の必須観点

| 観点 | 拘束する判断 |
| --- | --- |
| `図化目的` | 人間修正レビューで確認する原因箇所の呼び出し順序だけを固定する。 |
| `図正本` | Mermaid シーケンス図を含む Markdown を task 内の図成果物正本として固定する。 |
| `原因箇所` | 修正前調査と修正方針判断で確認済みの原因箇所だけを固定する。 |
| `問題点` | 何が問題かを 1 文で固定する。 |
| `修正方針` | どう直すかを 1 文で固定する。 |
| `含めない範囲` | 未確認の原因、未確認の修正案、全体シーケンスを図から除外する。 |

## 判断規約

- 観測事実と仮説を分ける。
- 原因が仮説に留まる場合は修正方針を採用しない。
- 表面症状ではなく、表面症状を生んだ責務違反または契約違反を原因の原因として扱う。
- 既存状態モデルで説明できる場合は、新しい状態値を採用しない。
- `null` が来る場合は、`null` が契約値か異常値かを先に判断する。
- `null` が異常値の場合は、呼び出し側の分岐追加ではなく、返却元または境界契約の修正を優先する。
- 修正方針が仕様変更、機能追加、受け入れ条件の新規判断を必要とする場合は、修正レーン対象外として返す。
- 影響ファイルは候補として返してよいが、実装 agent の変更ファイルを確定しない。
- `原因箇所シーケンス図` は修正前調査と修正方針判断で確認した原因箇所だけを扱う。
- `原因箇所シーケンス図` は問題点と修正方針を 1 文ずつ明示する。
- `原因箇所シーケンス図` は Mermaid シーケンス図を含む Markdown で作る。
- `原因箇所シーケンス図` は `mmdc -i <diagram>.md -o <temporary>.md --artefacts <temporary-directory>` で Mermaid 構文を確認する。
- `原因箇所シーケンス図` は、参加者、呼び出し順序、分岐、問題点、修正方針が図内で読める場合、Mermaid だけでよい。
- `原因箇所シーケンス図` が大きくなり、人間修正レビューの判断を読みにくくする場合は図を分割する。

## 非対象規約

- 修正前調査の実施は扱わない。
- 人間修正レビューの代替判断は扱わない。
- 修正実行入力の作成は扱わない。
- プロダクトコードの変更は扱わない。
- プロダクトテストの変更は扱わない。
- docs 正本本文の更新は扱わない。

## 出力規約

- 判断結果: `修正方針判断` の完了、未完了、停止の判定を返す。
- 観測済み問題: 根拠から確認できる問題を返す。
- 原因の原因: 表面症状を生んだ責務違反または契約違反を返す。
- 責務境界: 壊れている責務と壊れていない責務を返す。
- 採用する修正方針: 恒久修正として採用する方針を返す。
- 禁止する修正: 実装 agent に許可しない対症療法を返す。
- 影響ファイル候補: 観測事実に基づく候補を返す。
- 原因箇所シーケンス図正本path: 作成または更新した Markdown の path を返す。
- 原因箇所シーケンス図描画結果path: 作成した SVG、PNG、screenshot の path を返す。
- 原因箇所シーケンス図問題点: 確認済みの問題を返す。
- 原因箇所シーケンス図修正方針: 確認済みの直し方を返す。
- 原因箇所シーケンス図検証結果: Markdown 確認と `mmdc` 構文確認または描画確認の結果を返す。
- 残る不足: 修正へ進めない未確認事項を返す。
- 根拠参照: 判断に使った根拠を返す。
- 禁止事項: 出力にプロダクトコード、プロダクトテスト、docs 正本本文の変更を含めない。

## 完了規約

- 観測済み問題、原因の原因、責務境界、採用する修正方針、禁止する修正が根拠参照付きで返っている。
- 修正方針が既存仕様へ戻す恒久修正として説明されている。
- `null`、状態値、既定値、catch 分岐などの対症療法になりやすい箇所がある場合は、採用または禁止の判断が返っている。
- `原因箇所シーケンス図` の Markdown path が返っている。
- `原因箇所シーケンス図` が原因箇所の呼び出し順序、問題点、修正方針を含んでいる。
- `原因箇所シーケンス図` の Markdown 確認と `mmdc` 構文確認または描画確認の結果が返っている。
- 人間修正レビューへ渡せる判断材料が返っている。

## 停止規約

- 人間観測記録が不足する場合は停止する。
- 修正前調査が不足する場合は停止する。
- 原因が仮説に留まり、採用する修正方針を固定できない場合は停止する。
- `原因箇所シーケンス図` の原因箇所、問題点、修正方針のいずれかが不足する場合は停止する。
- `原因箇所シーケンス図` に未確認の原因または未確認の修正案が含まれる場合は停止する。
- `mmdc` または `mmdc` が要求する Chrome / Chromium が使えず Mermaid 構文確認または描画確認ができない場合は停止する。
- `mmdc` の構文確認が失敗する場合は停止する。
- 仕様変更、機能追加、受け入れ条件の新規判断が必要な場合は停止する。
- 修正方針が対症療法か恒久修正か判断できない場合は停止する。
- 停止時は不足項目、衝突箇所、固定できない判断、戻し先を返す。
