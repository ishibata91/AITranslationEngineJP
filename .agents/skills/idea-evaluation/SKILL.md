# アイデア評価

## 目的

`idea-evaluation` は、`idea-shaping` が固定した最小案を製品コードから分離した砂場で実装し、変更前との比較で価値を確かめる技能である。

比較の結果は、アイデアを支持する材料、棄却する材料、または判断に足りない材料として返す。

## 入力

- 最小案: `idea-shaping` が作った変える対象、変えない条件、比較前の状態、観察する振る舞い。
- 評価対象: 比較に使う入力または利用場面。
- 使える資源: 時間、接続先、機械、データ。

最小案、評価対象、比較前の状態を固定できない場合は、実装と評価を始めず不足を返す。

## 砂場

Codex 本体は、`.gitignore` で除外される `tmp/<task-id>/` などの場所へ、最小案の実装、入力、実行手順、出力を置く。

砂場を使う前に、対象の場所が Git の追跡対象外であることを確かめる。

砂場の実装は、比較に必要な最小範囲に限る。製品コードを変更しない。

外部データまたは秘密情報を repository へ書かない。必要な場合は取得方法、保存場所、除外理由だけを記録する。

## 比較評価

Codex 本体は、比較前とアイデア適用後を同じ入力、設定、接続先、測定方法で実行する。

条件を揃えられない場合は、条件差と予想される影響を記録する。条件差だけを根拠に、アイデアを支持または棄却しない。

評価では次を確認する。

- 期待した効果。
- 予想した副作用。
- 予想外の変化。
- 実行時間、費用、必要資源の差。
- 出力を読む必要がある品質。

数値だけで品質を断定しない。品質が評価対象に含まれる場合は、代表的な出力を読み、観察内容を残す。

## 判定

Codex 本体は、1 回の比較を次のいずれかで返す。

- `支持`: 期待した効果を確認し、採用を妨げる副作用を確認していない。
- `棄却`: 期待した効果を確認できない、反対方向の変化がある、または副作用が効果を上回る。
- `人間判断`: 効果と副作用の重さを測定結果だけで比較できない。
- `判断不能`: 比較条件、入力、測定方法、または資源が不足する。

支持と棄却は、評価した範囲だけに当てはまる。未評価の利用場面へ一般化しない。

アイデアを変更した場合は、変更後のアイデアを別の評価として扱う。効果を得るために同じ評価を反復しない。

## 記録

Codex 本体は、`docs/exec-plans/active/<task-id>/idea-evaluation.md` へ次を記録する。

- 最小案と比較前の状態。
- 砂場の場所と追跡対象外である確認結果。
- 比較前と適用後の実行手順。
- 使用した入力と揃えた条件。
- 効果、副作用、予想外の変化、必要資源の結果。
- 読んだ出力と観察内容。
- 判定と判定が当てはまる範囲。

## 扱わない対象

- アイデアを評価可能な最小案へ具体化する作業。`idea-shaping` が扱う。
- 効果が出るまでアイデアを改良して回す作業。
- 製品コードへの統合と製品仕様の確定。
- 外部資料を網羅して候補を集める調査。`research-protocol` が扱う。
- 原因が実在する不具合の調査と修正。`fix-workflow` が扱う。
