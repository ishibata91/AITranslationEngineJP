# Specification Protocol

## 入力

- 要求: 仕様が満たす内容と要求を識別できる番号。
- 語彙: 主語と目的語に使える正本がある場合だけ受け取る。
- 出力先: 指定がある場合だけ受け取る。

入力の名前、保存場所、作成元の工程を前提にしない。

## 仕様を作る

要求ごとに節を分ける。
各仕様へ要求番号から追跡できる番号を付ける。
どの要求にも対応しない仕様は書かない。

各要求に次の三種類を揃える。

- 正常系: 要求が想定する状況で成立する振る舞い。
- 対象に入る側の境界: 要求の対象範囲の端でも成立する振る舞い。
- 対象に入らない側の境界: 要求の対象外では要求の動作をしない振る舞い。

各仕様に次の情報を書く。

- 仕様文: 利用者から観測できる振る舞いを「〜こと」で終わる文にする。
- 前提条件: 仕様が問われる状況を書く。状況を選ばない場合は「なし」と書く。
- 確かめ方: 成立を判断するために見る画面、出力、送信内容、保存内容などを書く。
- 対応する実テスト: 実テストとの対応を記録できる場所を用意する。対応が未確定の場合は空にする。

確かめ方を書けない振る舞いは仕様にしない。

## 記述規則

- 主語と目的語は要求に現れる語を使う。
- 語彙の正本が渡された場合は、正本にある語も使える。
- 新しい名詞が必要な場合は、語彙へ追加する判断を人間へ求める。
- 語彙へ追加しない場合は名詞を作らず、動作を説明する。
- 設計理由、変更箇所、処理手順、図を書かない。
- 要求のうち満たさない部分がある場合は、対応する要求へ明記する。

## 境界を書けない場合

三種類のいずれかを書けない場合は、要求の対象範囲が確定していない。
不足する境界と、決める必要がある対象範囲を未解決の論点として返す。

## 書かないこと

- 責務配置と実装方法。
- source file、関数、table の変更手順。
- test の設計と実装。
- 承認順序、実行順序、呼び出し元、次の工程。
- 作業管理用の識別子と保存場所。

## 返す成果物

- 要求ごとの仕様。
- 各仕様の前提条件と確かめ方。
- 要求のうち満たさない部分。
- 仕様にできなかった要求と不足情報。
- 指定された出力先へ書いた場合は出力先の path。

## 完了条件

- 全ての仕様が要求へ対応している。
- 各要求に正常系と二つの境界がある。
- 全ての仕様に前提条件と確かめ方がある。
- 全ての仕様文が「〜こと」で終わる。

## 停止条件

- 要求が不足する。
- 要求の対象範囲が不明で、正常系または境界を定められない。
- 観測可能な確かめ方を定められない。
- 必要な語彙を人間の判断なしに追加できない。

停止時は、不足項目、確定できない仕様、判断が必要な語彙を返す。
