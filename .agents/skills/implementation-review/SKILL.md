# Implementation Review

## 入力

- 承認済みの `plan.md`、`design.md`、`spec.md`。
- 実装後のsourceと変更差分。
- `implementation.md`。
- テスト結果。
- 調査結果と追加制約がある場合は該当成果物。

## 実行境界

- 読み取り専用で検証する。
- source、test、設計成果物、実装結果を書き換えない。
- 代替設計を選ばない。
- 人間の承認を代行しない。

## 照合する

- `design.md` の変更点がsourceへ反映されているかを確認する。
- `spec.md` の全仕様が実装されているかを確認する。
- 仕様と実テストまたは観測結果の対応を確認する。
- 変更差分に設計外の責務変更と仕様追加がないかを確認する。
- 呼び出し元、依存先、状態遷移、永続化、外部接続への影響漏れを確認する。
- 必須検証の実行結果と失敗の有無を確認する。
- `implementation.md` と実差分が一致するかを確認する。
- 一時観測ログと未完了のplaceholderが残っていないかを確認する。

根拠を確認できない項目は通過させない。

## 判定する

全ての設計変更と仕様に実装根拠と検証根拠がある場合だけ通過とする。
不一致、未確認、設計外変更が一つでもある場合は否決とする。

## 返す成果物

- 判定: 通過または否決。
- 仕様ごとの実装根拠と検証根拠。
- 否決理由と該当fileまたは成果物の場所。
- 影響漏れ候補。
- 不足資料と未確認範囲。

## 停止条件

- 必須入力が不足する。
- 承認済み設計の版を特定できない。
- sourceまたはテスト結果を確認できない。

停止時は判定可能な範囲と不足資料を返す。
