# Implementation Review

## 入力

- 承認済みの `plan.md`。
- 実装後の変更差分。

## 実行境界

- 読み取り専用で検証する。
- `plan.md` と変更差分だけを読む。
- repository、変更前後のsource、test、設計成果物、実装記録、会話文脈を読まない。
- 代替設計を選ばない。
- 人間の承認を代行しない。

## 照合する

- `plan.md` が要求する変更が、変更差分に実装されているかを確認する。
- 変更差分だけから確定できる不具合を確認する。
- 変更差分だけから確定できる、著しい性能劣化を確認する。

不具合は、変更した制御、値、状態、エラー処理、入出力の矛盾によって、計画された振る舞いを損なう問題に限定する。
著しい性能劣化は、反復ごとの外部呼び出しや永続化によるN+1、全件処理の追加、計算量の明白な増加に限定する。

可読性、命名、慣用、軽微な性能改善、変更差分から確定できない懸念は確認しない。
`plan.md` の範囲から大きく外れた変更は報告するが、否決理由にしない。

## 判定する

`plan.md` の要求を満たさない変更、または確定した不具合か著しい性能劣化が一つでもある場合は否決とする。
上記がない場合は通過とする。

変更差分だけでは判定できない項目を、否決理由にしない。

## 返す成果物

- 判定: 通過または否決。
- `plan.md` の要求ごとの変更差分上の根拠。
- 否決理由と該当する差分のfile、行、理由。
- 計画外の大きな変更がある場合は、判定と分けた報告。
- 変更差分だけでは判定できない範囲。

## 停止条件

- `plan.md` がない。
- 変更差分がない。

停止時は判定を出さず、不足している入力だけを返す。
