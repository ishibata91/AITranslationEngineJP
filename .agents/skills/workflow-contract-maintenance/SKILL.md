# 作業流れ契約保守

## 目的

`.codex` 配下の作業流れ契約を、別 Codex セッションまたは agent が同じ境界、同じ入力、同じ判断、同じ停止条件で読める状態に保つ。

## 対応役割

- 人間から直接依頼された Codex 本体だけが使う。
- 別 agent（`fresh` または `fork`）から呼ばれた場合は拒否する。

## 入力

- 依頼種別: 監査、変更、監査後変更のいずれか。
- 対象: 監査または変更対象の skill、agent 定義、許可済みコマンド、または AGENTS.md の作業流れ記述。
- 既存規約: 整合の基準にする正本（AGENTS.md、関連モジュール skill、関連下位 skill、agent 定義、`.codex/config.toml`、`.codex/README.md`）。

## 正本配置

- skill 形式: frontmatter (`name`、`description`) と Markdown 本文。`.agents/skills/<name>/SKILL.md` に置く。
- agent 定義: frontmatter (`name`、`description`、`model`) と本文。`.codex/agents/<name>.md` に置く。
- agent と skill の紐づけ、起動 `model` は agent 定義の frontmatter に置く。
- 許可済みコマンドの allow と deny は `.codex/config.toml` の permissions に置く。
- 作業流れの skill 体系正本: 入口 skill `.agents/skills/{feature-workflow,fix-workflow}/SKILL.md`、実行段の skill `.agents/skills/{storybook,implementation,finalization}-module/SKILL.md`、および各下位 skill。
- 概念ルールの正本: `AGENTS.md`。skill 名、順序、TRIGGER 条件などの skill 特有知識は、各 skill の frontmatter `TRIGGER when` / `SKIP when` と本文に閉じる。
- プロダクト仕様の正本は `docs/` とし、本 skill は仕様を変更しない。
- 外部正本が衝突する場合は停止し、衝突内容を人間へ返す。

## 規約配置表

skill 内に書く内容は次の表で拘束する。

| 規約 | 書く | 書かない |
| --- | --- | --- |
| 入力規約 | 必須入力、非必須入力、承認状態 | 判断基準、出力形、完了、停止 |
| 外部参照規約 | skill 外の正本、参照優先順位、衝突時の扱い | skill 内の表、手順、出力義務 |
| 内部参照規約 | skill 内の表、DAG、分類、各参照が拘束する判断 | 外部正本、手順、出力義務 |
| 判断規約 | 担当役割が判断してよい範囲と外す範囲 | 入力必須、出力形、戻し先 |
| 非対象規約 | skill が扱わない成果物、判断、変更対象、他へ渡す対象 | 不足、衝突、停止 |
| 出力規約 | 返す情報、置き場所、粒度、含めないもの | 判断、完了、停止 |
| 完了規約 | 完了状態、必要根拠、検証、完了時に返す情報 | 非対象、停止 |
| 停止規約 | 進めてはいけない状態、戻し先、人間判断条件 | 通常の判断基準、扱わない対象 |

## 監査観点表

| 観点 | 確認内容 |
| --- | --- |
| 既存規約整合 | AGENTS.md、対象 skill、対象 agent 定義、承認済み判断に従っているか |
| 規約項目抽出 | 対象が固定している規約を抽象名ごとに 1 文で示せるか |
| 依存関係網羅 | 対象が依存する skill、agent 定義、契約、成果物が漏れなく列挙されているか |
| 役割実行可能性 | 入力、書き換え範囲、出力、戻し先、停止条件が揃って実行可能か |
| 矛盾検出 | 対象内または依存先との間に責務、入力、出力、完了、停止の矛盾がないか |

## 拘束条件

- skill は判断基準とする。手順、定型書式、参照タイミング一覧、知識範囲一覧は持たない。
- 規約の 1 文は、担当役割、担当役割が触る物、担当役割が行う動作の 3 つが取れる形で書く。
- 主語は担当役割にする（Codex 本体、人間、agent 名、skill 名）。
- 目的語は読み手が指させる物にする（file、節、欄、行、値、command）。
- 動詞は実行できる動作にする（書く、消す、番号を振る、並べる、確かめる、返す、止める）。
- 担当役割が読み直して気づくことを求める規約は、成果物の欄と書式で置き換える。書き手が埋められない欄は空欄として残り、読み手が空欄を見て判断できる。
- 規約は肯定形で書き、担当役割が何をするかを示す。否定形は、明確に禁止したい振る舞いを止める時だけ使う。
- 禁止したい書き方を伝える時も、望む書き方を肯定形で示す。禁止例の語句を引用として本文へ残さない（読み手が禁止例と規約本文を取り違える）。
- 入力規約と出力規約の各項目は `名前: 説明` 形式で書き、1 項目に複数の意味を含めない。
- 入力規約と出力規約の項目名は、指す対象が 1 つに定まる具体名にする。
- 規約配置が曖昧な場合は、入力、判断、非対象、出力、完了、停止のどれを拘束する内容かで分類する。
- 規約項目が別 skill の担当成果物の作成規約または品質判断である場合は、担当 skill へ移動する。
- ファイル名、agent 名、skill 名、command 以外の英語由来名詞は、解釈の幅が狭い日本語へ置き換える。
- 廃止ファイル、旧参照、参照先を持たない空ファイル、禁止文言だけの説明ファイルは残さない。
- agent ごとの入力、出力、完了、停止の規約は対応 skill へ統合し、独立ファイルに散らさない。
- AGENTS.md には概念ルールだけを残す。
- 監査は既存規約への適合だけを評価する。
- 矛盾がある場合は、矛盾箇所と人間判断項目を返す。修正内容の確定は人間へ委ねる。

## 扱わない対象

- プロダクトコード、プロダクトテスト、プロダクト仕様文書の変更。
- 削除理由または削除後の正本確認先がない削除。
- 推測による権限不足や所有者不明の補完。

## 返す成果物

- 対象: 監査または変更した `.codex` 配下の対象名とパス。
- 規約要約: 対象が固定している規約を抽象名ごとに 1 文で。
- 既存規約整合判定: 従うべき規約と、従っているかの判定を根拠付きで。
- 依存関係と整合結果: 依存先一覧と、入力・出力・完了・停止の整合結果。
- 役割評価: 入力、書き換え範囲、出力、戻し先、停止条件の妥当性。
- 更新・削除ファイル: 変更したファイル、削除理由、削除後の正本参照先。
- 検証結果: 実行した検証または未実行理由。
- 人間判断項目: AI だけで確定できない境界、削除、責務分割、名前変更。

## 完了条件

- 対象の形式が既存 SKILL.md または agent 定義に揃っている。
- 監査時は、既存規約への適合判定が根拠付きで返っている。
- skill 本体に手順、定型書式、参照タイミング一覧、知識範囲一覧が残っていない。
- ファイル名、agent 名、skill 名、command 以外の英語名詞が本文に残っていない。
- 規約の各文から、担当役割、担当役割が触る物、担当役割が行う動作の 3 つを取り出せる。
- 担当役割が読み直して気づくことを求める規約が残っておらず、成果物の欄と書式で書かれている。
- 規約が肯定形で書かれ、否定形は禁止したい振る舞いに限られている。禁止例の語句が本文に残っていない。
- 入力規約と出力規約が `名前: 説明` で書かれ、1 項目 1 意味で揃っている。
- 非対象規約と停止規約が混在していない。
- 許可済みコマンドが `.codex/config.toml` の permissions に置かれている。
- AGENTS.md に skill 特有知識（skill 名、順序、TRIGGER 条件など）が残っていない。

## 停止条件

- 別 agent（`fresh` または `fork`）から呼ばれた。
- プロダクトコード、プロダクトテスト、プロダクト仕様文書の変更が混ざる。
- agent 定義に実行境界、起動 `model`、所有者、責務境界のいずれかが欠ける。
- 残す英語表記がファイル名、agent 名、skill 名、command のどれにも当たらない。
- 削除理由または削除後の正本確認先がない削除を要求された。
- 決定済み規約の正本が不明、依存対象が網羅できない、または特定役割の範囲が不明。
- 停止時は不足項目、衝突箇所、戻し先を返す。
