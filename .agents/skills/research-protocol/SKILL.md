# Research Protocol

## 目的

`research-protocol` は、ループで回す実験の判断基準と、`criteria.md` と `loop-log.md` の書き方を固定する作業プロトコルである。実験の段取り（何を作り、どの順で承認を取るか）は `experiment-workflow` が持つ。

品質を上げる実験は、原因が 1 つ実在する不具合の究明と構造が違う。不具合は原因が 1 箇所にあるので候補を潰せば収束するが、品質は複数の要因が同時に効くため、潰すのでなく効果の大きさを積み上げる形になる。どこで止めるかを先に決める必要があり、そのための判断基準を本 skill が持つ。

## 対応役割

- Codex 本体が task 文脈を持ったまま読んで適用する。
- `達成条件レビュー` は `criteria_reviewer` agent（`fresh`、読み取り専用）が担う。
- `作り込みの検査` は `metric_gaming_reviewer` agent（`fresh`、読み取り専用）が担う。
- `選択肢の調査` は `researcher` agent（`fresh`、読むことと検索だけ）が担う。
- 呼び出し元は `experiment-workflow`、または同等の入力を渡す上位 skill とする。

## 呼び出し元から渡される情報

- 事象: 人間が見た、実験を起こす元になったこと。
- 変える対象: 実験で書き換える対象の一覧。
- 使える資源: 使える機械、外部の接続先、外部データ、1 回の実験にかかる時間。

## 作業前に読む正本

- `criteria.md` の雛形: `docs/exec-plans/templates/task-folder/criteria.md`。
- `loop-log.md` の雛形: `docs/exec-plans/templates/task-folder/loop-log.md`。
- 測定値の雛形: `docs/exec-plans/templates/task-folder/measurements.csv`。
- 判断基準の根拠と出典: `docs/references/research-methods.md`。判断に迷う場合と、規約の根拠を確かめる場合に読む。この資料は機械翻訳の研究を出典に持つが、主張は繰り返す実験一般へ一般化して読む。
- 外部成果物が不足または衝突する場合は停止し、衝突箇所を返す。

## 分離1 探索の段と確証の段を分ける

Codex 本体は、実験を探索の段と確証の段に分け、どちらの段にいるかを `loop-log.md` の各回の段の欄へ書く。

- 探索の段: データを見て構造を見つけ、仮説を作る。見る値と測り方を自由に変えてよい。
- 確証の段: 実験の前に固定したものだけを見る。仮説、予測、判定の境界、測定手順、標本数を先に書き、回している間に変えない。

Codex 本体は、探索の段で見つけた構造を、同じ標本で確証の根拠にしない。探索で作った仮説は、確証の段で別の標本にかける。

Codex 本体は、探索から出た仮説を `loop-log.md` の仮説の表の出どころの欄へ、探索から出たと書く。

Codex 本体は、確証の段で固定する対象と、足してよい対象を分ける。

- 固定する: 判定の境界、測定手順、標本の分け方。
- 足してよい: 仮説の候補。足した場合は足した回を `loop-log.md` へ書く。

## 分離2 標本を開発用と評価用に分ける

Codex 本体は、標本を開発用と評価用に分け、分けた根拠（層別の軸と件数）を `criteria.md` の標本の表へ書く。

- 開発用: ループの各回で測る。値の差が偶然かを確かめず、値の動きだけを見る。
- 評価用: 達成の判定のときだけ測る。使った回数を `criteria.md` の標本の表へ書く。

Codex 本体は、標本数の見積もりを評価用に対して行う。検出したい差の大きさを先に決め、その差を見分けられる件数を見積もる。見積もった件数が資源に収まらない場合は、検出したい差を大きく取り直すか、人間へ論点として上げる。

Codex 本体は、層別の軸を、測る値を偏らせる要因が覆われるように選ぶ。

Codex 本体は、評価用を見る回数が増えた場合、増えた事実を `loop-log.md` へ書く。同じ標本を見て繰り返し判断すると、その標本に合わせ込む結果を招く。

## 分離3 ループを止める条件と採否の判断を分ける

Codex 本体は、判定の境界をループを止める条件として扱い、採否の判断と分ける。

- 判定の境界: 満たすまでループを回す。満たしたらループを止める。
- 採否: 人間が標本を読んで決める。自動で測った値だけで決めない。

Codex 本体は、人間が採らないと決めた場合、その理由を新しい仮説として `loop-log.md` の仮説の表へ書き、次の回へ回す。判定の境界を動かさない。

## 達成の線の置き方

Codex 本体は、達成条件の各行の達成の線を、目指す位置と届く見込みの 2 つから置き、両方を `criteria.md` の線の出どころの欄へ書く。目指す位置だけでは線の位置が決まらない。目指す位置と変える前の値の間のどこへ線を置くかが残るためとする。

- 目指す位置: その値がどこまで来れば事象が解消するか。同じ数え方で測った比べる相手の値、または事象が解消する水準を書く。比べる相手が何かを添えて書く。
- 届く見込み: `予備の回` で対象を 1 つ変えたときの動き幅を書く。`選択肢の調査` が返した報告されている効果の大きさと、前の task の実績があれば併せて書く。

Codex 本体は、線を目指す位置と変える前の値の間へ置く場合、変える前の値から線までの隔たりが `予備の回` の動き幅の何回分に当たるかを書く。回数から次を判断する。

- 回数がループで回せる回数を超える: 届く見込みが無い。線を変える前の値へ近づけて置き直すか、変える対象を選び直す。
- 回数が 1 回分以下: 対象を 1 回変えるだけで満たせるため、ループを回す意味が無い。線を目指す位置へ近づける。

Codex 本体は、ループで回せる回数を、呼び出し元から渡された 1 回の実験にかかる時間と使える資源から見積もり、`criteria.md` の線の出どころの欄へ書く。

Codex 本体は、測りやすさ、実装の容易さ、切りの良い数を線の出どころにしない。これらは事象が解消するかと関わらないため、満たしても事象が残る線になる。

Codex 本体は、`予備の回` で動き幅が揺れの底以下だった行について、その対象がその行に効かないと判断する。変える対象を選び直して `予備の回` をやり直す。選び直しても動かない行は診断の表へ移す。

Codex 本体は、線の出どころを埋められない行を達成条件へ置かず、診断の表へ移す。

Codex 本体は、達成の線の値を自分で決める。人間が承認するのは目的への貢献の欄とし、線の値を人間の承認対象にしない。線が働く形かは `達成条件レビュー` が検証する。線が高いか低いかは、`達成条件レビュー` も人間も判定しない。

## 揺れの底の測定

Codex 本体は、準備の段で対象を変えずに同じ条件で 2 度測り、達成条件の各行について 2 度の値の差を揺れの底として `criteria.md` の揺れの底の欄へ書く。同じ条件で測っても値は動くため、動く幅を先に知らないと、変えた効果と揺れを区別できない。

Codex 本体は、揺れの底を測った 2 度分を `measurements.csv` の 0 回目として 2 行で書き、変えた対象の欄へ 1 度目と 2 度目の別を書く。

Codex 本体は、2 度測れない行を達成条件へ置かず、診断の表へ移す。人が標本を読んで数える行は 2 度読む手間がかかるため、置き続ける判断をするなら 2 度読む。揺れの底が無い行は、値の差が揺れで説明できるかを確かめられない。

Codex 本体は、割合で測る行について、変える前の値と達成の線の差が揺れの底以下の場合、達成の線を見分けられる標本の件数を見積もり直す。標本の件数を増やすと揺れの底が下がるためとする。

- 見積もった件数が資源に収まる: 件数を増やし、増やした件数で変える前の値と揺れの底を測り直して達成条件に残す。
- 見積もった件数が資源に収まらない: 診断の表へ移し、移した理由を診断の表へ書く。

Codex 本体は、件数で数える行について、悪化が起きていない回でも達成の線を超える確率を見積もり、`criteria.md` の線の出どころの欄へ書く。見積もった確率が 5% を超える行は、次の順で対処する。

- 達成の線を、変える前の件数から離れた位置へ置き直す。線を変える前の件数と同じ位置に置くと、標本の件数を増やしても確率は下がらない。件数を増やすと平均も比例して増え、線が平均の位置に残るためとする。
- 離した線が事象の解消と結びつかなくなる場合は、診断の表へ移し、移した理由を診断の表へ書く。

この 5% は本 skill が定める判定の厳しさであり、値を変える判断は人間が行う。

Codex 本体は、線を置き直す作業を `達成条件レビュー` の通過より前に終える。実測を見て線を置き直すことは、通過前であれば正規の手順とする。通過より後に線を動かすと `作り込みの検査` が否決する。

## 仮説の立て方

Codex 本体は、対立する仮説を 2 つ以上立て、`loop-log.md` の仮説の表の各行へ予測と落ちる条件を書く。

- 予測: その仮説が正しい場合に、どの値がどちらへどれだけ動くか。
- 落ちる条件: 予測が外れたとき、その仮説が落ちると言える形。

Codex 本体は、仮説を 1 つしか立てられない場合、立てられない理由を仮説の表へ書く。

Codex 本体は、どの値がどう動いても説明できてしまう仮説を、落ちる条件を書ける形まで絞り込む。

## 要因の振り方

Codex 本体は、変える対象の数と、要因の間で効果が変わるかどうかで振り方を選び、選んだ振り方を `criteria.md` へ書く。

- 変える対象が 1 つ: 1 回で 1 つを変える。
- 変える対象が 2 つ以上で、要因の間で効果が変わる見込みがある: 組み合わせで振る。何回で個別の効果と要因の間の効果を分けられるかを書く。
- 要因の間で効果が変わることが既に分かっている: その要因を 1 つの塊として扱ってよい。塊にすると個別の効果は測れなくなるため、個別の効果が要る場合は塊にしない。

Codex 本体は、1 回で 1 つだけ変える形を選んだ場合、要因の間で効果が変わらないと判断した根拠を `criteria.md` へ書く。要因の間で効果が変わる場合にこの形を選ぶと、ある要因を変えた回で効果が出ず別の要因を変えた回で急に効く形になり、効かなかった要因を効かないと結論してしまう。

Codex 本体は、限られた回数を段階に配分する。まず少ない回数で効く要因を絞り、絞れた要因について回数を足して要因の間の効果を測る。

## 測定手段の固定

Codex 本体は、測定手段を確証の段の間で変えない。測定手段は、数え方、標本の選び方、使う道具、外部の接続先を含む。

Codex 本体は、測定手段を変える必要が出た場合、過去の全ての回を新しい測定手段で測り直し、測り直したことを `loop-log.md` の測定手段を変えた記録へ書く。測り直せない場合は変えない。

Codex 本体は、測定手段を変えた回を境に、前後の回を直接比べない。

Codex 本体は、値が動いた原因が変えた対象か測定手段かを分けられない場合、分けられないことを `loop-log.md` へ書く。

## 値の差を改善と呼ぶ条件

Codex 本体は、評価用の標本で測った値の差を改善と呼ぶ前に、標本の取り方の揺れで説明できないことを確かめる。使った手続きと試行の回数を `loop-log.md` へ書く。

Codex 本体は、複数の値や複数の条件のどれが効いたかを探す場面で、補正した手続きを使う。同時に多く比べると偶然の当たりが増える。達成条件に並べた複数の値は、同時に満たすべき条件として扱い、この補正の対象にしない。

Codex 本体は、自動で測った値が達成の線を満たしても、人間が読む標本を併せて採否を決める。

Codex 本体は、自動で測った値を改善の目標そのものに据えない。値を狙って調整した結果が人が読む評価で劣る事例が報告されているため、値は変更が効いたかの確認に使う。

## 標本を読んだ結果の記録

Codex 本体は、標本を読んだ結果を、良い悪いの印象でなく、誤りの種類と重さで記録する。

Codex 本体は、誤りの種類を `criteria.md` の誤りの種類の表へ task ごとに定義し、回の間で変えない。変えると回の間で件数を比べられない。

Codex 本体は、重さを 2 段で付ける。大きい（読んで意味を取り違える、または明らかに壊れている）と、小さい（気づくが意味は通る）。

Codex 本体は、標本を読んだ役割（人間か `fresh` か）を記録へ書く。誰の判断で質が落ちていないと言えるかを、後から辿れる状態にする。

Codex 本体は、標本そのものを砂場へ置き、`criteria.md` と `loop-log.md` へ集計だけを書く。標本が著作物またはライセンスの制約を含む場合は、砂場に置いて repo へ入れない。

## 正解が手元にあるかで手続きを選ぶ

Codex 本体は、比較の基準になる正解が対象ごとに手元にあるかどうかで、使える手続きが違うことを `criteria.md` へ書く。

- 正解が対象ごとにある: その正解と突き合わせる手続きが使える。
- 正解が無い: 対象の入力と出力だけから測る手続きへ切り替える。何をもって改善と呼ぶかの根拠が薄いことを書く。

Codex 本体は、正解がある対象と無い対象を混ぜて 1 つの実験にしない。対象ごとに独立した実験として扱う。

## 収束しないときの扱い

Codex 本体は、立てた仮説がすべて落ちた場合、次のいずれかを行い、行った根拠を `loop-log.md` へ書く。

- 仮説の候補を足す。
- 要因の切り分け方を変える。

Codex 本体は、候補の中で最良であることと、正しいことを分けて書く。候補の集合に正しい説明が含まれている保証は無い。

Codex 本体は、仮説の候補を足しても要因の切り分け方を変えても達成の線へ近づかない場合、人間へ論点として上げる。

## 常に守ることと、採否を決める回で守ること

Codex 本体は、実験の重さによらず次を守る。

- 3 つの分離（探索と確証、開発用と評価用、止める条件と採否）。
- 確証の段で固定する対象を実験の前に書くこと。
- 自動で測った値だけで採否を決めないこと。

Codex 本体は、採否を決める回で次を足して守る。

- 評価用の標本で測り、値の差が標本の取り方の揺れで説明できないことを確かめること。
- 複数の条件のどれが効いたかを探す場合に、補正した手続きを使うこと。
- 人間が読む標本を、誤りの種類と重さで記録すること。

## criteria.md

Codex 本体は、雛形の欄を空欄のまま残し、埋まっていない欄を人間が見て判断できる状態にする。

- 覆う範囲の表: 覆う範囲が狭い言い方から広い言い方へ並べる。各行に、その言い方に当たり前の行の言い方に当たらない事例を書く。事例を書けない行を探す対象にしない。
- 達成条件の表: 目的への貢献の欄が空欄の行を達成条件へ置かず、診断の表へ移す。測りやすさ、既存の値との差の大きさ、実装の容易さを貢献の理由にしない。揺れの底の欄と線の出どころの欄を各行について埋める。人間が承認するのは目的への貢献の欄だけとし、貢献の承認の欄へ承認された日付を書く。
- 診断の表: 達成条件に置かない値を持つ。ループが達成の線を満たさないときに、何が効いていないかを見るために測る。達成条件から移した行は、移した理由の欄へ、線が揺れに埋もれたのか、線を見分けられる件数が資源に収まらなかったのか、線の出どころを埋められなかったのかを書く。
- 選択肢の表: 1 行 1 つで書き、1 つの理由で複数行の採否を決めない。採らない行の棄却が置く前提と今回での確認の欄へ、棄却の理由が置いている前提と、その前提が今回の task で成り立つかの確認を書く。確認を書くまで採否の欄を空欄で残す。呼び出し元から渡された資源を前提から外す判断も行として書き、人間承認の欄を空欄で残す。
- 標本の表: 開発用と評価用の件数と層別の軸と使った回数を持つ。
- 誤りの種類の表: 標本を読むときの分類を task ごとに定義する。

## loop-log.md

Codex 本体は、数値の並びを `loop-log.md` へ書かず、`measurements.csv` へ書く。回が増えても `loop-log.md` が読める状態を保つ。

- 各回の節: 段、変えた対象、測った標本、判定、変更の識別子、標本を読んだ結果の集計と読んだ役割、次にすること。
- 仮説の表: 対立する仮説と、予測と落ちる条件と結果と出どころ。
- 測定手段を変えた記録: 変えた対象と、過去の回を測り直したこと。
- 採否: 人間の判断と理由と、次の回へ回す仮説。

## 測る道具

Codex 本体は、達成条件の表の数え方を実装した道具を砂場へ置く。道具は測るだけで、対象を変えない。

Codex 本体は、道具の出力へ次を入れる。

- 達成条件の各行について、測った値と達成の線と、満たすか満たさないか。
- 数えた対象の件数と、数える対象から外した件数と、外した理由。
- 無作為に選んだ標本。件数を引数で指定できる形にする。

Codex 本体は、道具の出力先を 2 つに分ける。数値と判定は `measurements.csv` へ書き、標本そのものは砂場へ書く。

## 達成条件レビュー

`達成条件レビュー` は、人間承認を取る前に、達成条件と測る道具が達成を測れるかを検証する AI 検証である。`criteria_reviewer` agent が担う。人間承認より前に置くことで、抜け道と揺れによる書き直しを承認の前に終わらせる。

- 入力: `plan.md` のパス、`criteria.md` のパス、測る道具のパス、`measurements.csv` のパス、`task-id`、対象 repo のルート。
- 検証内容:
    - 覆う範囲を広げたかの検証: 覆う範囲の表の各行に、その言い方に当たり前の行の言い方に当たらない事例が書かれているかを見る。事例が書かれていない行は、同じ範囲を別の語で言い直しただけで覆う範囲が広がっていないため否決する。行が 1 つしか無く、行えない理由も書かれていない場合も否決する。
    - 棄却の検証: 選択肢の表の採らないと決めた行の棄却が置く前提と今回での確認の欄が埋まっているかを見る。欄が空欄のまま採否の欄が埋まっている行を否決する。棄却が正しいかは判定しない。
    - 抜け道の検証: 達成条件の全ての行を満たしながら、事象が解消しない出力を 1 つ作れるかを試す。作れた場合は、その出力を示して否決する。作れた出力が `criteria.md` の誤りの種類の表のどれに当たるかを確かめ、どれにも当たらない場合は、標本を読んでも拾えない崩れ方として種類の漏れを返す。
    - 目的への貢献の検証: 目的への貢献の欄が事象の解消に効く理由を述べているかを見る。測りやすさ、既存の値との差の大きさ、実装の容易さだけを理由にしている行を否決する。
    - 数え方の検証: 数え方の欄が実装を読まずに再現できる粒度で書かれているかを見る。測る道具の実装が数え方の欄と一致しているかを照合し、食い違う行を否決する。
    - 線の出どころの検証: 線の出どころの欄が、目指す位置と届く見込みの両方で埋まっているかを見る。片方だけの行、空欄の行、測りやすさと実装の容易さと切りの良い数を出どころにしている行を否決する。
    - 届く見込みの検証: 線の出どころの欄に書かれた `予備の回` の動き幅が、`measurements.csv` の `予備の回` と 0 回目の差と一致するかを照合する。食い違う行を否決する。
    - 回数の検証: 変える前の値から達成の線までの隔たりが、`予備の回` の動き幅の何回分に当たるかを確かめる。回数がループで回せる回数を超える行は、届く見込みが無いため否決する。回数が 1 回分以下の行は、対象を 1 回変えるだけで満たせてループを回す意味が無いため否決する。
    - 揺れに埋もれる線の検証: 変える前の値と達成の線の差が、揺れの底の欄の値を超えるかを確かめる。超えない行は、変えた効果と揺れを区別できないため否決する。`予備の回` の動き幅が揺れの底以下の行も、その対象がその行に効かないため否決する。
    - 見分けられる件数の検証: 件数で数える行について、悪化が起きていない回でも達成の線を超える確率の見積もりが書かれているかを見る。見積もりが無い行と、見積もった確率が 5% を超える行を否決する。
    - 交絡の検証: 測る値が変える対象以外の要因で動くかを確かめる。動く場合はその要因を挙げて否決する。
    - 道具の検証: 測る道具が、達成条件の各行の値と、数えた件数と、外した件数と外した理由と、無作為に選んだ標本を出すかを確かめる。欠けている出力を挙げて否決する。
    - 変える前の値の検証: 現在の値の欄と揺れの底の欄が実データで再現するかを確かめる。再現しない行を否決する。
    - 標本の分け方の検証: 標本の表が開発用と評価用に分かれ、同じ層別の軸で分かれているかを見る。重なっている場合と、検出したい差を見分けられる件数の見積もりが無い場合は否決する。
    - 標本の代表性の検証: 層別の軸が、測る値を偏らせる要因を覆っているかを確かめる。偏りが残る軸の取り方を否決する。
    - 診断の切り分けの検証: 事象の解消に直接効く値が診断の表へ落ちている場合は、漏れ候補として返す。
- 判断範囲: 達成条件の成立可否、数え方と実装の食い違い、抜け道の存在、交絡の指摘、線が働く形かの判定を行う。線が働く形かは、線の出どころが埋まっているか、線と変える前の値の差が揺れの底を超えるか、線を見分けられる標本の件数があるかで判定する。覆う範囲については、前の行の言い方に当たらない事例が書かれているかだけを判定する。棄却については、前提と今回での確認が書かれているかだけを判定する。達成の線の値そのものの大小、選択肢の採否、棄却の正しさは判定しない。
- 出力: 判定（通過または否決）、否決理由（照合したソースの場所または再現した出力つき）、抜け道の出力と作り方、漏れ候補、検証できなかった対象。
- 完了: 達成条件の表の全ての行に判定が付き、覆う範囲の表の全ての行に判定が付き、選択肢の表の採らない行に判定が付き、抜け道の検証を試した結果が作れたか作れなかったかで書かれている。
- 否決時: Codex 本体が同じ文脈で `criteria.md` または測る道具を書き直し、`達成条件レビュー` を再実行する。通過するまで繰り返す。否決を人間承認で越えない。否決理由を解消できない場合は停止して人間へ論点として上げ、ループの段へ入らない。
- 通過時: Codex 本体が通過した日付を `criteria.md` のレビュー節へ書く。この日付が、達成の線と数え方を固定する起点になる。

## 作り込みの検査

`作り込みの検査` は、達成条件を満たした後に、達成のための実装になっていないかを検査する AI 検証である。`metric_gaming_reviewer` agent が担う。

- 入力: `criteria.md` のパス、`loop-log.md` のパス、`measurements.csv` のパス、砂場の標本のパス、測る道具のパス、作業 branch の分岐元 commit、`task-id`、対象 repo のルート。
- 検査観点:
    - 出力の後加工: 分岐元 commit からの差分に、測る値を直接動かす処理が入っていないかを確かめる。測る値に当たる文字列を消す処理、置き換える処理、打ち切る処理を見つけた場合は否決する。
    - 対象の選び方: 測る対象の選び方が回の間で変わっていないかを確かめる。母数が回ごとに変わっている、外す条件が増えている、選ぶ範囲が狭まっている場合は否決する。
    - 原因の分離: 各回で変えた対象が、選んだ振り方と一致しているかを確かめる。1 回で 1 つだけ変える形を選びながら 2 つ以上を変えた回がある場合は否決する。外部の接続先と使う道具が回の間で変わっている場合も否決する。
    - 数え方の変更: 数え方が `criteria.md` のレビュー節に書かれた `達成条件レビュー` の通過日付より後に変わっていないかを確かめる。変わっている場合、過去の全ての回が測り直されているかを確かめ、測り直されていなければ否決する。
    - 達成の線の変更: 達成の線が `達成条件レビュー` の通過日付より後に動いていないかを確かめる。動いている場合は否決する。線の出どころの欄が通過日付より後に書き換わっている場合も否決する。
    - 測る道具の細工: 測る道具が数え方の欄と違う判定をしていないかを確かめる。特定の値を除く条件、閾値の丸め、母数から外す条件が数え方の欄に書かれていない場合は否決する。
    - 標本の質: 砂場の標本を読み、達成条件を満たしながら質が落ちている出力が無いかを確かめる。事象と別の壊れ方が出ている場合は、その出力を示して否決する。
    - 標本の使い分け: 最後の回が評価用の標本で測られているかを確かめる。開発用だけで達成を判定している場合は否決する。評価用を使った回数が回を追って増えている場合は、その回数を示して漏れ候補として返す。
    - 段の記録: 各回に段が書かれているかを確かめる。探索の段で作った仮説が同じ標本で確証の根拠に使われている場合は否決する。
    - 採否と線の分離: 人間が採らないと決めた回の後に達成の線が動いていないかを確かめる。動いている場合は否決する。
    - 誤りの種類の一貫性: 標本を読んだ結果に使った誤りの種類が回の間で変わっていないかを確かめる。変わっている場合は否決する。
    - 読んだ役割の記録: 標本を読んだ役割が回ごとに記録されているかを確かめる。記録が無い回がある場合は、誰の判断で質が落ちていないと言えるかを辿れないため否決する。
    - 診断の値の逆行: 診断の表の値が、達成条件を満たす過程で悪化していないかを確かめる。悪化している場合は漏れ候補として返す。
- 判断範囲: 細工の有無の判定と根拠の提示を行う。達成条件の値の大小、達成の線の妥当性、採否は判定しない。
- 出力: 判定（通過または否決）、否決理由（照合した差分の場所または示す出力つき）、漏れ候補、検査できなかった観点。
- 完了: 検査観点の全てに判定が付き、標本を読んだ結果が質が落ちているか落ちていないかで書かれている。
- 否決時: Codex 本体がループへ戻り、否決理由に当たる変更を差し替えて回を足す。否決を人間承認で越えない。

## 探す前に覆う範囲を広げる

Codex 本体は、選択肢を探す前に、達成したいことを、より多くの事例を覆う言い方へ書き直し、`criteria.md` の覆う範囲の表へ書く。事象の場面だけを覆う言い方で探すと、その場面のためだけに作られた手段しか候補に上がらず、既にある手段が候補から外れる。

Codex 本体は、書き直した言い方ごとに、その言い方に当たり書き直す前の言い方に当たらない事例を 1 つ書く。事例を書けない言い方は、同じ範囲を別の語で言い直しただけであり、覆う範囲が広がっていないので探す対象にしない。

Codex 本体は、書き直しを 2 回以上行い、各回を覆う範囲の表の行として残す。1 回しか行えない場合は、行えない理由を表へ書く。

Codex 本体は、覆う範囲が最も広い言い方を探す対象にする。

Codex 本体は、複数の事象が同じ言い方へ収まる場合、その言い方を 1 行として書き、収まった事象を列挙する。1 つの測る値で複数の事象を覆えるためとする。

Codex 本体は、覆う範囲の表の各行について、標本の各対象に 1 対 1 で付く比べる相手があるかを見る。比べる相手がある行は、比べる相手と突き合わせる手続きを探す対象へ含める。手続きの選び方は `正解が手元にあるかで手続きを選ぶ` 節が持つ。

Codex 本体は、`選択肢の調査` の起動入力へ書き直した言い方を渡し、事象の文そのものを探す対象にしない。

Codex 本体は、`選択肢の調査` が見つからなかったと返した場合、覆う範囲をさらに広げて起動し直す。広げられなくなるまで繰り返す。

Codex 本体は、覆う範囲を広げられなくなり、どの言い方でも手段が見つからない場合に限り、測る手段を自作するか、その行を診断の表へ移す。

Codex 本体は、覆う範囲を広げすぎたかの判定を本節で行わない。広げすぎた言い方から作った達成条件は、達成条件を満たしながら事象が残る出力を作れる形になるため、`達成条件レビュー` の抜け道の検証が落とす。

## 選択肢の調査

`選択肢の調査` は、達成条件を測る手段と対象を変える手段について、自作の前に既存の手法を洗う調査である。`researcher` agent が担う。

- 入力: `plan.md` のパス、事象、探す対象（覆う範囲の表で探す対象にした言い方）、探す手段の別（測る手段か変える手段か）、使える資源、`task-id`、対象 repo のルート。
- 探す範囲: 外部（学会と論文の公開資料、公開されている実装、配布されているデータ）と、repo 内（同じ判定または同じ測定をしている既存の実装）の両方。
- 判断範囲: 選択肢を挙げること、出どころを示すこと、要る資源を見積もること、出どころが報告している効果の大きさを写すことを行う。選択肢の採否は決めない。効果の大きさを自分で見積もらない。
- 出力: 選択肢（1 件 1 つ）、出どころ（参照できる形）、要る資源、報告されている効果の大きさとそれを測った条件、当てはまらない点、探した範囲、渡された言い方ごとの結果、見つからなかった対象。
- 完了: 渡された言い方ごとに、外部と repo 内の両方に当たった結果が返っている。

Codex 本体は、測る手段を自作する前に `researcher` を起動し、結果を `criteria.md` の選択肢の表へ 1 行 1 つで書く。

## 棄却の再確認

Codex 本体は、`fresh` が返した棄却と、前の task が残した採らない判断を、`criteria.md` の選択肢の表の採否の欄へそのまま写さない。`fresh` は task の文脈を持たないため、棄却がこの task の条件で成り立つかを判定できない。前の task の棄却も、棄却した時点の条件を前提に置いた判断である。

Codex 本体は、棄却の理由が置いている前提を取り出し、その前提が今回の task で成り立つかを確かめ、確かめた結果を選択肢の表の棄却が置く前提と今回での確認の欄へ書く。

Codex 本体は、確かめるまで採否の欄を空欄で残す。

Codex 本体は、前提が成り立たない棄却を採らない理由にしない。その選択肢を今回の条件で判断し直す。

## 扱わない対象

- 実験の段取り、成果物の承認順序、branch 運用。`experiment-workflow` が扱う。
- 目的への貢献の欄が人間の困りごとと合っているかの判定。人間が承認する。達成条件に置く値の選定と達成の線の値は Codex 本体が決め、`達成条件レビュー` が検証する。
- 原因が 1 つ実在する不具合の原因究明。`fix-decision` が扱う。単一の原因を確定する進め方と、複数の要因の効果を積み上げる進め方は別である。
- 測る道具の実装。
- 出典の一覧と手法の詳細。`docs/references/research-methods.md` が持つ。

## 返す成果物

- 段の判定: 現在が探索の段か確証の段か、その根拠。
- 覆う範囲: 書き直した言い方の各行と、各行で書いた事例と、探す対象にした言い方。
- 棄却の再確認: 採らない行ごとの、棄却の理由が置いている前提と、その前提が今回の task で成り立つかの確認結果。
- 達成の線の置き方: 達成条件の各行の達成の線と、線の出どころと、揺れの底。
- 診断の表へ移した行: 移した行と、移した理由。
- 標本の分け方: 開発用と評価用の件数、層別の軸、評価用を見た回数。
- 仮説: 対立する仮説と、各仮説の予測と落ちる条件。
- 要因の振り方: 選んだ振り方と、個別の効果と要因の間の効果を分けられる回数。
- 固定した対象: 確証の段で固定した判定の境界、測定手順、標本の分け方。
- 改善と呼べるかの判定: 値の差と、揺れで説明できるかの確認結果、使った手続きと試行回数。
- 標本を読んだ結果: 誤りの種類と重さの集計。
- 達成条件レビューの判定: 通過または否決、否決理由、抜け道、漏れ候補。
- 作り込みの検査の判定: 通過または否決、否決理由、漏れ候補。
- 収束しない場合の扱い: 足した候補、変えた切り分け方、人間へ上げた論点。

## 完了条件

- `criteria.md` の覆う範囲の表の各行に、前の行の言い方に当たらない事例が書かれ、探す対象にした言い方が記されている。
- `criteria.md` の選択肢の表の採らない行の棄却が置く前提と今回での確認の欄が埋まっている。
- `loop-log.md` の各回に段が書かれている。
- `criteria.md` の達成条件の各行に揺れの底と線の出どころが書かれている。
- 件数で数える行に、悪化が起きていない回でも達成の線を超える確率の見積もりが書かれている。
- `criteria.md` の標本の表が開発用と評価用に分かれ、層別の軸と件数が書かれている。
- `loop-log.md` の仮説の表に対立する仮説が 2 つ以上書かれ、各行に予測と落ちる条件と出どころが書かれている。1 つの場合は理由が書かれている。
- 要因の振り方が `criteria.md` へ書かれ、1 回で 1 つだけ変える形を選んだ場合は根拠が書かれている。
- 確証の段で固定した対象が実験の前に書かれ、回している間に変わっていない。
- 採否を決める回で、値の差が揺れで説明できないことが確かめられている。
- 標本を読んだ結果が、誤りの種類と重さで記録されている。
- `達成条件レビュー` と `作り込みの検査` が通過している。

## 停止条件

- 事象が渡されておらず、仮説の落ちる条件を書けない。
- 覆う範囲を広げられなくなり、どの言い方でも測る手段が見つからず、測る手段を自作もできない。
- 対象を変えずに 2 度測れず、揺れの底を出せない。
- 線が揺れに埋もれる行について、標本の件数を増やせず、診断の表へも移せない。
- 標本を開発用と評価用に分けられない。
- 検出したい差を見分けられる件数が資源に収まらず、検出したい差を取り直せない。
- 測定手段を変える必要が出て、過去の回を測り直せない。
- 立てた仮説がすべて落ち、候補を足しても切り分け方を変えても達成の線へ近づかない。
- `達成条件レビュー` の否決理由を書き直しで解消できない。
- `作り込みの検査` の否決理由に当たる変更を差し替えられない。
- 停止時は不足項目、衝突箇所、固定できない判断、戻し先を返す。
