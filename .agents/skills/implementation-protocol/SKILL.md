# Implementation Protocol

## 入力

- 承認済みの `plan.md`、`design.md`、`spec.md`。
- 対象 repository。
- 調査結果と追加制約がある場合は該当成果物。
- `implementation.md` の出力先。

## 実装する

最初に `coding-protocol` を読む。
変更対象の言語とfolderに対応する規約を読む。

`design.md` の変更点と `spec.md` の仕様だけを実装する。
`design.md` と `spec.md` が食い違う場合は停止する。
設計にない責務変更または仕様追加を行わない。

product code、test、fixture、story、観測ログのうち、承認済み設計に必要な成果物を変更する。
一時観測ログは最終検証前に削除する。

## 検証する

`coding-protocol` が対象言語へ定める検証を実行する。
全ての仕様を実テストまたは人間が観測できる確認へ対応づける。
実テストがある場合は `spec.md` の `対応する実テスト` を更新する。

失敗を承認済み設計の範囲で修正する。
承認済み設計を越える変更が必要な場合は実装を止める。

## implementation.mdを書く

次を記録する。

- 変更したfileと変更理由。
- 仕様ごとの実装箇所。
- 実行した検証と結果。
- 未確認事項と停止理由。
- `人間の指摘`。

`人間の指摘`は空欄で作る。
人間が記入した内容を削除または言い換えない。

## 返す成果物

- product codeとtestの変更差分。
- 更新した`spec.md`。
- `implementation.md`。
- 検証結果。
- 停止理由。

## 完了条件

- 承認済み設計の変更点が実装されている。
- 全ての仕様に観測可能な確認結果がある。
- 必須検証に失敗が残っていない。
- 一時観測ログが残っていない。

## 停止条件

- 承認済み成果物が不足または衝突する。
- 実コードが設計の前提と食い違う。
- 仕様追加または設計変更が必要になる。
- 必須検証の失敗を三回の試行で解消できない。

停止時は変更を隠さず、未完了箇所と必要な設計判断を `implementation.md` へ書く。
