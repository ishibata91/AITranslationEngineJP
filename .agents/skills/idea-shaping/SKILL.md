# アイデア形成

## 目的

`idea-shaping` は、曖昧なアイデアを、砂場で試せる最小案へ具体化する技能である。

最小案は、何を変え、何を変えず、どの結果で価値を確認するかを示す。

## 入力

- アイデア: 変えたい対象と意図。
- 利用場面: アイデアが価値を持つ条件。
- 期待する効果: 良くなると予測する対象と理由。
- 制約: 変更できない対象、使える資源、許容できない副作用。
- 調査結果: `research-protocol` が返した候補。ある場合だけ使う。

アイデアまたは利用場面を固定できない場合は、具体化せず不足を返す。

## 最小案

Codex 本体は、最小案を次の対象へ分けて書く。

- 変える入力、処理、出力。
- 変えない条件。
- 比較前の状態。
- 確認したい振る舞い。
- 失敗または副作用として観察する振る舞い。
- 砂場に限定する仮定。

最小案は、製品へ統合する設計にしない。比較に必要な範囲へ絞る。

## 成果物

Codex 本体は、作業計画を使う場合、`docs/exec-plans/active/<task-id>/idea.md` へ最小案を記録する。

成果物は、アイデア、利用場面、期待する効果、最小案、比較前の状態、観察する副作用、評価へ渡す条件を持つ。

`idea-evaluation` は成果物を入力として、砂場への実装と比較評価を行う。

## 扱わない対象

- 外部資料から候補を探す調査。`research-protocol` が扱う。
- 砂場または製品コードへの実装。
- 実行結果の比較評価。`idea-evaluation` が扱う。
- 製品仕様と統合方法の決定。
