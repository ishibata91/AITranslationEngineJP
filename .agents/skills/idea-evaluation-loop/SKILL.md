# アイデア評価ループ

## 目的

Codex 本体は、具体的なアイデアを固定し、変更前と適用後の差から、アイデアが狙った効果を生むかを確かめる。

Codex 本体は、アイデアを効くまで改良しない。アイデアを書き換えた場合は、元の評価を終え、書き換えたアイデアを別の評価として始める。

## 対応役割

- Codex 本体は、評価全体の文脈を持ち、比較条件の固定、PoC の実装、測定、判定を行う。
- 人間は、改善と副作用の両方が確認された場合に、採用を検討する価値があるかを判断する。
- `fresh` は、標本の読み取りを独立して行う必要がある場合に限り使う。Codex 本体は、アイデアの予測または期待する判定を `fresh` へ渡さない。

## 入力

- アイデア: 変更する対象と変更内容。
- 期待する効果: アイデアによって良くなると予測する対象と理由。
- 評価対象: アイデアを適用して比較できる入力または利用場面。
- 使える資源: PoC に使える時間、接続先、機械、外部データ。
- 予想する副作用: 人間が既に想定している悪化。未指定の場合は Codex 本体が候補を挙げる。

Codex 本体は、アイデア、期待する効果、評価対象のいずれかを固定できない場合に作業を止め、不足している入力を人間へ返す。

## 評価前に固定する対象

Codex 本体は、結果を見る前に次の対象を固定し、`docs/exec-plans/active/<task-id>/idea-evaluation.md` へ書く。

- 比較する変更前の状態。
- 適用するアイデアの内容。
- アイデアが正しい場合に現れる差。
- アイデアが効かないと判断できる差。
- 予想する副作用と、副作用を見つける観点。
- 評価する標本と、標本を選んだ理由。
- 変更前と適用後で揃える条件。
- 測る値、または人が出力を読む場合の数え方。
- 支持と棄却を分ける境界と、境界の出どころ。
- 評価を終える条件。

Codex 本体は、境界の出どころを、変更前の揺れ、利用上意味がある最小の差、既存の調査結果、または人間が示した許容範囲のいずれかで書く。Codex 本体は、測りやすい数または切りの良い数を境界にしない。

Codex 本体は、許容できる副作用の大きさを入力または実測から決められない場合、その境界を推測で埋めない。Codex 本体は、効果と副作用の測定結果を人間判断へ渡す。

Codex 本体は、標本に次の対象を含める。

- アイデアの効果が現れると予測する対象。
- アイデアの効果が現れないと予測する対象。
- 予想する副作用が現れやすい対象。
- 通常の利用範囲を代表する対象。

## 比較条件

Codex 本体は、変更前と適用後の間でアイデア以外の条件を揃える。条件には入力、モデル、設定、外部の接続先、標本の選び方を含める。

Codex 本体は、既存のモデル、設定、標本数、接続先を repository の file または command の出力で確かめ、根拠の場所を `idea-evaluation.md` へ書く。Codex 本体は、確かめていない値を現在の条件として扱わない。

Codex 本体は、アイデア以外の条件を揃えられない場合、異なる条件と影響を `idea-evaluation.md` へ書き、その差だけでアイデアを支持または棄却しない。

Codex 本体は、出力に揺れがある場合、同じ条件で複数回測る。固定できる乱数の値がある場合は、その値を変更前と適用後で揃える。

Codex 本体は、人が出力を比較する場合、可能な範囲で変更前と適用後の別を伏せ、提示順を入れ替える。読み手がアイデアを知ったことで評価が偏る可能性を減らす。

## 1回の評価

Codex 本体は、1回の評価で次の対象を記録する。

- 実行したアイデアの内容と、評価を識別する番号。
- 変更前と適用後で揃えた条件。
- 使用した標本。
- 期待する効果について確認した差。
- 予想する副作用について確認した差。
- 予想していなかった変化。
- 処理時間、費用、入力の大きさなど、運用へ影響する差。
- 結果を読んだ役割。
- 判定と根拠。

Codex 本体は、自動で測った値だけで翻訳品質を判断しない。Codex 本体または人間が標本を読み、意味、文脈、文体、情報の欠落について確認する。

## 判定

Codex 本体は、1回の評価を次のいずれかで判定する。

- 支持: 期待する効果と一致する差があり、採用を妨げる副作用を確認していない。
- 棄却: 期待する効果と一致する差がない、反対方向の差がある、または効果に対して副作用が明らかに大きい。
- 人間判断: 期待する効果と副作用の両方があり、どちらを重く扱うかを測定結果だけでは決められない。
- 判断不能: 標本、測定回数、比較条件、または測る手段が不足し、支持と棄却を分けられない。

Codex 本体は、支持または棄却を、測った範囲での判定として返す。未評価の利用場面まで効果を一般化しない。

## ループを続ける条件

Codex 本体は、判定が判断不能の場合に限り、判断を妨げた不足を1つ選び、次の評価で補う。

Codex 本体は、次の評価でもアイデア、変更前の状態、期待する効果、副作用の数え方を保つ。測る手段を変えた場合は、変更前と過去の適用後を新しい手段で測り直す。

Codex 本体は、アイデアの変更が必要になった場合、現在の評価を棄却または判断不能で終える。Codex 本体は、変更後の内容へ新しい評価番号を付け、変更前のアイデアと結果を残す。

Codex 本体は、支持を得るために標本を外す、判定の境界を動かす、副作用の数え方を変える操作を行わない。

## 成果物

Codex 本体は、`docs/exec-plans/active/<task-id>/idea-evaluation.md` に次の情報を残す。

- 固定したアイデアと期待する効果。
- 変更前の状態と比較条件。
- 標本の内訳と選定理由。
- 効果、副作用、予想外の変化、運用への影響の測り方。
- 支持と棄却を分ける境界と、境界の出どころ。
- 各評価の実行条件、結果、判定、次の評価で補う不足。
- 最終判定と、判定が当てはまる範囲。
- 人間判断へ渡した論点と、人間が返した判断。

PoC の出力、測定の途中結果、外部データを repository に入れられない場合、Codex 本体は `.gitignore` で除外される砂場へ置き、`idea-evaluation.md` には場所と集計だけを書く。

## 完了条件

- 固定したアイデアと変更前の状態を指し示せる。
- 期待する効果と副作用を同じ標本で比較している。
- アイデア以外で異なる条件と、その影響を記録している。
- 最終判定が支持、棄却、人間判断、判断不能のいずれかで記録されている。
- 最終判定の根拠と、判定が当てはまる範囲が記録されている。

## 扱わない対象

- 課題を解決できるまで変更案を探索する作業。`experiment-workflow` が扱う。
- 採用を決めたアイデアを製品仕様として設計し、統合する作業。採用後に `design-workflow` へ渡す。
- 原因が実在する不具合の調査と修正。`fix-workflow` が扱う。
- 評価していない利用場面に対する効果の保証。

## 停止条件

- 変更前の状態を再現できない。
- アイデア以外の条件差を記録できない。
- 期待する効果を観察できる標本を用意できない。
- 判断不能の原因を補うために必要な資源が、使える資源を超える。
- 人間判断が必要な交換条件について、人間の判断を得られない。

Codex 本体は、停止時に不足している対象、得られた証拠、確定できない判断、再開に必要な入力を返す。
