# Spec: prebuilt-dictionary-editor

## R-1 用語辞書を編集する

- R-1-1（正常系）: 利用者がテーブルUIから原語、訳語、品詞を持つ用語を作成できること
  - 前提条件: 新しい用語の原語、訳語、品詞が揃っている
  - 確かめ方: テーブルUIで作成と変更を確定を行った後に入力内容を持つ用語が表示されることを確認する
  - 対応する実テスト: REF-15
- R-1-2（正常系）: 利用者がテーブルUIに表示された用語の原語、訳語、品詞、Skyrimカテゴリを確認できること
  - 前提条件: テーブルUIに用語が表示されている
  - 確かめ方: テーブルUIに原語、訳語、品詞、Skyrimカテゴリが表示されることを確認する
  - 対応する実テスト: REF-14、REF-15
- R-1-3（正常系）: 利用者がテーブルUIに表示された用語の原語、訳語、品詞を更新できること
  - 前提条件: テーブルUIに用語が表示されている
  - 確かめ方: テーブルUIで変更と変更を確定を行った後に更新後の内容が表示されることを確認する
  - 対応する実テスト: REF-15
- R-1-4（正常系）: 利用者がテーブルUIに表示された用語を削除できること
  - 前提条件: テーブルUIに用語が表示されている
  - 確かめ方: テーブルUIで削除と変更を確定を行った後に削除した用語が表示されないことを確認する
  - 対応する実テスト: REF-15
- R-1-5（対象に入る側の境界）: 利用者が同じ原語を持つ複数の用語を作成できること
  - 前提条件: テーブルUIに表示されている用語と原語が同じ新しい用語を作成している
  - 確かめ方: テーブルUIで作成と変更を確定を行った後に複数の用語が表示されることを確認する
  - 対応する実テスト: REF-15
- R-1-6（対象に入る側の境界）: 利用者が同じ原語を持つ複数の用語の一つを更新した場合に選んだ用語だけが更新されること
  - 前提条件: 同じ原語を持つ複数の用語がテーブルUIに表示されている
  - 確かめ方: 一つの用語を更新して変更を確定した後に選んだ用語だけが更新されることを確認する
  - 対応する実テスト: REF-15
- R-1-7（対象に入らない側の境界）: 利用者が原語、訳語、品詞を欠く用語を作成または更新できないこと
  - 前提条件: テーブルUIで原語、訳語、品詞のいずれかを欠く内容を入力している
  - 確かめ方: 変更を確定しても保存されないことを確認する
  - 対応する実テスト: REF-15
- R-1-8（対象に入らない側の境界）: 利用者が用語を表示した後に別の編集で変更された場合に更新または削除できないこと
  - 前提条件: テーブルUIに表示した用語が別の編集で変更されている
  - 確かめ方: 変更を確定しても表示時の内容で保存されないことを確認する
  - 対応する実テスト: REF-15
- R-1-9（対象に入らない側の境界）: 利用者が用語辞書が受け付けない品詞を入力した場合に作成または更新できないこと
  - 前提条件: テーブルUIで用語辞書が受け付けない品詞を入力している
  - 確かめ方: 変更を確定しても保存されないことを確認する
  - 対応する実テスト: REF-15

## R-2 テーブルUIで絞り込む

- R-2-1（正常系）: 利用者が原語、訳語、品詞、Skyrimカテゴリの各列で用語をフィルタできること
  - 前提条件: 各フィルタに一致する用語と一致しない用語がある
  - 確かめ方: 各フィルタを入力して検索を行った後に一致する用語だけが表示されることを確認する
  - 対応する実テスト: REF-15
- R-2-2（対象に入る側の境界）: 利用者が51件以上の用語をフィルタした場合に50件ごとのページを移動できること
  - 前提条件: フィルタに一致する用語が51件以上ある
  - 確かめ方: テーブルUIで1ページに50件が表示され、次のページに残りの用語が表示されることを確認する
  - 対応する実テスト: REF-15
- R-2-3（対象に入らない側の境界）: 利用者が用語に一致しないフィルタを入力した場合に用語が表示されないこと
  - 前提条件: テーブルUIのいずれかの列に一致しないフィルタを入力している
  - 確かめ方: 検索後に一致する用語がないことを表示することを確認する
  - 対応する実テスト: REF-14

## R-3 編集APIを読み取り経路から分離する

- R-3-1（正常系）: 利用者がテーブルUIから用語を編集しても読み取り経路が編集APIを呼ばないこと
  - 前提条件: テーブルUIで用語を作成、更新、または削除している
  - 確かめ方: 読み取り経路に編集APIが使われないことを確認する
  - 対応する実テスト: REF-15
- R-3-2（対象に入る側の境界）: 利用者が表示後に変更されていない用語を更新できること
  - 前提条件: 表示後に用語が変更されていない
  - 確かめ方: 変更を確定した後に入力内容が表示されることを確認する
  - 対応する実テスト: REF-15
- R-3-3（対象に入らない側の境界）: 利用者が表示後に変更された用語を更新できないこと
  - 前提条件: 別の編集によって用語が変更されている
  - 確かめ方: 変更を確定しても表示時の内容で保存されないことを確認する
  - 対応する実テスト: REF-14、REF-15

## R-4 行ごとの変更を確定する

- R-4-1（正常系）: 利用者がテーブルUIの行に表示する原語、訳語、品詞を編集し、全て取消または変更を確定できること
  - 前提条件: テーブルUIに用語が表示されている
  - 確かめ方: 編集後に変更した原語、訳語、品詞だけが保存され、全て取消後に変更前の内容が表示されることを確認する
  - 対応する実テスト: REF-14
- R-4-2（対象に入る側の境界）: 利用者が複数のSkyrimカテゴリを持つ用語の行を開いた場合にSkyrimカテゴリごとの行を確認できること
  - 前提条件: テーブルUIに複数のSkyrimカテゴリを持つ用語が表示されている
  - 確かめ方: 最初はSkyrimカテゴリが畳まれ、操作後にSkyrimカテゴリごとの行が表示されることを確認する
  - 対応する実テスト: REF-14
- R-4-3（対象に入る側の境界）: 利用者が行を削除した場合に変更を確定まで削除対象の行がグレーで表示されること
  - 前提条件: テーブルUIに用語が表示され、利用者が削除を操作している
  - 確かめ方: 削除対象の行とSkyrimカテゴリがグレーで表示され、変更を確定前には表示から消えないことを確認する
  - 対応する実テスト: REF-14
- R-4-4（対象に入らない側の境界）: 利用者が変更または削除を保留している間はページングまたは検索できないこと
  - 前提条件: テーブルUIに変更または削除を保留した行がある
  - 確かめ方: 前へ、次へ、検索の操作が無効であることを確認する
  - 対応する実テスト: REF-14

## R-5 行ごとの保留を取り消す

- R-5-1（正常系）: 利用者が編集または削除を保留した用語の行で同じ取消を選べること
  - 前提条件: テーブルUIで編集または削除を保留した行が表示されている
  - 確かめ方: 行の操作に同じ取消が表示されることを確認する
  - 対応する実テスト: REF-14
- R-5-2（正常系）: 利用者が編集または削除を保留した用語の行だけを取り消せること
  - 前提条件: テーブルUIで複数行に編集または削除を保留している
  - 確かめ方: 選んだ行だけが変更前に戻り、別の行の保留が残ることを確認する
  - 対応する実テスト: REF-14
- R-5-3（対象に入る側の境界）: 利用者が編集を保留した用語を削除してから取消を選んだ場合に編集の保留が残ること
  - 前提条件: テーブルUIの同じ行で編集と削除を順に操作している
  - 確かめ方: 取消後に行がグレーでなくなり、編集内容が残ることを確認する
  - 対応する実テスト: REF-14
- R-5-4（対象に入る側の境界）: 利用者が新規作成を保留した用語を取り消した場合に新しい行が表示されないこと
  - 前提条件: テーブルUIで新規作成を操作している
  - 確かめ方: 行の取消後に新しい行が表示されず、変更を確定しても作成されないことを確認する
  - 対応する実テスト: REF-14
- R-5-5（対象に入らない側の境界）: 利用者が一行の保留を取り消しても別の行に保留がある間はページングまたは検索できないこと
  - 前提条件: テーブルUIで複数行に編集または削除を保留している
  - 確かめ方: 一行の取消後に別の保留行が残り、前へ、次へ、検索の操作が無効であることを確認する
  - 対応する実テスト: REF-14

## R-6 編集する行だけを入力欄にする

- R-6-1（正常系）: 利用者が編集を選んだ用語の行だけを入力欄で表示できること
  - 前提条件: テーブルUIに削除保留でない複数の用語が表示されている
  - 確かめ方: 編集を選んだ行だけに原語、訳語、品詞の入力欄が表示され、別の行は文字表示であることを確認する
  - 対応する実テスト: REF-14
- R-6-2（対象に入る側の境界）: 利用者が別の用語の編集を選んだ場合に前の行が文字表示へ戻り、前の行の保留が残ること
  - 前提条件: 一つの用語の行を編集して保留している
  - 確かめ方: 別の行の編集を選んだ後に、新しい行だけが入力欄で表示され、前の行の変更が変更を確定に含まれることを確認する
  - 対応する実テスト: REF-14
- R-6-3（対象に入る側の境界）: 利用者が新規作成を選んだ場合に新しい行だけが入力欄で表示されること
  - 前提条件: テーブルUIに用語が表示されている
  - 確かめ方: 新規作成後に新しい行だけに原語、訳語、品詞の入力欄が表示されることを確認する
  - 対応する実テスト:
- R-6-4（対象に入らない側の境界）: 利用者が削除を保留した用語を編集できないこと
  - 前提条件: 用語の行が削除保留でグレーで表示されている
  - 確かめ方: 削除保留の行に編集操作と入力欄が表示されないことを確認する
  - 対応する実テスト: REF-14
