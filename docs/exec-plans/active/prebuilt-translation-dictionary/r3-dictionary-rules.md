# R-3 辞書項目の単位と辞書作成規則

## 目的

同じ英語表記に複数の意味がある場合でも、Skyrimで使われている意味と公式日本語訳を別の辞書項目として扱う。

R-3は分類規則を固定する段である。R-3の人間確認が終わるまで、17,346件の大量分類、辞書項目の除外、R-4以降の実装を始めない。

## 実データで確認した事実

- 移植済み辞書は17,346件である。
- 同じ`source`を持つ組は1,155組ある。
- 同じ`source`で異なる`dest`を持つ組は19組ある。
- 同じ`source`と`dest`を持つ組は1,142組あり、2,552件のSkyrimの分類が含まれる。
- `derive:*`を`category`に持つ人名の派生項目は529件ある。
- stopwords-isoの1語完全一致で除外できる項目は10件である。
- 日本語WordNet 1.1で英語見出しが一致する項目は853件である。
- 日本語WordNet 1.1で同じ`synset`に`dest`と完全一致する日本語見出しがある項目は400件である。
- 400件のうち145件は複数の`synset`に一致し、13件は複数の品詞に一致する。

stopwords-isoは一般語の意味と訳を持たない。stopwords-isoだけでは、一般辞書に同じ意味と訳があるかを判定できない。

日本語WordNetとの原語と訳語の一致だけでも意味は確定しない。`Frost → フロスト`は3つの`synset`に一致した。`Attack → 攻撃`は9つの`synset`と名詞、動詞の両方に一致した。Skyrimの`NPC_`にある馬の名前を、一般辞書にある人物名の意味と同一とは判定できない。

## tableの分け方

英語表記、意味、Skyrimでの使用箇所、一般辞書との照合、レビュー、変更履歴を別tableにする。

| table | 1行が表すもの | 主な値 |
|---|---|---|
| `dictionary_term` | 1つの英語表記 | `source` |
| `dictionary_sense` | 1つの意味と公式訳 | `term_id`、`dest`、品詞、意味を区別する説明、収録判断、レビュー段階、`revision` |
| `dictionary_occurrence` | Skyrimまたは派生処理で見つかった1つの使用箇所 | `term_id`、`sense_id`、Skyrimの`category`、出どころの種類、出どころの識別子、移植時の訳語、派生方法 |
| `general_dictionary_match` | 1つの意味と一般辞書の1つの意味候補との照合 | `sense_id`、辞書名、version、`synset`、品詞、定義、日本語見出し、一致状態、判定理由 |
| `dictionary_review` | AIまたは人間が行った1回のレビュー | `sense_id`、レビューした者、収録または除外の判断、理由、日時 |
| `dictionary_change` | 1回の値変更 | 対象table、対象`id`、変更した値、変更前、変更後、変更した者、変更理由、日時 |

```text
dictionary_term
  ├── dictionary_sense
  │     ├── general_dictionary_match
  │     └── dictionary_review
  └── dictionary_occurrence ── 分類後に dictionary_sense へ結ぶ

dictionary_change ── 上の各tableの変更を記録する
```

`dictionary_term`は英語表記を重複させない。`Imperial`は1行だけ作る。

`dictionary_sense`は意味ごとに行を分ける。意味を区別する説明は修正されるため、説明文をdatabaseの一意制約には使わない。

`dictionary_occurrence.sense_id`は分類前には空にできる。R-4は移植済みの使用箇所を推測で意味へ結ばず、根拠が揃った後に`sense_id`を設定する。

複数のSkyrimレコードが同じ意味を使う場合は、複数の`dictionary_occurrence`を1つの`dictionary_sense`へ結ぶ。Skyrimの`category`は意味ではなく使用箇所に持たせる。

`derive:two`、`derive:shrt`、`derive:byname`はSkyrimの`category`ではない。`dictionary_occurrence`の派生方法に保存し、Skyrimの`category`へ混ぜない。

### `Imperial`で守る単位

`dictionary_term`には`Imperial`を1行作る。`dictionary_sense`には少なくとも次の3行を別の意味として作れる形にする。

| 原語 | 訳語の例 | 品詞 | 意味を区別する説明 |
|---|---|---|---|
| `Imperial` | `インペリアル` | 名詞 | Skyrimの種族を表す。 |
| `Imperial` | `帝国の`または`帝国軍の` | 形容詞 | 帝国または帝国軍に属することを表す。 |
| `Imperial` | `帝国軍` | 名詞 | 帝国軍または帝国軍に属する者を表す。 |

現在の移植済み辞書には、`Imperial → インペリアル`の`RACE`と`NPC_`がある。`Imperial Legion → 帝国軍`と、`Imperial Bow → 帝国軍の弓`などの複合した原語もある。現在の出どころは`master_term.id`と`category`だけであり、3つの意味へ自動で割り当てる根拠としては不足している。

R-4は不足する根拠を推測で補わない。どの意味か確定できない使用箇所は`dictionary_occurrence.sense_id`を空にして人間判断へ送る。

## 各プロパティを置くtable

| プロパティ | 必要性 | 理由 |
|---|---|---|
| 原語 | `dictionary_term` | 検索と英語原文との照合に使う。 |
| 訳語 | `dictionary_sense` | 一般辞書の日本語見出しと公式訳を比較する。 |
| 品詞 | `dictionary_sense` | `Imperial`の名詞と形容詞、`Lock`の名詞と動詞を分ける。 |
| 意味を区別する説明 | `dictionary_sense` | `Fence`の「柵」と「盗品売人」のような同じ品詞の別の意味を分ける。 |
| Skyrimの分類 | `dictionary_occurrence` | `Frost`の`NPC_`と`MGEF`のように、Skyrim内の用途から意味を絞る。 |
| 出どころ | `dictionary_occurrence` | 公式strings、`master_term`、人名派生、手動追加を区別する。 |
| 一般辞書との一致状態 | `general_dictionary_match` | 自動判定の結果と人間またはAIが確認した結果を分ける。 |
| 一般辞書の参照 | `general_dictionary_match` | 辞書名、version、`synset`、品詞、定義、一致した日本語見出しを保存する。 |
| 収録判断 | `dictionary_sense` | `未判断`、`収録`、`除外`を分ける。 |
| レビュー段階 | `dictionary_sense` | 現在どこまで確認されたかを検索に使う。 |
| レビュー結果 | `dictionary_review` | 過去のAIレビューと人間レビューを消さずに残す。 |
| 変更理由 | `dictionary_change` | 変更前後、変更した者、変更日時と一緒に残す。 |
| revision | `dictionary_sense` | MCPから取得した後の競合更新を防ぐ。 |

品詞は`名詞`、`動詞`、`形容詞`、`副詞`、`その他`、`不明`のいずれかにする。固有名は名詞として扱い、意味を区別する説明で対象を明記する。

## 一般辞書との一致状態

一般辞書との一致状態は次の6つに固定する。

| 状態 | 条件 |
|---|---|
| `未確認` | 一般辞書との照合を実行していない。 |
| `英語見出しなし` | 原語に対応する英語見出しがない。 |
| `同じ表記だけあり` | 英語見出しはあるが、同じ意味と判断できる候補がない。 |
| `同じ意味の候補あり` | 品詞、定義、訳語から同じ意味である可能性がある。自動照合はこの状態までしか進めない。 |
| `同じ意味と訳` | 人間またはAIがSkyrim側の意味と一般辞書の意味と訳を同じと確認した。 |
| `同じ意味と訳ではない` | 人間またはAIが意味または訳の違いを確認した。 |

日本語WordNetの`synset`に原語と訳語が存在しても、自動処理は`同じ意味の候補あり`までにする。`Frost → フロスト`のように、同じ表記と訳語が複数の意味へ一致する場合があるためである。

## 一般語を除外する規則

次の条件をすべて満たした`dictionary_sense`だけを一般語として除外する。

1. 一般辞書との一致状態が`同じ意味と訳`である。
2. 確認に使った一般辞書のversionと意味の識別子が保存されている。
3. 収録判断が`除外`である。
4. 変更理由に、Skyrim側の意味と一般辞書側の意味を同じと判断した根拠がある。
5. AIまたは人間のレビュー結果が保存されている。

自動照合、stopwords-isoとの一致、英語見出しの存在だけでは除外しない。除外対象もdatabaseから削除しない。判定結果と理由を残し、確定した辞書の出力対象から外す。

## 既存の一般語判定の使い方

stopwords-isoの一致結果は、一般辞書との照合を優先するための印として使う。stopwords-isoとの一致だけで除外しない。

人名派生で使っている本文の用法回数は、一般語である可能性を示す補助情報として使う。`lc >= 3`かつ`lc >= uc`という既存条件だけで除外しない。

称号、種族名、短い語を除く既存の人名派生規則は、人名の部分形を作るための安全条件として残す。完成した辞書から一般語を除く条件には流用しない。

## 日本語WordNet 1.1の扱い

日本語WordNet 1.1を最初の一般英日辞書として使う。英語と日本語が同じ`synset`へ結ばれており、品詞と定義を確認できるためである。

日本語WordNet 1.1は配布元が最大5%の項目に誤りがある可能性を明記している。照合結果は候補作成に限り、自動除外には使わない。

英語見出しの一致は853件であり、辞書全体を覆わない。一致しない項目をSkyrim固有と判断しない。R-4の分類結果で不足の種類と件数を確認してから、別の一般英日辞書を追加するか判断する。

## 実データへの適用例

| 原語と訳語 | Skyrimの分類 | 判定 |
|---|---|---|
| `Imperial → インペリアル` | `RACE` | 名詞。Skyrimの種族を表す。一般辞書には英語見出しがあるが、同じ意味と訳の候補は確認できない。 |
| `Imperial → インペリアル` | `NPC_` | 現在の出どころだけでは種族名、人物名、形容詞のどれかを確定できない。意味を区別する説明を`不明`のまま人間判断へ送る。 |
| `Imperial Legion → 帝国軍` | `FACT` | 名詞。Skyrimの軍事組織を表す。`Imperial`の形容詞とは別の辞書項目にする。 |
| `Fence → 柵` | `FACT`、`MGEF`、`SPEL` | 名詞。区域を囲う構造物を表す。日本語WordNetに同じ意味と訳の候補がある。 |
| `Fence → 盗品売人` | `PERK` | 名詞。盗品を扱う人物を表す。`Fence → 柵`とは別の辞書項目にする。 |
| `Frost → 冷気` | `ENCH`、`MGEF`、`SPEL` | 名詞。低温または冷気の効果を表す。`NPC_`の馬の名前とは別の辞書項目にする。 |
| `Frost → フロスト` | `NPC_` | 名詞。Skyrimの馬の名前を表す。日本語WordNetの人物、気象、物質の候補と同じ意味とは判断しない。 |
| `Lock → 錠前` | `MISC` | 名詞。扉などを閉じる器具を表す。日本語WordNetに同じ意味と訳の候補がある。 |
| `Lock → 開錠` | `ACTI`、`DOOR` | 動詞または操作名。`Lock → 錠前`とは別の辞書項目にする。品詞は原文の使用箇所を確認して確定する。 |
| `Ancient → エンシェント` | `derive:two` | 人名派生の出どころを持つ。一般的な形容詞と衝突するため、派生元と本文の用法を確認するまで収録判断を行わない。 |

## 現在の出どころで確定できない範囲

移植済み項目の出どころは`master_term.id`と`category`だけである。公式strings上のplugin、record、field、周辺文脈は保持していない。

`Imperial`の`NPC_`や`Lock`の`ACTI`の意味と品詞は、現在の出どころだけでは確定できない。R-4は確定できない項目を推測で埋めず、`不明`と人間判断が必要な理由を保存する。

## 人間確認が必要な決定

1. 英語表記、意味、使用箇所、一般辞書との照合、レビュー、変更履歴を別tableにする。
2. 日本語WordNetとの自動一致は除外候補の作成までにする。
3. AIまたは人間が同じ意味と訳だと確認した意味だけを除外する。
