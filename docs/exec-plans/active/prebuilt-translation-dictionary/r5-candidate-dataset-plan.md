# R-5 未収録候補データセット作成計画

## 目的

公式stringsを持つベースゲームと公式DLCのESMから英語原文を抽出し、名詞と固有名詞の句を集める。作成中の辞書と一般辞書の情報を付け、軽いagentが登録を検討する価値を文脈付きで仕分けできる候補データセットを作る。

本計画はR-5のデータ作成だけを扱う。製品機能、画面、MCP、正規辞書DBのschemaは変更しない。

## 作る成果物

| 成果物 | 内容 |
| --- | --- |
| `source.sqlite3` | 既存のC#抽出器が公式ESMから取得した英語原文と出どころ。 |
| `candidates.jsonl` | 名詞句ごとに、出現回数、原文、出どころ、抽出理由、辞書照合結果をまとめた仕分け前データ。 |
| `agent-input/` | `candidates.jsonl`を1,000件ごとに分けた送信単位。 |
| `agent-output/` | agentの判断と理由を同じ候補IDへ結び付けた結果。 |
| `classification.sqlite3` | 候補、全出どころ、辞書照合、agentの判断を検索できる検分用DB。 |
| `summary.md` | 入力件数、抽出件数、辞書照合件数、判断別件数、未処理件数、注意が必要な例。 |

`candidates.jsonl`と`agent-output/`は途中結果を後から検証できる形で残す。仕分け結果だけを残して抽出理由や除外理由を捨てない。

## 候補データの単位

同じ英語表記は1候補へまとめる。候補には、その表記が現れた全ての原文上の出どころを結び付ける。同じ英語表記が異なる意味で使われている可能性があるため、英語表記だけを見て意味を1つに固定しない。

候補は最低限、次の値を持つ。

| 値 | 用途 |
| --- | --- |
| `candidate_id` | agentの入力と出力を結ぶ安定したID。 |
| `source` | 原文から抽出した英語表記。 |
| `part_of_speech` | 形態素解析で得た品詞。 |
| `occurrence_count` | 全原文での出現回数。 |
| `occurrences` | `plugin`、`form_id`、`edid`、`rec`、`field`、`ordinal`、英語原文。 |
| `extraction_reason` | 名詞句、固有名詞、既存辞書の言及など、抽出した理由。 |
| `dictionary_matches` | 作成中の辞書にある同じ表記の意味候補。 |
| `general_dictionary_matches` | 一般辞書にある英語見出し、品詞、定義。 |

## 実行手順

### 1. 公式ESMから英語原文を抽出する

既存の`tools/extractor`を使い、入力pluginごとの英語原文を`source.sqlite3`の`extracted_field`へ保存する。新しいESM解析処理は作らない。

抽出後に、plugin別の原文件数を記録する。固定一覧にないpluginが1件でも含まれていた場合は先へ進まない。

### 2. 名詞と固有名詞の句を抽出する

`tmp/prebuilt-translation-dictionary/r5/`に一時的なGoの抽出処理を置く。repositoryが既に依存している`prose`を使い、英語原文を形態素解析する。

抽出単位は単独の名詞だけにしない。連続する固有名詞と名詞、および固有名詞の内部に現れる`of`、`the`、`&`を句としてまとめる。全体の句と単独語を無条件に両方出す処理は、`Raven Rock`から`Rock`だけを大量に作るため行わない。

動的タグ、記号だけの値、空文字列は対象外にする。語句の前後空白と連続する空白を正規化する。大文字と小文字を同じ照合keyにするが、表示用の英語表記と原文は変更しない。

### 3. 作成中の辞書と照合する

正規辞書DBの`dictionary_term`、`dictionary_sense`、`dictionary_occurrence`を読み取り、同じ英語表記の意味候補を候補データへ付ける。

同じ英語表記が辞書DBにあるという理由だけで候補を削除しない。同じ表記の別の意味を失うため、作成中の辞書の意味、訳語、Skyrimの分類と原文をagentへ渡す。

### 4. 一般辞書と照合する

日本語WordNet 1.1の英語見出しを照合し、品詞、`synset`、英語定義を候補データへ付ける。

英語見出しの一致だけで一般語として除外しない。原文での意味と一般辞書の意味が同じかはagentが判断する。

### 5. 軽いagentへ仕分けを依頼する

候補は1,000件ごとの`agent-input/*.jsonl`へ分ける。1,000件は送信単位であり、token上限を保証する値として扱わない。

agentは英語表記だけを見ず、原文、作成中の辞書の意味候補、一般辞書の定義を確認する。同じ英語表記に複数の意味がある場合は、意味ごとに判断を分け、根拠にした出どころを記録する。

判断は次の4種類に固定する。

| 判断 | 意味 |
| --- | --- |
| `candidate` | 作成中の辞書と一般辞書の両方に同じ意味がなく、登録を検討する価値がある。 |
| `existing_dictionary` | 作成中の辞書に原文と同じ意味がある。 |
| `general_word` | 一般辞書に原文と同じ意味がある。 |
| `needs_human` | 原文または辞書の情報だけでは意味を確定できない。 |

全ての判断に日本語の理由を必須とする。agentが判断を返さなかった候補、理由が空の候補、出どころを示さない意味分割は未処理として残す。

### 6. 結果を検分用DBへ保存する

候補、全出どころ、辞書照合、agentの判断と理由を`classification.sqlite3`へ保存する。同じ入力を再実行しても同じ候補IDへ結果が結び付く形にする。

`candidate`だけをR-6へ渡す。`existing_dictionary`、`general_word`、`needs_human`も削除せず、判断と理由を検分用DBへ残す。

## 最初の確認

`Skyrim.esm`だけで次を確認する。

1. `source.sqlite3`に`Skyrim.esm`以外の原文がない。
2. 同じ英語表記の出どころが1候補へ集約されている。
3. 複数語の固有名が単独の一般名詞へ大量に分割されていない。
4. 作成中の辞書に同じ表記がある候補にも原文が残っている。
5. 一般辞書の英語見出し一致だけで除外されていない。
6. agentの全判断に理由と根拠にした出どころがある。
7. 未処理件数を再開可能な形で取得できる。

最初の確認で処理の欠落または大量の断片が見つかった場合は、公式DLCへ広げる前に抽出条件を直す。判断区分や入力項目を変えた場合は、`Skyrim.esm`の仕分けを同じ条件で作り直す。

## 完了条件

- 固定した5つの公式ESMについて、英語原文の抽出件数を記録している。
- 固定一覧にないpluginが候補の出どころへ混ざっていない。
- 全候補に1件以上の原文上の出どころと抽出理由がある。
- 全候補が4種類の判断のいずれか、または未処理として検索できる。
- agentが処理した全判断に理由がある。
- `candidate`、`existing_dictionary`、`general_word`、`needs_human`、未処理の件数を`summary.md`へ記録している。
- 正規辞書DBを変更していない。

## 本計画で行わないこと

- 候補へ日本語訳を付けること。
- 候補を正規辞書DBへ登録すること。
- 人間レビューで採用または除外を確定すること。
- 製品コード、画面、MCPを変更すること。
- 第三者Modを入力に加えること。
