## やることの要点

複数行を 1 リクエストにまとめて翻訳する機構を作る。台詞を 1 行ずつ翻訳する現状を、会話でまとまる行をチャンク単位でまとめて 1 リクエストで送る形へ変える。

- 出力を単一訳文からキー配列（行キーごとの訳文）へ変え、返ったキーだけ確定する部分成功を可能にする。
- 1 チャンクのサイズを行数でなくトークン予算（1 リクエストの最大トークンの目安）で切り、接続・モデルごとに可変にする。行ごとのトークン長差を吸収するため。弱いローカルモデルは小さく、クラウドモデルは大きく指定できる。
- バルク応答が壊れた行・欠けた行は未訳のまま残し、再実行で拾う。バッチ再送はしない。
- 本 task（slice 1）は抽出子・スキーマを変えず、既にグループできる同一 INFO（`response_order`）の複数応答行をまとめる機構をまず作り切る。

会話フロー（DIAL トピック・QUST クエスト・INFO の PNAM 前連結）を抽出してグループを広げる段は、後続 task（slice 2）として `design.md` に起動条件つきで残す。

## やらないことの要点

- 会話に連ならない単独行を、コスト目的だけでまとめる詰め込みはしない。単独行は従来どおり 1 行 1 リクエストのまま残す。
- 会話フローの抽出（C#/Mutagen での DIAL・QUST・PNAM 抽出、migration、`er.md` 同期）は本 task で扱わず slice 2 へ回す。
- 非同期 batch API への対応は扱わない。`gemini-xai-batch-translation` task が別軸で担当する。
- 固有名一貫性の事後検証（known-issues no2 の別項）は扱わない。
