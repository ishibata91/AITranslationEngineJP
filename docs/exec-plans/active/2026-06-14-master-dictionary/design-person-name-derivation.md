# 設計: 人名の部分形を辞書へ派生する規則

本書は、固有名の機械置換で人名の形ゆれを埋める「派生規則」の設計を、現在状態として固定する。判断履歴は `docs/changelog.md` に残す。

## 目的と問題

master 辞書は固有名（地名・物・人名）を確定訳語へ機械置換して訳を一貫させる。人名だけは本文での出方が「フルネーム＋二つ名 / 名のみ / 短名」と揺れ、辞書（`NPC_:FULL` のフルネーム）とかみ合わず、名のみで出た人名が AI 任せになって一貫性が崩れる（例: `Grelod the Kind`→`親切者のグレロッド` は辞書にあるが、台詞の `Grelod` 単独は当たらず AI が `グレロド` と訳す）。

本設計は、`NPC_:FULL` と `NPC_:SHRT` から名のみ訳を機械派生し、安全フィルタで一般語衝突を防いで `master_term` へ焼く。

## 方式（4 段）

1. base 辞書（現行のまま）: REC が `:FULL` で終わる行（`WOOP:FULL` 除く）の Source→Dest。
2. 派生（部分形を 3 種で生成）:
   - shrt: `NPC_:SHRT`（作者記述の短縮別名）の Source→Dest をそのまま。例 `Maro`→`マロ`。
   - byname: Source に ` the ` を含む名。英は前部、日は Dest の末尾カタカナ連。例 `Grelod the Kind`／`親切者のグレロッド`→`Grelod`→`グレロッド`。
   - two: 空白 2 語で Dest に漢字が無く `・` で同数に割れる名。英の空白と日の `・` を整列。例 `Mercer Frey`／`メルセル・フレイ`→`Mercer`→`メルセル`、`Frey`→`フレイ`。
3. 安全フィルタ（過剰置換を構造で止める）。
4. 焼き込み: 派生を `master_term` へ追加（base 衝突は base 優先）。実行時の置換器 `internal/engine/dictionary.go` は無改造。

## 安全フィルタ（規則の中核）

各派生候補を、用法分布と語形で採否する。観測した失敗の手書き除外でなく、構造判定にする。

- 用法比: 本文で各英単語が小文字で出た回数 lc（一般語用法）と、文頭以外で大文字始まりで出た回数 uc（固有名用法）を数え、`lc≥3 かつ lc≥uc` なら一般語とみなし捨てる。例 `Mine`(166/43)・`Master`(56/38)・`Blood`(177/38) は捨て、`Mercer`(0/46)・`Grelod`(0/27) は残す。なお `Imperial`(5/126) は用法比だけでは残る側だが、種族/ハウス語の集合に含むため別条件で捨てる（地の文の `Imperial soldier` 等を `インペリアル` に誤置換しないため）。
- 縮約素体（`aren` 等）を捨てる。`Aren't` の `Aren` の誤当たりを防ぐ。
- 称号（master, lord, captain 等）・種族/ハウス語（dunmer, nord, imperial 等）を捨てる。
- two の category 形容語フィルタ（`Dwarven`・`Skeletal` 等の creature ラベル混入抑制）は本実装に入れない。検証済みの数値（破壊型過剰置換 0・被覆 99.9%・held-out 汎用性）はフィルタ無しで得たものであり、追加は未検証のため対象外とする。起動条件は「ハーネスで過剰置換が減り被覆が落ちないと実測したとき」。
- 日本語側は純カタカナ（＋ー・）に限る。漢字の役割語（`衛兵` 等）を名と誤認しない。
- 英語側は大文字始まり 4 文字以上。
- two は base ゲーム XML 限定で派生する。patch/mod の Source/Dest 対応ずれ（USSEP で `Dunmer Ghost`→`サルティス・アイドレン` が観測された）による誤訳を避ける。

## 構成（合意済み）

- 言語と置き場所: Go の純粋パッケージ。置換器 `dictionary.go` と同じ engine 配下に置く。
- 実行時機: ビルド時生成。派生を `master_term` へ焼く。永続した派生行は目視・差し戻しできる。
- I/O 配線: XML 解析・用法集計の読込・`master_term` 書込はルールクラスの外。

### 純粋ルールクラス（単一・副作用なし）

入力（決定的、ファイル/DB/時刻/乱数に触れない）:
- `NPC_:FULL` の (source, dest) 一覧
- `NPC_:SHRT` の (source, dest) 一覧
- 用法集計（語ごとの lc / uc）
- base の原語集合（衝突判定用）
- 設定（しきい値、称号・種族・縮約の集合、category 語のしきい）

出力:
- 安全な派生 (source, dest, 由来種別) 一覧

純粋ロジック: 3 種の分割と安全フィルタ。用法集計（本文→lc/uc）は別の純粋関数にし、ファイル読込だけ外へ出す。

### ビルド時の配線（クラス外）

1. base master_term は現行の C# extractor が作る。
2. Go のビルド用 command が XML から NPC 対と本文を読み、用法集計を作り、ルールクラスを呼び、base 衝突を除いて派生行を `master_term` へ追加する。
3. 派生行は由来種別が分かるよう category を `derive:<種別>`（`derive:shrt` / `derive:byname` / `derive:two`）にして印を付ける。スキーマ変更は要らない（既存の `category` 列を使う）。実行時の置換器は category を見ず source で照合するため、派生行は無改造で取り込まれる。

## テスト基準

- ルールクラスのユニットテストカバレッジ 100% を基準とする（`go test -cover`）。
- 全分岐を 1 つずつ突く例: `Grelod the Kind` 採用 / `Olava the Feeble` 名前置 棄却 / `Mercer Frey` 分割 / ハイフン語数不一致 棄却 / `Redoran Guard`(漢字 Dest) 棄却 / `Master` 用法比 棄却 / `Imperial` 採用 / `Aren` 縮約 棄却 / 称号・種族 棄却 / category 形容語 棄却 / 純カタカナ外 棄却 / 最小長未満 棄却 / base 衝突 skip。
- I/O 配線（XML→master_term）は結合テストで別に見る。

## 検証で得た事実（base + DLC 実データ）

- 公式日本語 Dest を正解に、会話文 34,496 行（`INFO:NAM1`）で測定。
- 被覆率: 99.9%（正解カナが最終出力に出る、長一致含む）。真の未被覆 4 件は `Frost`（馬の名／冷気の同綴り異義）。
- 部分形の単独被覆: base のみ 54.1% → 派生で 88.5%。`Grelod` の原問題は解消。
- 破壊型の過剰置換（`Master`→`マスター` 全置換、`Aren't`→`アレン't`）: 0。
- 汎用性（held-out）: フィルタ基準を Skyrim 本文だけで作り、未使用の Dragonborn 本文へ適用しても、フィルタ判定の揺れ 0/521、過剰 0.44%（in-sample 1.03% 以下）。
- 検証ハーネス: `_probe7_eval.py`（被覆/過剰）、`_probe8_miss.py`（未被覆内訳）、`_probe9_generality.py`（held-out）。

## 既知の限界

- 同綴り異義（`Frost` 馬／冷気、`Nahkriin` 人物／仮面）は文脈が要るので、文字列置換では原理的に解けない（実測 0.1%）。
- two の creature/汎用ラベル混入は残差が皆無でない（実測 過剰上限率 in-sample 1.03%・held-out 0.44%、いずれも破壊型 0）。category 形容語フィルタは未検証のため本実装に入れていない。
- 第三者（非 Bethesda）mod の XML では未検証。`two` は mod の Source/Dest 対応に依存する。

## 対象外

- 話者経由の参考語注入（案C）。本設計は置換主軸で部分形を埋め、注入は採らない。
- 既存 base 辞書の単一トークン地雷（`Mine`→`鉱山` 等）の掃除。用法比フィルタは流用できるが、別判断とする。
