## 実装範囲（縦切り 3 段）

各段は単体で画面から観測できる成果にする。前段が動かないまま次段へ進めない。

### Slice 1: 機械置換内訳（terms）の供給

- 境界: 結果取得経路に置換内訳を足す。画面の表示器は既存のため触らない。
- 触る対象: `internal/api`（`ResultView` に terms を足し、`ListResultsPage` で各行の原文へ辞書を当て直す）、`internal/engine/dictionary.go`（`Apply` は再利用、辞書構築の公開要否を実装時に判断）、`frontend/src/gateway/translation-gateway.ts`（terms の変換）、wails 生成物の更新。
- 依存: なし（独立）。
- 検証単位: `dict.Apply` の単体テスト（純粋ロジック）。実画面で結果行に内訳が出ることを確認する。
- 注意: `ListResultsPage` は叙述文と台詞の両方を返す。両方に辞書を当てる。ページ取得ごとの辞書構築コストは実装時に判断する。

### Slice 2: 実プロンプト参照 ＋ プロンプト構築の所在移設

- 境界: プロンプト構築を `provider`（AI クライアント層）から `engine`（翻訳手続き層）の純粋関数へ集約する。実行時と取得時の両方でこの関数を使う。実プロンプトを結果行に出す。
- 触る対象: `internal/engine`（プロンプト構築の純粋関数を新設。base 指示・口調指示・置換済み原文を組む。テンプレートはこの段ではコード内に置く）、`internal/provider/openai_compatible.go`（完成プロンプトを受け取る形へ変更、文面定数を撤去）、`internal/api`（`ResultView` に実プロンプトを足し、取得時に再構成）、`frontend`（実プロンプト表示節の追加。表示設計は storybook-module）。
- 依存: なし。ただし Slice 3 の前提になる（テンプレート編集はこの構築関数のテンプレートを差し替える）。
- 検証単位: プロンプト構築の純粋関数の単体テスト。実画面で結果行に実プロンプトが出ることを確認する。

### Slice 3: テンプレート編集・口調精緻化・画面間ナビゲーション

- 境界: base 指示文と口調指示テンプレートを専用テーブルへ永続化し、編集画面から編集でき、翻訳と実プロンプトへ反映する。口調指示テンプレートの構造を見直す。性質文の中身（属性 → 性質文の対応）はハードコードのまま使い、その編集は新 plan で扱う。
- 触る対象: `db/migrations`（テンプレート用 migration を 1 本追加）、`internal/model`（テンプレートの struct）、`internal/store`（テンプレートの CRUD）、`internal/api`（テンプレート CRUD メソッド）、`internal/engine`（Slice 2 の構築関数が DB テンプレートを読む。口調指示の言い回しと差し込み構造を見直す）、`frontend`（テンプレート編集画面、画面間ナビゲーション、gateway ラッパ）。
- 依存: Slice 2（プロンプト構築の集約）。画面が増えるためナビゲーション導入を含む。
- 検証単位: プロンプト構築の純粋関数の単体テスト（テンプレート差し込み）。実画面でテンプレート編集 → 保存 → 実プロンプト反映を確認する。口調指示の合成は実プロンプト参照で確認し、実 LLM の訳文は補助観測にとどめる。
- storybook-module: テンプレート編集画面と画面間ナビゲーションの表示設計を Storybook で扱う。

## テスト設計

単体テストで書く対象（design-module の限定リストに沿う）:

- `dict.Apply`（純粋ルール、置換内訳）: 原文 → 置換済み文と内訳を、境界条件まで覆う。terms 供給はこの再利用で足りる（Slice 1）。
- プロンプト構築の純粋関数: base 指示・口調指示・原文・テンプレート差し込みの組み立てを覆う。LLM 出力品質に直結するため対象にする（Slice 2・3）。

単体テストで書かない対象（実画面操作と実データで確認する）:

- store の CRUD、Wails 境界、画面ロジック、フォーム検証、ナビゲーション。
- DB や LLM を含む統合経路。

実画面・実データの観測点は plan の `完了定義` に従う。実 LLM は LM Studio（別マシン、`http://192.168.0.226:1234`）を使う。

## 後続モジュールへの引き継ぎ

- 画面変更想定: Yes（Slice 1・2 は結果行の表示追加、Slice 3 はテンプレート編集画面の新設と画面間ナビゲーション）。
- storybook-module へ進むか: Yes（Slice 3 の編集画面・ナビゲーション、および結果行の表示追加分）。
- 実装は Slice 1 から順に進める。各 Slice で implementation-module（frontend ロジック・backend・テスト・観測）と、画面表示がある場合は storybook-module を通す。
