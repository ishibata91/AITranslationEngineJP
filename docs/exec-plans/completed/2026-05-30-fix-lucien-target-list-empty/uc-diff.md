# UC 差分候補: fix-lucien-target-list-empty

## 分類

- 分類: 差分なし
- 理由: 既存ユースケースと画面設計の既存期待で、本不具合の問題と期待状態を説明できる。新規の仕様変更や機能追加の判断は不要である。

## 根拠とした入力

- 観測記録: `docs/exec-plans/active/fix-lucien-target-list-empty/observation.md`
- 修正方針判断: `docs/exec-plans/active/fix-lucien-target-list-empty/fix-decision.md`

## 参照した正本

- UC 正本: `docs/usecases/uc-translation-management.md` の フェーズ「翻訳実行」内ユースケース「処理対象を確認する」
- 画面設計正本: `docs/screen-design/screens/term-translation-phase.md` の「E-04 処理対象一覧」

## 既存期待での説明

- ユースケース「処理対象を確認する」の主シナリオ第5項は「処理対象名、処理対象詳細、metadata、ページ操作を表示する」と定める。
- 同ユースケースの完了条件の成功条件は「処理対象一覧または空状態を確認できる」と定める。
- 同ユースケースの代替シナリオ A1「処理対象がない」は、表示できる処理対象がない場合に限り空状態を表示すると定める。
- 画面設計「E-04 処理対象一覧」の状態別表示は、表示可能時に検索、件数、ページ操作、処理対象一覧を表示すると定める。
- 本不具合は、処理対象が実在し進捗母数(4,931)が示すのに、初回表示で処理対象一覧が空状態となる状態である。
- これは「処理対象がない場合だけ空状態」という既存期待からの逸脱として説明できる。

## 確定原因との対応

- 確定原因は frontend 初回ロード経路の取得結果が連番不一致で破棄される反映取りこぼしである(fix-decision.md)。
- 反映取りこぼしを是正すれば、既存の成功条件「処理対象一覧または空状態を確認できる」のうち、処理対象が実在する場合に一覧を確認できる期待へ復帰する。
- 期待値そのものを変える仕様変更ではないため、ユースケース正本の改訂は不要である。

## 備考

- 初回ロード時の取得競合と反映保証は内部実装の振る舞いであり、利用者視点のユースケース記述に追加する必要はない。
- 「処理対象がない」場合に空状態を表示する代替シナリオ A1 は維持されるべきで、本不具合の是正と矛盾しない。
- UC 正本本文は変更していない。本書は差分候補の判断記録である。
