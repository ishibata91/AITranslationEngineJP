# E2E テスト観点差分: fix-lucien-target-list-empty

## 分類

- 分類: 追加候補あり
- 理由: 処理対象が実在するジョブの初回表示で処理対象一覧が反映される、という修正対象を証明する観点が、E2E テスト観点正本に不足している。

## 既存観点の確認

- 既存観点 `E2E-UC-045`（対象画面: 単語翻訳、関連UC: 翻訳段階を開始する）が存在する。
- `E2E-UC-045` は処理対象一覧の表示を「前提条件」として置き、開始ボタン押下後の状態遷移を主に証明する観点である。
- `E2E-UC-045` は初回ロード時に処理対象一覧が空にならないこと自体を期待値として証明していない。
- 関連UC「処理対象を確認する」を対象画面「単語翻訳」で検証する観点は正本に存在しない。
- よって本不具合(処理対象が実在するのに初回0件)を直接証明する観点は不足している。

## 不足の判断

- 不足1: 単語翻訳画面の初回表示で、進捗パネルの母数が 1 以上なら処理対象一覧に行が表示され空状態にならない観点。
- 不足2: 検索操作で件数が反映された状態から画面をリロードした初回表示で、再び空状態にならない観点。
- これらは確定原因(初回ロード経路の反映取りこぼし、リロードで再現)を直接証明する観点である。

## 前提条件の観測可能化(人間レビュー指摘の是正)

- 指摘: 旧 E2E-LTLE-001 と E2E-LTLE-003 は前提条件を「処理対象が実在する/しないジョブカード」と書いていた。
- 問題: 画面設計正本「翻訳管理画面側のジョブカード前提」は「ジョブカードからは処理対象の実在有無を判別できない」と定める。利用者が画面上で観測できない内部状態を前提条件にしていた。
- 規約: E2E テスト規約は前提条件を「テスト開始時に利用者が画面上で確認できる表示状態だけ」で書くと定める。内部状態や DB 内容は前提条件に書けない。
- 是正: 前提条件の観測点を単語翻訳段階画面の初回表示後に移し、進捗パネルの「AI 翻訳対象語」母数表示で書き分けた。E2E-LTLE-001 は母数 1 以上、E2E-LTLE-003 は母数 0 を観測可能な前提状態にした。
- 根拠: UC 正本「処理対象を確認する」は「母数が 1 以上のとき一覧に行が表示される」「母数が 0 のとき空状態を表示する」と定める。画面設計正本「進捗パネル E-03」は「AI 翻訳対象語」母数を表示項目に定める。前提条件の差(母数 1 以上 / 母数 0)から初回表示で期待する状態(一覧に行 / 空状態)が観測差として確定する。

## selector の扱い

- 画面設計「E2E 固定 selector」では、画面全体 `term-translation-phase-screen`、処理対象行 `term-translation-phase-processing-target-row.<target-id>` が固定済みである。
- 画面設計「E-04」では、処理対象一覧領域の `aria-label=処理対象一覧` が固定済みである。
- 一方、進捗母数(AI 翻訳対象語)表示、処理対象「件数」表示、「空状態(処理対象が見つかりません。)」、検索入力欄の固定 selector は画面設計に存在しない。
- 前提条件で観測する進捗母数(母数 1 以上 / 母数 0)はこの未確定 selector に依存するため、E2E 自動化には selector 確定が必要である。
- E2E テスト規約に従い、未確定 selector は独断で補完せず `備考` に未決として書き、不足記録へ回す。

## 観点が止まらなかった理由

- 前提条件(進捗母数 1 以上 / 母数 0)と期待値(母数 1 以上時は初回表示で一覧、母数 0 時のみ空状態)と対象画面(単語翻訳)は UC 正本と画面設計正本で確定でき、観点の論理は判断不足ではない。
- 画面全体と処理対象行の固定 selector は確定済みのため、観点の骨格を実装可能な粒度で書ける。

## 判断不足(人間が確定すべき事項)

- 進捗母数(AI 翻訳対象語)表示の固定 selector が画面設計正本に未定義である。前提条件で母数 1 以上 / 母数 0 を機械的に観測する自動化が現状は書けない。
- 件数表示、空状態(処理対象が見つかりません。)、検索入力欄の固定 selector も未定義である。
- 人間が確定すべき事項: 画面設計正本「E2E 固定 selector の一覧」へ、進捗母数表示・件数表示・空状態表示・検索入力欄の固定 selector を追加するか判断する。これらは `data-testid-gaps.md` に対象画面、対象要素、必要 selector、関連テスト ID として記録済みである。

## data-testid 不足

- 不足する固定 selector: 処理対象件数、処理対象一覧の空状態(処理対象が見つかりません。)、処理対象一覧内の検索入力欄。
- これらは追加候補観点 E2E-LTLE-001 から E2E-LTLE-003 が参照する要素であり、固定 selector が画面設計「E2E 固定 selector」に未登録である。
- 不足は複数行へ広がるため、E2E テスト規約に従い `docs/exec-plans/active/fix-lucien-target-list-empty/data-testid-gaps.md` へ対象画面、対象要素、必要 selector、関連テスト ID を記録した。
