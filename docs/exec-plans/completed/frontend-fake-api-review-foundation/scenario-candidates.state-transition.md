## Candidate Scenarios

### CAND-FFARF-ST-001 fakeAPI 起動で空状態を表示できる

- `根拠要件`: task-frame 完了条件「空状態を fakeAPI で再現できる」、usecase 完了条件「状態パターンごとの表示を確認できる」
- `viewpoint`: state-transition
- `candidate scenario id`: `CAND-FFARF-ST-001`
- `actor`: フロントエンドレビューer
- `trigger`: fakeAPI 起動モードで空状態パターンを指定して フロントエンド を開く。
- `遷移前状態`: フロントエンド は未起動で、API 接続先は未確定である。
- `開始条件`: レビュー起動モードが有効で、空状態パターンが有効な値として渡されている。
- `遷移後状態`: root view は fakeAPI ゲートウェイ を注入された状態で起動し、対象画面は空状態として表示される。
- `期待結果`: Wails バインディング と バックエンド を呼ばず、空状態の 表示モデル が描画される。
- `観測点`: agent-browser 上で空状態の表示を確認でき、network / Wails 側の本番呼び出しが発生しない。
- `関連詳細要求タイプ`: 起動モード、DI による差し替え、空状態、混入防止
- `採用判断材料`: fakeAPI レビュー起動の最小成功遷移として採用候補にする。
- `競合注意`: 空状態の定義を画面別 モックデータ 側へ寄せるか、共通 状態パターン 側へ寄せるかは designer 統合時に確認する。

### CAND-FFARF-ST-002 空状態から読み込み中状態へ切り替えられる

- `根拠要件`: task-frame 完了条件「読み込み中を fakeAPI で再現できる」、coding-guidelines-フロントエンド UX 規約「読み込み中を画面上で区別できる」
- `viewpoint`: state-transition
- `candidate scenario id`: `CAND-FFARF-ST-002`
- `actor`: フロントエンドレビューer
- `trigger`: fakeAPI レビュー画面で読み込み中 状態パターンを選ぶ。
- `遷移前状態`: fakeAPI 起動モードで対象画面が空状態として表示されている。
- `開始条件`: 状態パターン切替が レビュー起動モード内で行われ、読み込み中 状態パターンが登録済みである。
- `遷移後状態`: 対象画面は読み込み中状態へ遷移する。
- `期待結果`: 以前の空状態データは表示に残らず、読み込み中の表示だけが観測できる。
- `観測点`: 表示は読み込み中として区別でき、成功データ、失敗メッセージ、設定不足メッセージが同時に表示されない。
- `関連詳細要求タイプ`: 状態パターン、読み込み中、表示状態の排他
- `採用判断材料`: レビュー中の 状態パターン切替が表示状態を置き換えることの採用候補にする。
- `競合注意`: 状態パターン切替 UI を作るか、URL または起動設定で切り替えるかは UI 設計側に残す。

### CAND-FFARF-ST-007 画面固有モックデータの追加で新しい成功状態へ遷移できる

- `根拠要件`: task-frame 完了条件「画面固有のモックデータを ユースケース task 側で追加できる」
- `viewpoint`: state-transition
- `candidate scenario id`: `CAND-FFARF-ST-007`
- `actor`: implementation task author
- `trigger`: ユースケース task 側で画面固有モックデータと成功 状態パターンを追加する。
- `遷移前状態`: fakeAPI 基盤は存在するが、対象画面固有のモックデータ は未登録である。
- `開始条件`: 追加される モックデータ は対象画面の フロントエンド API contract に適合している。

- `期待結果`: 新しい モックデータ は レビュー起動時だけ使われ、本番 API、永続化、本番初期状態 へ混入しない。

### CAND-FFARF-ST-008 本番起動から fakeAPI 状態へ遷移してはいけない

- `根拠要件`: task-frame 完了条件「本番起動では fakeAPI が選ばれない」、非対象「バックエンド の本番挙動変更」
- `viewpoint`: state-transition
- `candidate scenario id`: `CAND-FFARF-ST-008`
- `actor`: application user
- `trigger`: 本番起動で fakeAPI 状態パターン指定または レビュー用設定が残っている。
- `遷移前状態`: フロントエンド は本番起動モードで起動している。
- `開始条件`: 本番起動では レビュー起動モードが無効である。
- `forbidden transition`: 本番起動状態から fakeAPI ゲートウェイ 注入状態へ遷移してはいけない。
- `遷移後状態`: 本番ゲートウェイ が選ばれ、fakeAPI 状態パターン は無視または拒否される。
- `期待結果`: fakeAPI と モックデータ は本番 API、永続化、本番初期状態に影響しない。
- `観測点`: 本番起動では fakeAPI 固有の状態パターンが選択されず、Wails バインディング adapter 経由の本番ゲートウェイ が維持される。
- `関連詳細要求タイプ`: 禁止遷移、本番混入防止、DI 境界
- `採用判断材料`: hard gate に近い混入防止シナリオとして採用候補にする。
- `競合注意`: 起動モード判定の正本は実装範囲側で明確化が必要になる。

### CAND-FFARF-ST-009 未登録 状態パターン へ切り替えてはいけない

- `根拠要件`: task-frame 完了条件「状態パターンごとの表示を確認できる」、usecase 出力「実画面レビュー用状態パターン一覧」
- `viewpoint`: state-transition
- `candidate scenario id`: `CAND-FFARF-ST-009`
- `actor`: フロントエンドレビューer
- `trigger`: fakeAPI 起動モードで未登録 状態パターン 名を指定する。
- `遷移前状態`: fakeAPI 起動モードで対象画面が既知の状態パターンを表示している。
- `開始条件`: 指定された 状態パターン は登録一覧に存在しない。
- `forbidden transition`: 既知の表示状態から未登録 状態パターンの表示状態へ遷移してはいけない。
- `遷移後状態`: 既知の安全な状態に留まる、または レビュー用の明示的な拒否状態を表示する。
- `期待結果`: 未登録 状態パターン は成功状態として扱われず、既存 モックデータ や本番初期状態 へフォールバックしない。
- `観測点`: agent-browser 上で未登録指定の拒否を確認でき、別 状態パターンのデータが誤表示されない。
- `関連詳細要求タイプ`: 禁止遷移、状態パターン一覧、誤フォールバック防止
- `採用判断材料`: 状態パターン registry の防御条件として採用候補にする。
- `競合注意`: 拒否時に空状態へ戻すか、明示的エラーを出すかは人間判断候補である。

### CAND-FFARF-ST-010 同一 状態パターンの再実行で状態が重複または破損しない

- `根拠要件`: task-frame 完了条件「fakeAPI 起動モードが壊れていないことを局所テストで確認できる」
- `viewpoint`: state-transition
- `candidate scenario id`: `CAND-FFARF-ST-010`
- `actor`: フロントエンドレビューer
- `trigger`: 同一の状態パターンを再選択する、または同一 状態パターンで画面を再読み込みする。
- `遷移前状態`: fakeAPI 起動モードで対象画面が任意の登録済み 状態パターンを表示している。
- `開始条件`: 再選択または再読み込みの入力は同一 状態パターンである。
- `遷移後状態`: 対象画面は同じ 状態パターンの表示状態に留まり、重複データや不整合な中間状態を作らない。
- `期待結果`: モックデータの重複挿入、二重実行、永続化書き込み、本番初期状態 の上書きが起きない。
- `観測点`: 再実行後も表示件数、状態表示、操作可否が同じで、バックエンド 側の保存や本番 API 呼び出しが発生しない。
- `関連詳細要求タイプ`: 冪等再実行、局所テスト、混入防止
- `採用判断材料`: fakeAPI 基盤の壊れにくさを証明する候補として採用する。
- `競合注意`: 局所テストの対象を unit へ寄せるか、browser 確認へ寄せるかは designer 統合後の実装範囲で確定する。
