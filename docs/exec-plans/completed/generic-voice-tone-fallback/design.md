# 汎用台詞・PC 発話への口調付与（設計）

- `skill`: superpowers:brainstorming
- `status`: ready-for-human-review
- `source_plan`: `./plan.md`
- `関連`: `docs/exec-plans/completed/2026-06-20-character-persona-from-dialogue/persona-design.md`（口調分類器の境界）, `internal/core/tone/`（口調分類の純粋ルール）

## 1. 目的と親要件

会話レコードの口調付与を、話者を解決できた台詞だけでなく、全会話レコードへ広げる。

親要件は次の 3 つ。

- 話者を特定できない汎用台詞（衛兵・装備反応など）へ口調を付ける。
- プレイヤー発話（DIAL の選択肢）へ口調を付ける。これを「PC 口調」と呼ぶ。
- どの会話レコードも口調が決まり、「口調なし」が残らない状態にする。

「叙述文（narration）」は会話レコードでないため対象外。プレイヤー発話以外で口調が不要なレコードは無い前提で進める。

## 2. 現状の口調パイプラインと欠落（事実）

現状の口調は 4 段で付く。

```
C#抽出器        Go取込              口調生成                   注入/表示
──────────────────────────────────────────────────────────────────────
INFO の         extracted_          ListSpeakerLineSources     LoadLinePersonas
話者解決   →    info_speaker  →     (話者ごとに台詞を束ねる) → (line→line_speaker
(ANAM/            ↓                  tone.Classify(feats,        →persona_character)
GetIsID/        line_speaker          voice)                     口調 directive 注入
GetIsAliasRef)                       →persona_character
```

欠落の正体は 2 点。

1. C# 抽出器は INFO の条件（`GetIsVoiceType`・`GetIsSex`・`GetInFaction`・`GetIsRace`）を `PluginExtractor.cs` で取り出しているが、`SpeakerSqliteWriter.cs` が**解決済み話者しか中心 DB へ書かない**。条件由来の声型・性別はすべて捨てている。
2. 口調は `speaker` 経由でしか line へ届かない。`line` テーブルに声型・性別の列は無い。話者を解決できない汎用台詞には経路が無く、口調なしになる。

口調分類器 `tone.Classify(lines, voice)` は、本文の印が足りない時に voice 気質 prior へ畳む fallback（`DecisionPath="voice"`）を既に持つ。だが voice は話者経由でしか渡らないため、汎用台詞には届かない。

## 3. spike 結果（事実）

実データを read-only の probe（`tools/extractor` の `--probe-generic`）で確認した。対象は `Skyrim.esm` と `Outfit Recognition Framework.esp`。

```
                  汎用INFO    性別/声型あり     真の汎用(話者属性なし)
Skyrim.esm         12,940      3,437 (27%)       8,160 (63%)
Outfit Recognition  1,743         18 (1%)        1,691 (97%)
```

判明した事実。

- **真の汎用が多数派**。Skyrim で 63%、OutfitRecognition で 97% の汎用台詞は、話者の性別・声型・勢力・種族の条件を一切持たない。OutfitRecognition は `WornHasKeyword`（プレイヤー装備）・`GetPCIsSex`（プレイヤー性別）で絞られる。条件はプレイヤー側を見ており、しゃべるのは誰でもよい。話者属性からは何も出ない。
- **性別は綺麗に取れる**。声型 EDID はほぼ全て `Male*`／`Female*` 接頭で始まる（`MaleNord`・`FemaleCommander` など）。`GetIsSex` 条件も別途ある。「男だけ／女だけが言う台詞」は確実に判定できる。mod もバニラ声型を再利用するため耐性がある。
- **役どころは弱く混在**。`MaleGuard`(132)・`MaleSoldier`(530)・`Commander` 系はあるが、声型 token は役・種族・気質が混ざる。FLST も `GuardVoiceTypes`・`CWCitizenAggressiveVoiceTypes` のようにリスト名へ役・気分が埋まるが、構成員は両性・多気質にまたがり、`DefaultNPCVoiceTypes` は全声型を含む。役の抽出は一部しか効かず脆い。

推測（spike から）。汎用台詞の口調を「話者の気質」から決めるのは、多数派の真の汎用に対して根拠が無い。確実に使えるのは「その台詞自身の本文」と「条件が事実として狭めた性別」の 2 つに限られる可能性が高い。

## 4. 設計判断

### 4.1 口調の組み立て式

汎用台詞・PC 発話の口調を、次の重ね合わせで決める（design-module の人間設計レビューで段階選択から自由記述へ変更した）。

```
口調 = 自由記述の既定口調指示文（利用者が書く）＋ 感情段階（本文 1 行から）＋ 性別（一人称・語尾）
```

対人態度は段階（尊大／中立／丁寧）で選ばせず、利用者が自由記述の指示文で書く。汎用台詞と PC 発話で別々の指示文を持つ。感情段階（抑制／中／激情）と性別は、システムが自動で重ねる。

### 4.2 対人態度は自由記述で指定する

対人態度は「誰が・どんな関係で」しゃべるかで決まる。名指し話者は本文集計で対人段階を出すが、汎用台詞は誰でも言うため、また PC 発話はプレイヤーの選択肢のため、集計で対人段階を出す対象が無い。

判断: 汎用台詞・PC 発話の対人態度は段階で選ばせず、**利用者が自由記述の口調指示文で書く**。

- 汎用台詞には「汎用の口調指示文」を当てる。
- PC 発話には「PC の口調指示文」を当てる。
- 段階のセル表（感情段階×対人段階→セル名、`internal/core/tone/classifier.go` の `cellNames`）には乗せない。汎用・PC は対人段階とセル名を持たない。自由記述の指示文へ、後述の本文由来の感情段階と性別の一人称・語尾を重ねる。

### 4.3 性別の取り方

性別は条件が事実として狭めた情報で、日本語の一人称・語尾（`internal/core/rolespeech`）に最も効く。

判断: 汎用台詞の性別を次の優先で取る。

- `GetIsSex` 条件（極性を畳んで男／女を確定）。
- 声型条件 `GetIsVoiceType` が単一声型を指す時、その EDID の `Male`／`Female` 接頭。
- `GetIsVoiceType` が声型リスト（FLST）を指す時、構成員が全て同性なら同性、混在なら性別なし。

性別が取れない汎用台詞は性別なしで扱い、一人称・語尾の指定を付けない。PC 発話の性別は、訳時にプレイヤー性別が定まらないため、利用者が選ぶ PC 性別（男性／女性／未指定）を使う。未指定なら一人称・語尾を付けない。

### 4.4 感情段階は本文 1 行から

感情段階は文章そのものの性質で、話者が誰でも言葉に出ている。

判断: 汎用台詞・PC 発話の感情段階は、**その台詞の本文 1 行から出す**。1 行ごとの素材（感嘆符・引き伸ばし・強感情語の数）は `line_analysis` に本文ハッシュで既にキャッシュ済みのため、1 行分をそのまま段階化するだけで安い。

皮肉の誤検出（4.7）を抑えるため 2 点を伴う。

- 1 行の「激情」判定のしきい値を、話者集計より渋くする。感嘆符 1 個で激情へ振れないようにし、迷ったら中立側へ寄せる。
- 感情の翻訳指示は上書き命令でなく助言にとどめ、翻訳モデルが本文から読み取る余地を残す。

### 4.5 役どころは外す

役どころ（衛兵・兵士の register）は今回 scope に入れない。

理由: spike で声型 token・FLST 名からは一部しか取れず脆く、本文由来の感情段階と既定の対人段階で表現が重複する。費用対効果が低い。

### 4.6 名指し話者の口調は据え置き

名指し話者の口調（`persona_character`、話者単位の本文集計）は今回変更しない。1 行ごとの感情段階は汎用台詞・PC 発話にだけ効かせる。名指し話者へも 1 行感情を広げる選択はあり得るが、今回は触らない。

## 5. 口調解決の経路（routing）

レコード種別と話者解決の有無で経路を分ける。

```
①名指し話者あり（INFO）          → persona_character（話者集計。既存のまま）
②汎用（INFO・話者なし）          → 自由記述の汎用口調指示文 ＋ 本文1行の感情段階 ＋ 条件由来の性別
③PC発話（DIAL の選択肢・INFO上書き）→ 自由記述のPC口調指示文 ＋ 本文1行の感情段階 ＋ 利用者選択のPC性別
```

②③は対人段階の枝分かれを持たない。対人の文面は利用者の自由記述で常に同じ、感情段階は常に本文 1 行から、性別は条件由来（②）または利用者選択（③）で重ねる。これでどの会話レコードにも口調指示が付き、口調なしが残らない。

## 6. データとパイプラインの含意

実装で変える必要がある箇所（提案。詳細は writing-plans／実装で確定）。

- **抽出器（C#）**: INFO の条件から導いた性別を中心 DB へ永続する。現状は条件を取り出しても捨てている。staging `extracted_info_condition`（INFO の plugin・form_id・sex）へ書く。声型リスト（FLST）の構成員展開も性別判定のため読む。
- **取込（Go）**: INFO→line の対応を作る段で、条件由来の性別を domain `line_condition`（line_id・sex）へ橋渡しする。`extracted_info_speaker`→`line_speaker` と対称の解決。
- **純粋ルール（`internal/core/tone`）**: 1 台詞の `Features` から感情段階だけを出す関数を足す（対人段階は持たない）。激情しきい値は 1 行用に渋め。守るべき不変ルールとしてユニットテスト 100% カバレッジを基準にする。
- **既定口調の保存**: 「汎用の口調指示文」「PC の口調指示文」「PC の性別」を利用者指定値として `prompt_template`（単一行・DB 全消去の対象外・app 専用）へ列追加で持つ。
- **注入経路（`internal/engine`）**: 台詞 id 群へ口調を付ける一括処理で、話者解決の有無とレコード種別を見て ①②③ の経路へ振り分ける。②③ は自由記述の指示文へ、本文 1 行の感情段階と性別の一人称・語尾を重ねる。
- **公開境界（DTO・Store Port・Wails Bind）**: 結果表示の口調メタへ、汎用・PC の決定経路（「汎用」「PC」）・感情段階・性別を載せる（対人段階・セル名・印は汎用・PC では持たない）。`prompt_template` の取得・保存へ自由記述 2 つと PC 性別を足す。新しい Wails メソッドは足さず、既存の取得・保存の payload 拡張に収める。

## 7. 既知の限界（皮肉）

感情段階は表層特徴で測るため、皮肉は外れる。「へえ、"素敵な"鎧だこと！」は表層が感嘆符＋肯定語で激情・好意に見えるが、意図は冷たい侮蔑で、表層特徴では拾えない。

この弱点は今の感情軸に元からあるもので、汎用台詞で新たに生まれるわけではない。ただし違いが 1 つある。名指し話者は感情を複数台詞の中央値で出すため皮肉 1 行が薄まるが、汎用台詞は 1 行単位で薄める相手がいないため誤検出がそのまま出やすい。

判断: 舞台が皮肉文化でない（Skyrim の台詞は素直なものが大半）ため妥協する。4.4 の 2 点（激情しきい値を渋く・感情指示は助言止まり）で下振れを抑え、誤検出時は「たまに感情が強めに出る」程度に収める。

## 8. scope

含む。

- 汎用台詞（INFO・話者なし）への口調付与（自由記述の汎用口調指示文＋本文 1 行の感情段階＋条件由来の性別）。
- PC 発話（DIAL の選択肢・INFO の上書き）への口調付与（自由記述の PC 口調指示文＋本文 1 行の感情段階＋利用者選択の PC 性別）。
- 自由記述の汎用・PC 口調指示文と PC 性別の保存・編集面。
- 条件由来の性別の抽出・永続・注入。
- 1 行の感情段階を出す純粋ルールの追加とユニットテスト。

含まない。

- 役どころ（衛兵・兵士）の register tag。
- 汎用・PC への対人段階（尊大／中立／丁寧）の段階選択。対人は自由記述で書く。
- 名指し話者の口調を 1 行感情へ作り替えること。
- 勢力・種族・声型の気質 prior。
- 皮肉の検出。

## 9. 確定事項（design-module の人間設計レビューで確定）

- 性別の経路: staging `extracted_info_condition` → domain `line_condition`（`line_speaker` と対称）。
- 汎用・PC の口調指定: 段階選択でなく自由記述の指示文。`prompt_template` へ汎用口調・PC 口調・PC 性別を列追加。
- 感情・性別の重ね: 自由記述へ本文 1 行の感情段階と性別の一人称・語尾を自動で重ねる。
- 1 行の激情しきい値: 実装時に本文サンプルで較正（渋め）。
- PC 発話のレコード判定: (DIAL, FULL) と (INFO, RNAM)、NPC 返答 = (INFO, NAM1)。

## 10. 検証方針

実 app での目視確認を必須にする。

- 衛兵の汎用台詞（plan.md で観測した護送・逮捕など、`Innocence Lost - Quest Expansion.esp`）に口調が付くことを確認する。
- OutfitRecognition の装備反応台詞（真の汎用、性別条件のみ一部）に、既定の対人段階＋本文由来の感情段階で口調が付くことを確認する。
- PC 発話（DIAL の選択肢）に PC 既定の口調が付くことを確認する。
- 名指し話者の口調が従来どおりで非劣化なことを確認する。

接続先は `http://localhost:34115`、起動は `npm run dev:wails:run`。
