# 実装範囲・テスト設計: 2026-06-14-master-dictionary（趣旨訂正後）

適用は叙述文・台詞の本文への機械置換（貪欲最長一致）。固有名の独立表示は持たない。
詳細仕様は列挙しない。scope の境界・依存・検証単位だけ固定する。

## 実装範囲（scope の境界）

含む:

- db migration: 中心 SQLite（`db/aitranslation.dev.sqlite3`）へ `master_term` テーブルを追加する。最小は `(source 原語, dest 確定訳語)` ＋ 種別。一意キーは原語（本文置換の照合キー）。種別は保持してよいが照合は原語文字列で行う。
- extractor（C#/Mutagen）: 名前付きレコード（FULL を持つ武器・防具・NPC・地名など）の FULL を、英語 strings（原語）と日本語 strings（公式既訳）の 2 言語で読み、同一 FormKey で突き合わせ、既訳のある語を `(原語, 確定訳語)` として `master_term` へ登録する。対象種別の具体は実装時に決める。
- store（Go）: `master_term` の読み書き関数を足す（関数で持つ。engine が使う分の狭い interface は engine 側で宣言してよい）。
- engine（Go）: 辞書解決の差込点を新設する。`master_term` を読み込み、叙述文・台詞の原文（英語）に対し、辞書の原語を貪欲最長一致で照合して確定訳語（日本語）へ置換してから AI 翻訳へ渡す。置換は副作用のない純関数として切り出す。照合は最長一致優先・語境界・大文字始まりを手掛かりにする。
- engine: どの叙述文・台詞でどの固有名を置換したかを、表示用に持ち回る（結果行の併記用）。
- frontend: 叙述文・台詞の結果行に、本文で置換した固有名（原語 → 確定訳語）を併記する。表示構造は storybook-module（趣旨訂正後）で確定する。

含まない:

- 固有名そのものを訳の単位として出力する経路（`proper_noun`/`placement` の訳の単位化と xTranslator 出力）。本文への置換に絞る。
- 既訳の無い固有名への AI 訳語生成（既訳流用主軸）。
- 置換した語を AI へ参考語として注入する経路（置換主軸とする。誤置換が出た語の注入逃がしは将来検討で、本 task では作らない）。
- ルール・プロンプト編集 UI（T4）。起動時 wipe の実装。

## 依存

- T2 の中心 DB schema（narration・line・speaker）と翻訳実行画面・engine の `Run`。
- localized strings 資源（`dictionaries/Data/strings/`、英語＝原語、日本語＝既訳）。

## テスト設計

単体テストで書く対象:

- engine の貪欲最長一致置換（Go・純関数）: 辞書（原語 → 確定訳語）と原文を入力し、置換後の原文と置換した固有名一覧を返す純関数。最長一致優先（`Iron Sword` を `Iron` より先）、語境界（`Sword` が `Swordsman` の内側に当たらない）、大文字始まり一致、同綴り異義の扱い、複数出現を境界として検証する。
- extractor の `master_term` 構築（C#）: 抽出の正しさは C# テストで担保する（`architecture.md` §3）。FormKey での英語/日本語 FULL 突き合わせと、既訳のある語だけ登録することを検証する。

単体テストで書かない対象（E2E に任せる）:

- store の DB アクセス（`master_term` の sqlx 経路）。
- 結果行の画面ロジック・Wails bridge 周辺。

シナリオテスト（E2E）／実画面観測:

- 翻訳実行画面から実 mod を流し、叙述文・台詞の翻訳結果で、本文中の固有名が辞書の確定訳語へ置換され、同一原語へ複数の叙述文・台詞・複数 Mod で常に同一訳語が当たることを目視する（完了定義の観測点）。
