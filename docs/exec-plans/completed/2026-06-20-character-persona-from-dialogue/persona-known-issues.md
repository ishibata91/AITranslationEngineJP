# ペルソナの既知の問題（2026-06-23）

本書は、対話由来ペルソナ（スライス 1・2・4）で実 app 観測中に見つかった品質上の問題を記録する。表示・配線の機構は動くが、口調指示の中身が不足する問題である。

## 対応状況（2026-06-23、実装・検証・実画面目視まで完了）

問題 1・2・3 を実装で対応した。問題 4 は許容誤差として受け入れた。

設計の出どころ（人間修正）: 性別は声型でなく NPC の Female flag、年齢は race EditorID（`ElderRace`／`*Child`）、声型は対人 prior フォールバック専用。役割語は決定経路（本文／voice／保留）に依らず常に付く。一人称・語尾は戯画的にせず（フィクションの老人語 わし・〜じゃ を使わない）現実的な register にする。一人称・語尾テンプレートは外部ファイル `assets/role-speech.tsv`（race×sex×基底口調セル）に置き、見直しはファイル編集＋再 Run で回す。

検証: gofmt・go vet・go test 通過、tone と role_speech のカバレッジ 100%、C# extractor の build 成功。実 app（:34115）で dev DB を作り直し、`Innocence Lost - Quest Expansion.esp` を実 LLM（`hy-mt2-7b`）で再抽出→再生成→翻訳して目視した。

実画面の観測:
- 性別は 7 話者すべてに充填された（Grelod=Female、Constance=Female、Aventus=Male、子供は男女どおり）。
- Grelod（老女）の訳が老年女性の口調になり、若い男の乱暴口調（山賊風）が消えた。口調指示は「一人称は「わたし」。年配の女性らしい、落ち着いた言い回しにする。」。
- 子供は一人称が性別どおり（男児=ぼく、女児=わたし）で安定し、揺れが消えた。
- Aventus（保留経路）は対人段階が中立へ寄り、基底口調が「平明」になった。子供の役割語も付いた。
- Constance（成人女）は一人称「わたし」＋女性 register が付いた。基底口調は「淡々・実務」のまま（問題 4、許容誤差）。

以下は発見時の分析（記録として残す）。

## 問題 1: NPC 固定メタ（性別・年齢・世代）が口調指示から落ちている

### 現象

老婆 Grelod（声質 `FemaleOldGrumpy`）の訳が、若い男の乱暴口調（山賊風）になる。実 app の結果一覧で、Grelod の台詞が「お前、入るべきではない場所をうろついていたな」のように出て、老女らしい一人称・語尾（「わし」「〜じゃ」など）が出ない。基底口調は「ぞんざい」で対人態度（粗野）は合っているが、話者が老女だと訳へ伝わっていない。

### 原因

新ペルソナは基底口調（対人態度軸×感情表出軸）だけを口調指示へ出す。これは「どう relate するか（粗野・丁寧、抑制・激情）」を表すが、「誰か（性別・年齢・世代）」を表さない。両者は直交する。

- voice_type の EditorID（`FemaleOldGrumpy`）には 性別（女性）と年齢（老人）が符号化されているが、現実装はその気質部分（Grumpy → 気難）を対人軸の prior にしか使わず、性別・年齢を役割語（老人語・女性語）として出していない。
- 種族訛り（カジート三人称など）は語彙マーカーとして出しているが、性別・年齢・世代の役割語型は実装していない。
- 旧メタデータ専用機構が持っていた「気難しい老女の声」相当の情報（性別・年齢）が、作り直しで口調指示から消えた。

### 影響

- 対人態度が正しくても、話者の属性（老女・老人・男性・女性・子供）が訳文に出ず、別人格（山賊・若者など）になる。
- 多数のキャラに及ぶ。voice_type が 性別・年齢を持つ話者（全 786 の汎用気質 voice の多く）で起こる。

### 対応方針（未着手）

- voice_type の EditorID から 性別・年齢（世代）を固定属性として引き、役割語（一人称・語尾）の語彙マーカーとして基底口調へ重ねる。基底口調（態度）×語彙マーカー（属性・役割語）の合成にする。
- 概念モデル（`tone-concept-model.md`）の恒常源泉（生得＝性別、形成＝年齢・世代）と、固定方針 R5（出力類型は役割語＝金水敏を土台）・R7（種族訛りは軸と直交の語彙マーカー）に対応する。性別・年齢も同じ語彙マーカー層に置く。
- 実装の足場: `internal/engine/tone_catalog.go` の `raceMarkerTrait`（種族訛り）と同じレイヤーへ、voice_type 由来の 性別・年齢の役割語マーカーを足す。`buildToneTraits` が基底口調の性質文へ役割語マーカーを重ねる。
- 注意: 旧機構のハードコード性質文（「気難しい老女の声」）を戻すのではなく、役割語型の語彙マーカー（老人語・女性語等の一人称・語尾の置換型）として入れる。戯画化を避け穏当にする（R5）。

### 関連

- 概念モデル: `tone-concept-model.md`（恒常源泉・語彙マーカー＝役割語型）。
- 固定方針: `plan.md` R5・R7。
- 信号: `poc-tone-report.md`「メタデータ信号の棚卸し」（voice_type の EditorID が 性別・気質を符号化）。

## 問題 2: 一人称・語尾が同一話者内で揺れる（few-shot 未実装）

### 現象

同じ話者の訳で、一人称・語尾が行ごとに揺れる。Aventus（1 話者・基底口調「物腰やわ」）の実 app の訳:

- 「ついに……！**俺**の祈りが聞き届けられたぞ！」
- 「ほら、約束通りだ。……それから、ありがとう。本当に感謝してる**よ**。」
- 「これ以上の知らせは、今まで一度も聞いたことが**ねえ**！」

一人称が「俺」、語尾が「ぞ／よ／ねえ」と揺れ、同じキャラが別人の口調になる。

### 原因

口調指示が口調を言葉で「説明」するだけ（例「柔らかく丁寧な口調。相手を立てて穏やかに述べる。」）で、一人称・語尾を固定していない。LLM が行ごとに既定（俺 など）を選ぶため揺れる。固定方針 R3（few-shot で一人称・語尾を例示固定）が未実装である。

### 影響

- 話者の一貫性が崩れる。問題 1 と複合する: 性別・年齢マーカーを足しても、few-shot が無いと役割語（老人語・子供語）を安定して出せない。

### 対応方針（未着手）

- R3 の few-shot（英語原文 → その口調の訳文の例）で、基底口調ごとに一人称・語尾を決定的に固定する。`persona-design.md`「few-shot とマーカーの矛盾の検討」で合成順（マーカー優先で一人称・語尾を上書き）は設計済み。例文の具体が未実装。

## 問題 3: 保留経路の誤分類

### 現象

Aventus（興奮した子供。原文 "Finally!" "Aha! I knew you could do it!" など高感情・直截）が、基底口調「物腰やわ（柔らかく丁寧）」になり、実像と逆になる。決定経路は「保留」、印 6。

### 原因

印が不足（印 6 < 10）で固有声質に気質も無く、保留経路が薄い本文値を低信頼で保持した。その値が実像とずれた（保留は信頼度が低い経路）。

### 影響

- 保留経路の話者の基底口調が当てにならない。台詞が少ない固有キャラで起こる。

### 対応方針（未着手）

- 保留経路の扱いを較正する（中立へ寄せる／感情軸を主に使う／UI で低信頼を明示する のいずれか）。属性割当（スライス 3）の fallback とも関係する。

## 問題 4: 基底口調が話者の性質を取り違える例

### 現象

Constance（優しい世話役。"She really is kind"）が、基底口調「淡々・実務（事務的）」になり、優しさが落ちる。実 app の訳は「いたしませんわ」「お引き取り願えますか」と丁寧お嬢様風で、基底口調（淡々）と訳が食い違ってもいる。

### 原因

対人態度（中立）・感情（抑制）の集計が、彼女の穏やかさ・優しさを事務的と取った。表層の丁寧マーカーが少ない。なお基底口調（淡々）と訳の食い違いは問題 2（語尾を固定しない）が一因。

### 影響

- 個別キャラの取り違え。許容誤差か較正対象か要判断。

### 対応方針（未着手）

- 較正で詰めるか、許容誤差として受け入れるかを判断する。少数なら手修正（将来）で直す対象にもなる。
