# Design: <task-id>

`design.md` は「どう実装し、どう直すか」を人間が読んで判断するための説明を持つ。要求は `plan.md`、確定仕様（要求ごとの仕様）は `spec.md`、修正フローの再現確認・原因究明は `investigation.md` が持つ。
`design.md` と `spec.md` が食い違う場合は `spec.md` を優先する。
新規実装フロー（`feature-workflow`）と修正フロー（`fix-workflow`）が同じこのテンプレートを使う。

`plan.md` の要求ごとに節を分け、節と節の間に区切り線を置く。どの要求の節にも置けない内容は書かない。置き場所が無い内容は、`plan.md` の要求欄へ足すことを人間へ諮るか、捨てる。

既存実装は現況であって制約ではない。責務の分け方が変わる場合は、既存の呼び出し関係を作り直す案を書く。
