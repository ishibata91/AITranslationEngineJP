# Loop Log: <task-id>

`loop-log.md` は実験フロー（`experiment-workflow`）だけが作る。各回で立てた仮説と、その回で何をしたかの判断を持つ。
測った値は `measurements.csv`、標本を読んだ結果は砂場の `sample-review.jsonl`、達成条件と標本の分け方は `criteria.md`、判断基準は `research-protocol` skill が持つ。

数値の並びをこの file へ書かない。回が増えると読めなくなるため、値は `measurements.csv` が持つ。

## 予備の回

達成の線を置くために、準備の段で対象を 1 つ変えて値がどれだけ動くかを実測した回を持つ。ループの段の回数に数えない。

- 変えた対象: <1 つだけ書く>
- 選んだ理由: <その対象が効きそうと考えた理由>
- 測った標本: 開発用（評価用は使わない）
- 動き幅: <達成条件の各行について、0 回目からの差を 1 行 1 値で書く>
- 動き幅が揺れの底以下だった行: <あれば書く。その対象はその行に効かないので、対象を選び直すか診断の表へ移す>
- 置いた線: <各行の達成の線と、隔たりが動き幅の何回分に当たるか>

## 各回

回ごとに節を分ける。ループの段は回 1 から始まる。

### 回 <回番号>

- 段: <探索 / 確証>
- 変えた対象: <その回で変えた対象。組み合わせで振る回は水準を書く>
- 測った標本: <開発用 / 評価用>
- 判定: <満たす / 満たさない>
- commit: <その回の変更の commit hash>
- 標本を読んだ結果: <砂場の `sample-review.jsonl` を集計した結果を 1 行で。誤りの種類のうち増えたものと減ったもの>
- 読んだ役割: <人間 / agent 名>
- 次にすること: <次の回で変える対象>

## 仮説

対立する仮説を 2 つ以上立てる。1 つしか立てられない場合は理由を書く。

| 回 | 仮説 | 予測 | 落ちる条件 | 結果 | 出どころ |
| --- | --- | --- | --- | --- | --- |
| <回> | <何が効いていると考えるか> | <どの値がどちらへどれだけ動くか> | <予測が外れたとき、この仮説が落ちると言える形> | <落ちた / 残った> | <探索から出た / 実験の前に立てた / 人間の指摘から出た> |

探索の段で作った仮説は、確証の段で別の標本にかける。同じ標本で確証の根拠にしない。

## 測定手段を変えた記録

変えた場合だけ書く。変えていなければこの節を空のまま残す。

- <変えた日付>: <どの値の数え方を、どう変えたか>。過去の全ての回を新しい数え方で測り直し、`measurements.csv` を更新した。
- <変えた日付>: <接続先またはモデルを、どう変えたか>。この回を境に、以前の回と直接比べない。

## 採否

達成の線を満たした後に、人間が標本を読んで決める。線を満たすことはループを止める条件であり、採否ではない。

- 判断: <採る / 採らない>
- 理由: <標本を読んだ結果と、値では見えなかったこと>
- 採らない場合に次の回へ回す仮説: <人間の指摘を仮説の表へ足す。達成の線は動かさない>
