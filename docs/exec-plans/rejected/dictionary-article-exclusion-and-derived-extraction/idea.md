# アイデア: dictionary-article-exclusion-and-derived-extraction

## 対象と除外

今回の砂場評価の対象は R-1、R-2、R-3 と追加アイデア CI-1 とする。

R-5 は今回の砂場評価の対象外とする。

R-4 は対象外とする。

砂場は参考語を選ぶ直前までを扱う。

本文翻訳への受渡し、参考語 snapshot、永続化、結果表示、frontend は変更しない。

## アイデア

選択した辞書範囲の事前作成済み辞書語義からだけ、元の語義を指す照合別名を一時的に作る。

照合別名が本文に一致しても、砂場の出力は「どの元の辞書語義を選んだか」だけとする。

辞書DB、辞書項目、語義、レビュー、採否フラグは変更しない。

### R-1 の照合別名

原語が `The `、`A `、`An ` のいずれかで始まる場合だけ、先頭の一語と一個の空白を除いた文字列を候補にする。

原語と照合別名は既存どおり大文字と小文字を区別する。

`The Book of Life` の別名は `Book of Life` とする。

本文へ一致した別名は `The Book of Life` を所有者として返す。

### R-2 の照合別名

R-2 は既存の人名派生規則と重なる、最も狭い一形態だけを試す。

`dictionary_occurrence.skyrim_category = 'NPC_'` の出現を一件以上持つ選択対象語義で、原語が大文字小文字を区別しない空白区切りの ` the ` を含む場合に、最初の ` the ` より前だけを名前候補にする。

日本語訳の末尾にある連続したカタカナ列を名前の訳として取り出せる場合だけ候補にする。

`Grelod the Kind` と `親切者のグレロッド` から、`Grelod` と `グレロッド` の対応を作る。

`Grelod` が本文へ一致した場合は、元の `Grelod the Kind` を所有者として返す。

`NPC_` 以外の複合語、`the` を含まない複合語、二つ以上の部分語、語尾のカタカナ列を取れない日本語訳は対象にしない。

## R-3 の固定した安全条件

R-1 の照合別名は、次の全条件を適用する。

- 先頭が ASCII 大文字である。
- 照合別名の文字数が 4 以上である。
- 一語以上の ASCII 英字、アポストロフィ、ハイフンからなる語を、単一の ASCII 空白だけで連結した文字列である。
- 先頭、末尾、連続する空白を持たない。
- 元の完全一致原語と同じ文字列でない。
- 同じ照合別名を別の元の辞書語が所有しない。
- 照合別名が別の元の完全一致原語と衝突しない。

R-2 の照合別名は、空白を持たない一語だけとする。

R-2 は、source commit `da8533a042d9aff0c9a46731698a94f1bc0aca49` 時点の既存 `termderive` の `deriveByname` と `safePair` の次の条件を砂場側の純粋判定として再現する。

- 原語は `strings.ToLower(source)` に含まれるリテラルASCII文字列 `" the "` の最初の位置で分け、`strings.TrimSpace` 後の前部を名前候補にする。
- 日本語訳の末尾にあるカタカナまたは中黒の連続列が空でなく、日本語訳全体と同じでない。
- 名前はASCII大文字で始まり、4文字以上で、ASCII英字、アポストロフィ、ハイフンだけからなる。
- 名前の訳はカタカナまたは中黒だけからなり、カタカナを含み、2文字以上である。
- 名前は縮約語、称号、種族・ハウス語でない。
- 本文用法で小文字出現が3回以上かつ大文字出現以上の名前は除外する。

R-2 の小文字・大文字用法分布は、source commit `da8533a042d9aff0c9a46731698a94f1bc0aca49` の `termusage.BuildUsage` をそのまま使う。

`termusage.BuildUsage` へ渡す入力は、固定した本文コーパスを `extracted_field.id` 昇順で読んだ `rec = 'INFO'` かつ `field = 'NAM1'` の `source` 列だけとする。

R-2 の用法分布は評価用本文も含むため、R-2の評価は固定87,005本文への全件適用だけを示す。

R-2 の評価は未見本文への一般化を示さない。

R-2とR-3-R-2安全条件群の結果見出しは「固定コーパス内の記述的評価」とする。

評価器は結果manifest生成前に、R-2候補資格が同commitの `deriveByname` と `safePair` の結果に一致することを、単一ASCII空白、連続ASCII空白、タブ、改行、非ASCII空白、アポストロフィ、ハイフンを含む固定テストベクトルで確認する。

R-2 の照合別名にも、R-1 と同じ所有者衝突と既存完全一致原語との衝突除外を適用する。

複数の語義、訳候補、出現を持つ同一の `dictionary_term.source` は一つの所有者として扱う。

安全条件を満たさない候補は、理由とともに砂場の除外一覧へ記録し、本文照合へ渡さない。

既存の完全一致原語は、候補生成の結果にかかわらず変更しない。

## 利用場面

本文が書籍名やクエスト名を冠詞なしで参照する場面で、辞書には冠詞付きの正式名だけがある。

本文が二つ名を持つ NPC を名前だけで参照する場面で、辞書には二つ名を含む正式名だけがある。

現行の完全一致照合は前記の二場面を選べない。

## 期待する効果

安全条件を満たす別名に限り、完全一致照合で選べない本文中の書籍、クエスト、NPC 名を選べるようにする。

元の辞書項目を変更せずに、追加候補の有用性と誤一致の有無を分離して確認できる。

R-5 は共通の候補選択関数を経由するため、砂場で同期経路と batch 経路の同値を証明しない。

R-5 は今回の砂場評価の採否へ含めない。

R-5 は製品統合後に、二経路の実際の候補入力と保存結果を比較する検証へ渡す。

## 比較前の状態

比較前は、選択した辞書範囲の `dictionary_term.source` だけを、既存の語境界と最長一致で本文へ照合する。

比較前は、冠詞を除いた形と人名の部分形を追加しない。

## 砂場の入力と出力

評価の前に、次の読み取り専用スナップショットを固定する。

- `db/dictionary.sqlite3` のSHA-256と、語義、出現、訳候補、品詞、カテゴリ、由来、`inclusion_decision`。
- `tmp/prebuilt-translation-dictionary/r5/source.sqlite3` のSHA-256と、`extracted_field` の原文87,005件。
- 本文の固定キーである `extracted_field.id` と `(plugin, form_id, rec, field, ordinal)`。

辞書範囲は `all-senses` と `included-senses` の二条件を別々に測る。

`all-senses` は現行の事前作成済み辞書読取りと同じ全語義を候補にする。

`included-senses` は `dictionary_sense.inclusion_decision = 'include'` の語義だけを候補にする。

`included-senses` はプリビルド辞書DBの採否判断を候補絞り込みへ使う仮説である。

`included-senses` の結果は、現行読取り条件の製品結果を示すものではない。

評価器を実装した後、評価器を実行する前に入力 manifest を保存する。

入力 manifest は、辞書DBと本文DBの固定パスおよびSHA-256、本文 ID、自然キー、本文 SHA-256、本文分割群、開発用または評価用の割当だけを持つ。

入力 manifest は候補集合、照合結果、層、人間判定を持たない。

評価器の実行バイナリ SHA-256、source commit、対象commitとの差分、`go.mod`、`internal/core/dictionary/dictionary.go`、`internal/core/termderive/termderive.go`、`internal/core/termusage/termusage.go`、評価器ソースのSHA-256、実行コマンドを、結果を作る前に固定して入力 manifest へ併記する。

評価器は、凍結した入力 manifest が指す辞書DBと本文DBのSHA-256を検証してから読み取り、結果 manifest を生成する。

結果 manifest は候補集合、候補由来、照合結果、衝突理由、層を持つ。

本文 SHA-256 が同じ本文は一つの分割群とする。

各本文分割群は `SHA-256("dictionary-article-exclusion-v1:" + 本文 SHA-256)` の最初のbyteの最上位bitで開発用と評価用へ分割する。

最上位bitが `0` の本文分割群を開発用とする。

最上位bitが `1` の本文分割群を評価用とする。

同じ本文 SHA-256 を持つ本文は、異なる本文 ID や自然キーでも必ず同じ側へ置く。

結果 manifest は、辞書範囲、条件、本文位置、候補由来ごとに行を持つ。

結果 manifest の層は重複を許す。

- R-1追加一致層は、比較前に無く適用後に `r1_alias` 由来で追加された本文位置とする。
- R-2追加一致層は、比較前に無く適用後に `r2_alias` 由来で追加された本文位置とする。
- CI追加一致層は、CSに無くCI-1にだけある本文位置とし、`original`、`r1_alias`、`r2_alias` の候補由来を別の下位層とする。
- 小文字露出層は、CI-1で追加され、一致した本文文字列の先頭が ASCII 小文字である本文位置とする。
- 既存完全一致衝突層は、候補生成時に別名が完全一致原語と衝突して除外された候補キーとする。
- ケース衝突層は、CI-1でASCII小文字列が複数の所有者を持ち除外された候補キーとする。
- R-1除外候補層は、R-1の安全条件で除外され、除外しなければ評価用本文へ一致する候補キーと本文位置とする。
- R-2除外候補層は、R-2の安全条件で除外され、除外しなければ評価用本文へ一致する候補キーと本文位置とする。
- 候補なし層は、比較前と適用後の両方で一致がない本文とする。

R-1、R-2、CI追加一致、小文字露出、R-1除外候補、R-2除外候補の各本文位置層は、評価用に10本文以上を必要とする。

既存完全一致衝突層とケース衝突層は候補キー単位で全件を自動確認する。

候補なし層は、評価用の本文を本文 SHA-256 の昇順で10本文選ぶ。

必要な本文位置層が10本文未満の場合は、該当する規則と辞書範囲を評価不能とする。

評価用では、比較前から追加、消失、所有者変更した全一致位置を人間確認する。

評価用では、R-1除外候補とR-2除外候補の全一致位置も人間確認する。

比較前から維持された一致は全件を自動比較し、消失と所有者変更だけを人間確認する。

開発用では候補規則を変更しない。

開発用は、凍結した候補規則を実装した評価器の不具合だけを結果生成前に検出するために使う。

評価器の不具合を修正した場合は、結果生成前に新しい評価runとして入力 manifest、評価器ハッシュ、実行コマンドを再凍結する。

安全条件、R-2 の形態、CI-1 の候補範囲を変える場合は、別の固定アイデアを作る。

候補生成資格は選択対象語義単位で判定する。

衝突判定と照合所有者は `dictionary_term.source` 単位で判定する。

一つの照合所有者に複数の候補生成資格語義がある場合は、全ての資格語義 ID を昇順で保持する。

一致位置はUTF-8 byte offsetの半開区間 `[start_byte, end_byte)` とする。

結果 manifest は、`source[start_byte:end_byte]` が照合に使った文字列と一致することを検証して保存する。

結果 manifest は、本文 ID、辞書範囲、条件ごとに重複を除いた照合所有者集合も保存する。

本文単位の効果は、比較前と比較条件の照合所有者集合の追加、消失、維持だけで数える。

本文位置の追加、消失、所有者変更は、副作用を確認するためだけに数える。

同じ照合所有者が本文内の別位置で維持される場合は、本文位置の消失があっても本文単位の照合所有者消失としない。

砂場の出力は、辞書範囲、条件、本文 ID、自然キー、本文 SHA-256、`start_byte`、`end_byte`、照合に使った文字列、照合所有者である `dictionary_term.source`、候補生成資格語義 ID、候補由来、候補種別、除外理由とする。

R-4 が対象外であるため、`TranslationReference`、prompt、snapshot、API、画面の出力は測らない。

## 追加アイデア CI-1: 事前作成済み辞書のケースインセンシティブ照合

事前作成済み辞書DBを作った目的の一つである、選択した辞書範囲の語義を本文の大小文字に依存せず参照する効果を、別条件として測る。

CI-1 は、選択した辞書範囲の元の完全一致原語と、R-1・R-2 で安全条件を通った照合別名を候補にする。

CI-1 は、ASCII 英字、単一の ASCII 空白、アポストロフィ、ハイフンだけからなる候補だけを対象にする。

CI-1 は候補の照合だけをASCIIケースインセンシティブ比較へ変える。

CI-1 は、候補と本文の ASCII 英字だけを小文字へ畳み、元の本文位置と元の候補文字列を保持する。

CI-1 は一致した本文の表記を所有者にせず、元の `dictionary_term.source` を所有者として返す。

CI-1 は一致ごとに `original`、`r1_alias`、`r2_alias` の候補由来を保存する。

CI-1 の評価結果は候補由来ごとに分ける。

`The Companions` は `the companions` に一致しても、所有者を `The Companions` として返す。

同じ ASCII 小文字列を複数の元の辞書語が所有する場合は、CI-1 から照合文字列全体を除外する。

ケースを畳む前の文字列が同じ元の辞書語義に属する複数の語義、訳候補、出現を持つ場合は、一つの所有者として扱う。

R-3 の候補生成時の安全条件は維持する。

CI-1 は本文側の小文字表記にも一致するため、R-3 の「先頭が ASCII 大文字」の条件を本文一致の条件として使わない。

## CI-1 の利用場面と期待する効果

本文中の通常語と区別できる辞書語が、文頭以外や文法上の理由で小文字になって現れる場面を対象にする。

`included-senses` では、未審査または除外済みの辞書語義を候補に戻さない。

CI-1 の期待する効果は、ケースセンシティブ条件では選べない正式名と照合別名を追加で選べることとする。

CI-1 の価値は、候補由来を混ぜた追加一致の件数だけで判断しない。

追加一致が本文の文脈で元の辞書語を指すことを人間が確認できる場合だけ、効果として数える。

## CI-1 の比較条件

| 条件 | 照合候補 | 照合時の大小文字 | 目的 |
| --- | --- | --- | --- |
| CS | 選択した辞書範囲の完全一致原語、R-1 別名、R-2 別名 | 区別する | 現在の候補集合を固定する |
| CS-CI適格 | CS からケース衝突した候補を除外する | 区別する | ケース衝突除外による候補消失を測る |

CS-CI適格とCI-1は、候補集合、候補の所有者、語境界、最長一致、本文順を揃える。

CSとCS-CI適格の差は、ケース衝突除外のために失った候補として記録する。

- CI-1 が追加した本文中の一般語用法は、人間確認で効果として数えない。

## CI-1 で観察する副作用

- 小文字の一般語へ、ゲーム固有語または固有名の候補が一致する。
- 文章先頭以外の大文字語と小文字語を同じ対象と誤認する。
- ケースを畳んだ衝突を除外した結果、CS で選ばれた候補が消える。
- 元の完全一致原語をケースインセンシティブにした結果、R-1・R-2 と無関係な誤一致が増える。

## 比較する最小案

| 条件 | 本文へ渡す照合語 | 目的 |
| --- | --- | --- |
| 比較前 | 選択した辞書範囲の元の完全一致原語だけ | 現在の選択範囲を固定する |

比較前と適用後は、Go `regexp` の `\b` と同一のASCII word-boundary、最長一致、大小文字区別、本文順で一致を選ぶ。

評価器は、候補の先頭または末尾がアポストロフィかハイフンである場合も、Go `regexp` の `\b` と同じ一致結果を使う。

比較前評価器は、各辞書範囲と固定本文コーパス全件について、既存 `dictionary.NewDictionary(...).Extract` の照合所有者集合と一致することを結果manifest生成前に確認する。

比較前評価器は、句読点、アポストロフィ、ハイフン、非ASCII隣接文字を含む固定境界ベクトルでも既存 `Dictionary.Extract` と照合所有者集合が一致することを確認する。

CI-1 は大小文字だけを区別しない。

同じ開始位置では照合文字列が長い候補を優先する。

同じ開始位置で長さも同じ候補は、照合文字列の辞書順で先の候補を優先する。

異なる開始位置で一致範囲が重なる場合は、本文で左にある一致を選び、選んだ一致範囲の内側から別の一致を選ばない。

同じ照合文字列を複数の元の辞書語が所有する場合は、適用後から候補全体を除外する。

## 確認したい振る舞い

- 冠詞なしの本文参照が R-1 別名から選ばれる。
- NPC の名前だけの本文参照が R-2 別名から選ばれる。

- 既存の完全一致と別名が同じ位置へ一致する場合に、最長一致の結果が比較前の規則と一致する。

## 観察する失敗と副作用

- 一般語として読める本文箇所へ別名が一致する。
- 別名が複数の元の正式名へ戻る。
- 別名が既存の完全一致原語を覆い隠す。
- R-1 または R-2 の候補追加によって、比較前に選ばれた完全一致原語が選ばれなくなる。
- 形式条件を満たすが、人間の本文文脈では元の正式名を指さない一致が出る。

## 評価へ渡す条件

`idea-evaluation` は、砂場だけに候補生成と照合を実装する。

`idea-evaluation` は、元の辞書DBと製品コードを変更しない。

`idea-evaluation` は、追加一致を本文 ID と一致位置ごとに人間が確認できる形で保存する。

人間確認の単位は、評価用本文の本文 ID、一致位置、照合所有者、候補由来の組とする。

人間確認artifactは結果 manifest と、辞書範囲、条件、本文 ID、`start_byte`、`end_byte`、照合所有者、候補由来の安定キーで結合する。

人間確認artifactは、安定キー、本文全文、前後80 UTF-8 byteの文脈、本文 SHA-256、判定値、判定理由、判定者、判定時刻を保存する。

前後80 UTF-8 byteの文脈は、開始位置から前方80 byte、終了位置から後方80 byteを上限に取り、各端点を外側の最も近いUTF-8文字境界へ広げた範囲とする。

人間確認は各組へ次の一つだけを記録する。

- `intended`: 一致した本文文字列が、本文脈で照合所有者の対象または概念を指す。
- `false_positive`: 一致した本文文字列が、本文脈で照合所有者の対象または概念を指さない。
- `ambiguous_owner`: 本文脈だけでは一意な照合所有者を判断できない。
- `insufficient_context`: 保存された本文だけでは本文脈を判断できない。

人間確認は二人の判定者が独立して行う。

二人の判定値が一致した場合は一致値を最終値とする。

二人の判定値が不一致の場合は第三判定者が、本文全文、二つの理由、候補由来を読んで最終値と理由を記録する。

候補生成資格語義 ID は人間確認artifactの安定キーに含める。

人間確認artifactは、各候補生成資格語義の訳候補、意味、品詞、カテゴリ、由来を判定者へ提示する。

複数の候補生成資格語義を持つ照合所有者は、本文脈が一つ以上の候補生成資格語義を支持する場合だけ `intended` とする。

`false_positive` または `ambiguous_owner` は棄却として数える。

`insufficient_context` は支持にも棄却にも数えず、該当する規則、辞書範囲、候補由来を評価不能にする。

R-1除外候補とR-2除外候補は、人間確認artifactへ次の一つだけを記録する。

- `exclusion_justified`: 除外しなければ誤一致または所有者曖昧になる。
- `exclusion_missed`: 除外しなければ本文脈で一意な意図した一致になる。
- `exclusion_insufficient_context`: 保存された本文だけでは判定できない。

`exclusion_missed` はR-3の過剰除外として棄却に数える。

`exclusion_insufficient_context` は該当する規則と辞書範囲を評価不能にする。

既存完全一致衝突とケース衝突は、人間判定を使わず、結果 manifest の候補キー全件で自動確認する。

R-1 と R-2 は別々に支持または棄却する。

各規則は、辞書範囲ごとに支持または棄却する。

| 結論単位 | 必須の本文位置層 | 必須の候補キー層 |
| --- | --- | --- |
| R-1 | R-1追加一致 | 既存完全一致衝突 |
| R-2 | R-2追加一致 | 既存完全一致衝突 |
| R-3-R-1安全条件群 | R-1追加一致、R-1除外候補 | 既存完全一致衝突 |
| R-3-R-2安全条件群 | R-2追加一致、R-2除外候補 | 既存完全一致衝突 |
| CI-1 の各候補由来 | CI追加一致の該当候補由来 | ケース衝突 |

R-3は、R-1安全条件群とR-2安全条件群を別々の結論単位とする。

R-3-R-1安全条件群の支持は、R-1追加一致に `false_positive` と `ambiguous_owner` がなく、R-1除外候補に `exclusion_missed` がなく、既存完全一致衝突が全件除外され、必須層に10本文以上ある場合とする。

R-3-R-2安全条件群の支持は、R-2追加一致に `false_positive` と `ambiguous_owner` がなく、R-2除外候補に `exclusion_missed` がなく、既存完全一致衝突が全件除外され、必須層に10本文以上ある場合とする。

R-3の各安全条件群の棄却は、対応する追加一致に `false_positive` または `ambiguous_owner` が一件以上ある場合、対応する除外候補に `exclusion_missed` が一件以上ある場合、または既存完全一致衝突が一件でも照合候補へ残る場合とする。

R-3の各安全条件群は、対応する必須層が10本文未満、`insufficient_context` が一件以上、または `exclusion_insufficient_context` が一件以上の場合に評価不能とする。

各規則と辞書範囲の支持は、評価用本文に規則による `intended` の追加照合所有者が一件以上あり、追加照合所有者へ対応する本文位置の人間確認で `false_positive`、`ambiguous_owner`、`insufficient_context` がゼロであり、本文単位の既存照合所有者消失がゼロである場合とする。

各規則と辞書範囲の棄却は、規則による `intended` の追加照合所有者がゼロである場合、または追加照合所有者へ対応する本文位置に `false_positive`、`ambiguous_owner`、本文単位の既存照合所有者消失のいずれかが一件以上である場合とする。

CI-1 は R-1 と R-2 から独立して支持または棄却する。

CI-1 は、辞書範囲と候補由来ごとに支持または棄却する。

CI-1、辞書範囲、候補由来の支持は、評価用本文にCI-1だけが追加した `intended` の一致が一件以上あり、CI-1追加一致とCSからCS-CI適格で消失した一致の人間確認で `false_positive`、`ambiguous_owner`、`insufficient_context` がゼロであり、CS-CI適格からCI-1への本文単位の既存照合所有者消失がゼロである場合とする。

CI-1、辞書範囲、候補由来の棄却は、CI-1だけが追加した `intended` の一致がゼロである場合、またはCI-1追加一致とCSからCS-CI適格で消失した一致に `false_positive`、`ambiguous_owner` が一件以上ある場合、またはCS-CI適格からCI-1への本文単位の既存照合所有者消失が一件以上ある場合とする。

各規則、辞書範囲、候補由来は、表で対応する必須の本文位置層が10本文未満、`insufficient_context` が一件以上、または `exclusion_insufficient_context` が一件以上の場合に評価不能とする。

各規則と辞書範囲は、`exclusion_missed` が一件以上ある場合に棄却とする。

判定の優先順位は、棄却、評価不能、支持とする。

結果表は辞書範囲を主キーに含める。

`all-senses` の結論だけを現行読取り条件に対する結論として表示する。

`included-senses` の結論は候補絞り込み仮説の参考結果として別に表示する。

今回の砂場評価の結論は、規則、辞書範囲、候補由来ごとに `支持`、`棄却`、`評価不能` を記録する。

今回の砂場評価は製品への採用を決めない。

開発用で安全条件、R-2 の形態、CI-1 の候補範囲を変更する場合は、別の固定アイデアとして新しい `idea.md` を作る。

# 次の固定アイデア: NPC限定の冠詞除去と人名部分形

前節の評価済みアイデアは変更しない。

次の評価では、`NPC_` 出現を一件以上持つ辞書語義だけを別名候補の入力にする。

完全一致原語は従来どおり全選択辞書範囲から照合する。

冠詞付きNPC名は `The `、`An `、`A ` を一回だけ除き、残部を照合別名にする。

`X the Y` の二つ名は `X` だけを照合別名にする。

`the Y` は照合別名にも訳文にも使わない。

二語のNPC名 `A B` は、日本語訳が `ア・ベ` のように二語の純カタカナ中黒区切りで対応する場合だけ、`A → ア` と `B → ベ` を別名にする。

別名は、既存完全一致原語または別所有者の別名と文字列が衝突する場合に除外する。

比較前は完全一致原語だけを照合する。

適用後は完全一致原語と前記のNPC別名を照合する。

砂場は10語以上の `INFO:NAM1` 会話文500件を本文SHA-256の安定順で固定して使う。

期待する効果は、`Ulfric Stormcloak → Stormcloak → ストームクローク` のような人名の単独参照を安定して訳せることである。

誤訳として、`Captain`、`Lord`、`Hunt` のような肩書きまたは一般語を人名の訳へ固定する一致を観察する。

冠詞除去、二つ名、二語姓名分割の各由来を別々に記録する。

製品コード、辞書DB、採否フラグ、prompt、snapshot、永続化、画面は変更しない。
