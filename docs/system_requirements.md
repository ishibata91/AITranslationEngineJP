# システム要件

`requirements.md` の各業務要件を、どの仕組みで達成するかを定義する。
見出し番号は `requirements.md` の業務要件番号に対応させる。

## 1. Skyrim Mod を翻訳したい

- AI を利用して翻訳する。
- 対応する AI プロバイダ:
  - Gemini API
  - xAI API
  - OpenAI 互換 API（OpenAI 本体、および llama・LM Studio などのローカル実行を含む）
  - Claude API

## 2. 単語の一貫性を保ちたい

- Mod 横断で共有する永続マスター辞書（原語 → 確定訳語の対応表）を正本に持ち、同一原語へ常に同一訳語を割り当てて一貫性を保つ。
- 一貫性のスコープは Mod 横断とする。ジョブ内・Mod 内には限定しない。
- 揃える対象用語は、Skyrim の名前付きレコード（武器・防具・NPC・地名など、表示名を持つレコード）の固有名詞を機械的に特定する。
- 本文・会話文中にだけ現れる語の拾い上げは未確定。
- 訳語の供給方式は未確定。既訳（xTranslator の既訳・公式日本語版）の流用だけにするか、AI 翻訳を併用するかを決めていない。
- 辞書を本文翻訳へ適用する方式（プロンプト注入・機械置換など）と、一貫性の検証方式は未確定。

## 3. NPC の口調を保ちたい

- NPC レコードの属性からルールベースでペルソナを生成し、翻訳へ反映して口調を保つ。会話履歴の解析と AI 生成は将来検討とし、現時点では使わない。
- ペルソナは 2 つの表現で持つ。内部表現は構造化属性（種族・性別・役割・口調など）とする。適用形は構造化属性をテンプレート変換した翻訳ディレクティブ（翻訳 AI への口調指示文）とする。
- 構造化属性から翻訳ディレクティブへの変換はテンプレートで機械的に行い、AI を使わない。
- 翻訳ディレクティブを本文翻訳のプロンプトへ注入して口調を保つ。
- 属性 → 翻訳指示のルール集を永続化し、翻訳前にユーザーが設定・編集できる。
- 個々の NPC ペルソナは永続化しない。翻訳実行時にルールを適用して都度生成する。
- 使用する属性の選定、属性の分類、ルール合成時の衝突優先順位は概念モデルで整理する（未確定）。

## 4. xTranslator 形式で出力したい

- 機能要件は業務要件と同一であり、追加のシステム要件を設けない。
