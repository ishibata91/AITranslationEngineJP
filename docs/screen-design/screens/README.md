# Screen Designs

この directory は、画面別の画面設計書を置く。
画面設計書は、画面が何をして、何があるかを短く固定する正本である。

## Records

- `template.md`: 画面設計書のテンプレート
- `example-incomplete-job-list.md`: 画面設計書の記述例
- `dashboard.md`: ダッシュボード
- `provider-settings.md`: AIサービス設定
- `master-dictionary.md`: マスター辞書
- `master-persona.md`: マスターペルソナ
- `translation-management.md`: 翻訳管理シェル
- `translation-input-review.md`: 翻訳入力レビュー
- `translation-job-setup.md`: 翻訳ジョブ設定
- `translation-job-management.md`: 未完了ジョブ一覧
- `job-run.md`: 翻訳実行シェル
- `term-translation-phase.md`: 単語翻訳
- `persona-generation-phase.md`: NPC ペルソナ生成段階
- `body-translation-phase.md`: 本文翻訳段階
- `translation-complete.md`: 翻訳完了確認
- `output-management.md`: 出力管理

## Notes

- 画面設計書は、画面内のエレメントごとに表示項目、状態別表示、操作、依存情報を書く
- 画面IDは、画面設計書ごとに一意の固定名として書く
- 表示項目は、何を、どこから、どう、いつ表示するかを書く
- 状態別表示は、エレメント全体が状態ごとにどう見えるかを書く
- セレクタ（`aria-label`）は、画面IDの配下で表示項目と操作に書く
- 実装指示、テスト手順、agent handoff は書かない

## 項目説明

| 項目 | 説明 |
| --- | --- |
| 画面ID | 画面を一意に識別する固定名を書く |
| 目的 | 画面が利用者に提供する成果を書く |
| エレメント | 画面上の表示、入力、操作、状態表示を `E-01` 形式で書く |
| 概要 | エレメントが何かを短く書く |
| 表示項目 | 画面に出る文言、値、選択肢、アイコンを表で書く |
| 取得元 | DB、API、store、props、計算値などを書く |
| 表示形式 | 値をどの文言、形式、単位で見せるかを書く |
| 表示条件 | 表示項目が画面に出る条件を書く |
| 状態別表示 | 読み込み中、空、失敗、選択中、無効などの見え方を書く |
| 操作 | 利用者が行う入力、選択、押下、送信を書く |
| 有効条件 | 操作できる条件を書く |
| 成功時 | 操作後に起きる画面変化、状態変化、遷移を書く |
| 失敗時 | 操作失敗時に出す表示を書く |
| 依存情報 | 表示、操作、状態を決める依存先と用途を書く |
| セレクタ（`aria-label`） | 表示文言だけでは対象を説明できない場合のアクセシブル名を書く |

## 記述ルール

- エレメントの説明は、画面に存在するものだけを書く
- 画面IDは、同じ画面内のエレメントとセレクタのスコープとして扱う
- 表示項目は、表示項目、取得元、表示形式、表示条件を分けて書く
- 状態別表示は、状態名とエレメント全体の表示を分けて書く
- 操作は、有効条件、実行先、成功時、失敗時を分けて書く
- `data-testid` は画面設計書に書かない
- セレクタ（`aria-label`）は、表示項目または操作に紐づけて書く
- セレクタ（`aria-label`）が別画面と同じ文言になる場合は、画面IDで対象画面を先に絞る
