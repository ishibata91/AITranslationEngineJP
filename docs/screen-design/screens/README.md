# Screen Designs

この directory は、画面別の画面設計書を置く。
画面設計書は、画面が何をして、何があるかを短く固定する正本である。

## Records

- `template.md`: 画面設計書のテンプレート
- `example-incomplete-job-list.md`: 画面設計書の記述例

## Notes

- 画面設計書は、ワイヤーフレーム番号とエレメント説明を対応させる
- ワイヤーフレームは、画面上の箱、入れ子、番号だけを書く
- 表示内容、依存情報、操作、結果は、対応するエレメントに書く
- 実装指示、テスト手順、agent handoff は書かない

## 項目説明

| 項目 | 説明 |
| --- | --- |
| 目的 | 画面が利用者に提供する成果を書く |
| ワイヤーフレーム | 画面上の箱、入れ子、番号だけを書く |
| エレメント | ワイヤーフレーム番号に対応する表示、入力、操作を書く |
| 概要 | エレメントが何かを短く書く |
| 表示内容 | 画面に出る文言、値、選択肢、アイコンを書く |
| 依存情報 | 表示条件、有効条件、無効条件を決める状態やデータを書く |
| 表示条件 | エレメントが画面に出る条件を書く |
| 有効条件 | 操作できる条件を書く |
| 無効条件 | 操作できない条件と利用者へ見せる理由を書く |
| 操作 | 利用者が行う入力、選択、押下、送信を書く |
| 結果 | 操作後に起きる画面変化、状態変化、遷移を書く |
| セレクタ属性 | テストや画面確認で安定して参照する属性を書く |

## 記述ルール

- ワイヤーフレーム内の番号は、エレメント見出しの番号と一致させる
- ワイヤーフレームには、説明文、状態分岐、操作結果を書かない
- ワイヤーフレームは、親の箱の中に子の箱を入れて構造を示す
- エレメントの説明は、画面に存在するものだけを書く
- `data-testid` は、主要な操作対象と状態確認対象に書く
- `aria-label` は、表示文言だけで操作対象を説明できない場合に書く
